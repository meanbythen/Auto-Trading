## 0. 目标与非目标

### 目标
让程序按轮巡扫描结果自动完成：**选品种 → 选策略 → 开仓 → 风控 → 平仓 → 日终复盘**，最终支持无人值守。

### 非目标（本期明确不做）
- 跨品种对冲 / 套利
- 自动加仓网格、马丁格尔类资金曲线管理
- 多账户并行
- 未回测验证过的「品种×策略」组合直接实盘

### 硬前提
1. GUI 通道必须能**可靠切换并校验合约**，否则不允许自动选品。
2. 选品依据必须是**复合可交易性评分**，不能直接用 rotation 的行情适配分。
3. 默认 `max_active=1`（GUI）。多仓位只允许 ctp/sim 且受保证金与相关性约束。

## 2. 总体架构（五层）

```
┌─────────────────────────────────────────────────────────┐
│ L5 守护层 watchdog                                       │
│    心跳 / GUI 失败退避 / 登录失效 / 熔断 / 告警 / 日终复盘 │
├─────────────────────────────────────────────────────────┤
│ L4 执行层（复用现有）                                     │
│    sizer → risk → executor(gui/ctp/sim) → 记账 → 事件     │
│    【新增】合约切换校验、单仓互斥、切换时序               │
├─────────────────────────────────────────────────────────┤
│ L3 路由层 strategy_router                                │
│    品种 → 引擎（仅允许回测达标组合，否则回落默认引擎）     │
├─────────────────────────────────────────────────────────┤
│ L2 选品层 auto_select                                    │
│    行情适配分 + 流动性 + 保证金 + 相关性 + 时段 → 复合分   │
├─────────────────────────────────────────────────────────┤
│ L1 评分层（复用现有）                                     │
│    rotation_scan（多引擎加权）/ session_audit            │
└─────────────────────────────────────────────────────────┘
```

数据流：
`rotation rows` → `auto_select` → `候选排序` → `active_symbol 状态机` → `strategy_router` → `scan_symbol` → `sizer/risk` → `executor` → `events`

## 3. 关键设计决策（ADR）

### ADR-1 选品分 ≠ 盈利分
rotation 的 `score_market_state` 只回答"当前形态是否适配该模式"。直接据此开仓等于把形态适配当成正期望。
**决策**：新增复合评分 `tradability_score`，行情适配只占权重的一部分，其余来自回测边际、流动性、波动带、保证金余量。低于门槛不进入候选。

### ADR-2 候选池双层语义
现状：pool 与关注列表同步（14 个）。自动选品要求候选池更大。
**决策**：新增 `rotation_scan.pool_source`：
- `watch`（默认，保持现状）：只扫关注列表
- `enabled_universe`：扫品种表所有 enabled 行（候选池）
`strategy.symbols` 不再等同于候选池，而作为"人工保留名单"。运行时另设 `active_symbol`。

### ADR-3 合约切换必须 fail-closed
同花顺品种框打字后可能弹下拉、可能不提交。若未确认，后续买开按钮会把单下到旧合约。
**决策**：
1. 输入后按 `Enter`
2. `ctrl+a` / `ctrl+c` 回读并规范化比较（大小写、空格、非字母数字剔除）
3. 回读失败或与目标不一致 → **放弃本次下单**，记 `symbol_verify_failed` 事件并告警
4. 配置 `trade.gui.symbol_verify: strict | off`，默认 `strict`
5. 不允许"回读失败但继续下单"的降级路径

### ADR-4 单仓互斥 + 切换时序
**决策**：GUI 下 `max_active=1`。切换 active_symbol 必须满足：
```
无持仓 && 无在途订单 && 距上次下单 ≥ switch_cooldown_min && 校验通过
```
若当前持仓与新候选冲突，先按策略正常平仓（或等策略平仓信号），不强制市价换仓（避免额外滑点与两次点击风险）。

### ADR-5 策略路由需要证据
**决策**：路由表来自回测成绩库，不来自实时评分。准入线（建议值，可在配置覆盖）：
- 样本 ≥ 100 笔
- 盈亏比 PF ≥ 1.15
- 最大回撤 ≤ 15% 或 ≤ 资金×阈值
- 单笔期望 ≥ 手续费的 2 倍
未达标 → 回落 `strategy.engine` 默认引擎，且记 `router_fallback` 事件。

### ADR-6 配置不自动改写（除 auto_drop）
自动加品种不写 `config.yaml`，只用运行时 `active_symbol`。
**决策**：避免"自动加/自动删"竞态；auto_drop 仍保留，但改为只对 `watch` 名单生效，且与 active_symbol 解耦。

## 4. 模块设计

### 4.1 新文件 `src/strategy/auto_select.py`

#### 数据结构（签名草案）

```python
@dataclass(frozen=True)
class SelectConfig:
    enabled: bool = False
    pool_source: str = "watch"          # watch | enabled_universe
    max_active: int = 1
    min_score: float = 50.0             # 复合分门槛
    min_volume_lots: int = 500          # 近 N 根均量下限
    volume_lookback: int = 20
    max_margin_pct: float = 60.0        # 并发保证金 / 资金 上限
    refresh_min: int = 15               # 候选刷新周期
    switch_cooldown_min: int = 30
    only_at_session_open: bool = True   # 仅开盘后 X 分钟内选品
    board_dedup: bool = True
    atr_pct_min: float = 0.15           # 波动下限（防死水）
    atr_pct_max: float = 0.85           # 波动上限（防极端）
    weights: dict[str, float] = field(default_factory=lambda: {
        "market_fit": 0.45, "liquidity": 0.20, "vol_band": 0.15,
        "margin_room": 0.10, "backtest_edge": 0.10,
    })

@dataclass
class Candidate:
    symbol: str
    tradability: float          # 0~100 复合分
    market_fit: float
    liquidity: float
    vol_band: float
    margin_room: float
    backtest_edge: float
    margin_per_lot: float
    est_lots: int
    board: str
    reasons: list[str]
    blocked: str = ""           # 非空=被门槛拦下，附原因

class AutoSelector:
    def __init__(self, cfg, universe_rows, backtest_store=None) -> None: ...
    def rank(self, rotation_rows, *, capital: float, equity: float,
             open_positions: dict, bars_provider=None) -> list[Candidate]: ...
    def pick(self, candidates: list[Candidate], *, max_n: int = 1) -> list[Candidate]: ...
```

#### 复合评分算法

```
liquidity   = clamp01(log10(avg_vol_lots / min_volume_lots) ) → 0~100
vol_band    = 100 × [atr_pct_min ≤ atr_pct ≤ atr_pct_max] 的平滑得分
margin_room = 100 × clamp01((资本×max_margin_pct - 已占用保证金) / margin_per_lot)
backtest_edge = 0~100（PF/期望/回撤封装；无数据=0 并警告）
market_fit  = rotation score

tradability = Σ w_i × sub_score_i     （权重和为 1）
```

硬门槛（先于加权）：
- `market_fit < min_score` → 拦
- `avg_volume_lots < min_volume_lots`（无 volume 数据则跳过该门槛并记 `data_gap`）
- `est_lots < 1`（保证金不足）→ 拦
- 同板块已有持仓且 `board_dedup` → 拦
- 该品种当前时段不可交易 → 拦
- 回测未达标且 `require_backtest=true` → 拦

#### 板块去重表
静态映射（品种 → 板块），覆盖 81 个品种：黑色、有色、贵金属、能化、农产品、软商品、股指、国债、新能源。
（实现时放在 `auto_select.py` 常量表；不引入外部依赖。）

### 4.3 GUI 合约切换校验（改 `gui_trader.py`）

新增方法（伪代码）：
```python
def _ensure_symbol(self, symbol) -> bool:
    if not self.gui.get("symbol_input"):
        return not self.gui.get("symbol_verify_required_for_multi", True)
    code = normalize(symbol)                 # alnum, 大写
    self._type_into("symbol_input", code)
    pyautogui.press("enter")                 # 新增：提交
    time.sleep(0.2)
    got = self._read_symbol_text()           # ctrl+a, ctrl+c, pyperclip
    if normalize(got) != code:
        logger.error("合约校验失败：期望 {} 实际 {}", code, got)
        return False                          # fail-closed
    return True
```
配套：
- `_read_symbol_text()`：优先剪贴板；`pyperclip` 不可用时回退截图 OCR（可选依赖），再不行返回 `None` → 视为失败。
- `place_order`：`_ensure_symbol` 返回 False 时**不点任何买卖按钮**，返回 `OrderResult(ok=False, message="合约校验失败")`。
- 事件：`symbol_switch` / `symbol_verify_failed`。

### 4.4 runner 集成

#### 新增运行时状态

```python
self._active_symbol: str | None = None
self._active_since: datetime | None = None
self._last_select_at: datetime | None = None
self._halted: bool = False
self._halt_reason: str = ""
self._gui_fail_count: int = 0
self._switch_lock = threading.Lock()
```

#### ActiveSymbol 状态机

```
IDLE ──(到刷新点 & 空仓)──> SELECTING
SELECTING ──(候选 ≥1)──> ARMING ──(校验通过)──> ARMED
ARMING ──(校验失败)──> HALTED(可恢复)
ARMED ──(策略信号)──> PENDING_OPEN ──(成功)──> HOLDING
PENDING_OPEN ──(失败 N 次)──> HALTED
HOLDING ──(平仓信号/收盘清仓)──> PENDING_CLOSE ──> IDLE
任意 ──(日亏损/次数达上限/连续失败/手动急停)──> HALTED
HALTED ──(人工确认/次日重置)──> IDLE
```

守卫条件（每次迁移都要过）：
- 进入 SELECTING：`_symbol_is_flat_all()` 且无在途单
- ARMING→ARMED：合约校验成功且价格框回到对手价
- ARMED→PENDING_OPEN：`sizer` 手数 ≥1 且保证金可负担 且 `_sent_bar` 未发过
- 切换 active_symbol：距 `_last_select_at` ≥ `switch_cooldown_min`

#### scan_once 改造点

```
scan_once:
  _rollover_trading_day()
  _maybe_run_session_audit()
  _maybe_run_rotation_scan()
  if auto_select.enabled and 到刷新点:
      rows = rotation rows（上次缓存或现算）
      candidates = selector.rank(rows, capital, equity, positions)
      if candidates and 空仓: 进入 ARMING → 校验 → _active_symbol
  扫描目标 = [_active_symbol] if auto_select.enabled else self.symbols
```

> 关键：启用自动选品后，**只扫 active_symbol**，不再扫全关注列表，避免多合约并发下单。

#### auto_drop 与 auto_select 冲突收敛
- auto_drop 只对 `watch` 名单生效（写 config 的 `strategy.symbols`）
- auto_select 只影响 `_active_symbol`（运行时不写 config）
- 两者互不写同一字段

### 4.5 守护层（`src/scheduler/watchdog.py`，新文件）

职责：
- 心跳监控：`last_scan_at` 超过 3×scan_interval → 记异常
- GUI 连续失败：≥3 → `_halted`，禁止开仓（平仓仍允许）
- 登录失效：`_ensure_runtime_ready` 失败 → 重登，连续 3 次失败 → halt
- 交易时段边界：收盘前强制清仓复核；非交易时段不选品
- 告警：现有桌面提示 + 日志 ERROR + `events.jsonl`
- 日终复盘：收盘后生成当日成绩单（复用现有收盘复盘页逻辑）

## 6. 安全与风控矩阵

| 失败模式 | 检测手段 | 兜底动作 |
|---|---|---|
| 合约没切过去 | 回读比对 | 不下单 + 告警 + 计入失败 |
| 品种框下拉选错（前缀相同） | 回读精确比对 | 同上（strict 模式） |
| 重复下单 | `_sent_bar` + `order_dedup` | 跳过并记事件 |
| 点买开但实际未成交 | `assume_fill` 语义 / 账本核对 | 下一轮对账，记 `fill_mismatch` |
| 保证金不足 | `est_lots < 1` | 候选直接拦截 |
| 同板块集中 | 板块表 + 持仓 | 拦截 |
| 日亏损超限 | 现有 `max_daily_loss` | 停止开仓，仅允许平仓 |
| 开仓次数超限 | 现有 `max_orders_per_day` | 同上 |
| GUI 连续失败 | 计数器 | `_halted`，桌面告警 |
| 登录失效 | `_ensure_runtime_ready` | 重登，连续失败则 halt |
| 电脑休眠 | 现有 KeepAwake | 保持 |
| 无人值守夜间异常 | watchdog 心跳 | 记录 + 次日复盘提示 |

  - 切合约前必须无持仓
  - 校验失败时 0 笔订单
  - 同一 bar 不重复开仓
  - halt 后不再产生开仓单

### 影子运行（shadow mode）

### 灰度
1. shadow → 2. sim 成交 → 3. GUI dry_run → 4. GUI 1 手小资金 → 5. 放开。

## 9. 分阶段实施与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **0 安全件** | 合约切换校验、单仓互斥、失败熔断、切换时序 | 单测全绿；fake 集成中"校验失败=0 单"；现有 582 测试不回归 |
| **A 半自动** | 推荐 + UI「采纳」按钮（人工确认后切合约） | 推荐列表可读；采纳后 active_symbol 正确且校验通过 |
| **B 自动选品（单策略）** | auto_select + 状态机 + shadow 开关 | shadow 运行 2 周推荐可解释；实盘 1 手阶段无错单 |
| **C 自动选策略** | strategy_router + 成绩库 | 仅达标组合被路由；fallback 可观测 |
| **D 无人值守** | watchdog + 告警 + 日终复盘 | 连续 5 个交易日无人工干预且无错单/漏平仓 |

版本节奏建议：阶段 0 → 9.44.0；A → 9.45.0；B → 9.46.0；C → 9.47.0；D → 9.48.0。每阶段独立 CHANGELOG。

## 10. 风险登记册

## 12. 结论

- **技术可行**，但必须按 0→A→B→C→D 推进，不允许跳步。
- 当前最大风险不是评分算法，而是 **GUI 合约切换无校验**；这是阶段 0 的唯一硬前提。
- rotation 分只能作选品输入之一，不能作开仓依据；否则自动化的本质是"把形态适配当盈利"。
- 资金 18526 元决定了并发仓位上限为 1（GUI），设计已按此约束。
