# 策略研究体系评估与全闭环方案

- 评估日期：2026-11-21
- 评估基线：版本 49.23.2
- 评估范围：`src/backtest`、`src/research`、`src/screen`、`src/review`、`src/ops`、`src/strategy`、`config`
- 结论口径：只回答“研究环境是否够用、缺什么、怎么补”，不改代码、不评价行情判断

---

## 0. 一句话结论

**底层研究环境已经齐备，不缺数据、回测、优化和防过拟合的骨架；真正缺的是“组合层”和“研究治理层”。**

- 单策略、单品种这条线，从数据门禁、回测、优化、冻结样本外、上线评审到实盘健康监控已经闭环，成熟度高于多数自建系统。
- 不能直接回答的问题是：**多个品种放在一个账户里、多套策略同时跑时，资金怎么分、保证金够不够、相关性多大、组合回撤是多少**。项目目前没有组合回测，交叉测试也按固定手数排名，不是资金口径。
- 第二个缺口是研究治理：没有假设登记、失败实验库、决策日志和变更冻结，时间一长容易“只记得成功的实验”，反复在同一段历史上调参。

| 能力域 | 现状 | 完备度 | 主要缺口 |
|---|---|---|---|
| 数据与血缘 | K 线/tick 分库，运行清单记录数据哈希、配置哈希、git commit | 高 | tick 级回放、换月价差、容量数据 |
| 单品种回测 | 逐根撮合、滑点、手续费、涨跌停、流动性、平今平昨、换月分段 | 高 | 限价排队、部分成交概率、延迟 |
| 参数优化 | 训练/检验切分、滚动前进、多品种验收、冻结样本外、成交打乱 | 高 | 参数平原、联合扰动、PBO/DSR |
| 组合层 | 仅有实盘敞口上限，无组合回测/组合优化 | **低** | 共享资金、保证金、相关性、资金分配 |
| 实盘验证 | 上线四阶段、评审单、仿真/影子盘、滑点日志、健康对照 | 中高 | 退化根因、加仓/降仓节奏 |
| 策略生命周期 | 可启停、可对照回测、可配置停开仓 | 中 | 状态机、退役/复活标准、A/B |
| 研究治理 | 实验不可变快照与索引 | 中低 | 假设登记、失败库、决策日志 |

### 0.1 先纠正一个前提：现在是“单品种开仓 + 多品种持仓管理”

- 数据、回测、交叉测试本身支持多品种：`strategy.symbols` 是关注列表，交叉测试按策略×品种×周期跑。
- 常驻实盘只对**当前选中品种**开新仓；扫描清单 = 当前品种 + 账上所有非空持仓，其余持仓只做止损与收盘清仓（`src/scheduler/runner.py:630`）。
- 这不是“只能监控一个品种的数据”，而是**故意限制开仓范围**：避免没人盯的旧仓裸奔，也避免 GUI 模式一次挂太多合约。
- 因此当前形态是：一个账户可同时持多个品种，但新开仓集中在一个品种；组合风控只做净/总手数上限。

**这决定了组合回测的定位：**

- 如果继续“一次只做一个品种”，组合回测不是当务之急，价值主要在“选品种”和“验证资金/保证金假设”，优先级低于统计稳健性与执行校准。
- 如果打算升级为“多品种同时开仓”，组合回测是**前置条件**：没有它，就无法在上班前知道 8 个品种一起跑要占多少保证金、组合回撤多大、相关性会不会把风险叠成杠杆。

### 0.2 多品种挂机的升级可行性

结论先说：**目前不具备“多品种同时开新仓”的完整能力**，只具备“多品种同时持仓管理”的部分能力。

已经具备的：

- 扫描主循环本来就按清单逐个品种执行（`src/scheduler/runner.py:2275`）。
- 账本持仓、风控、三方对账都按合约名区分，可以同时持多个品种。
- 组合敞口上限已存在（`src/risk/portfolio.py:105`）。
- 柜台下单按合约路由，不限制品种数。

仍然缺的（缺一项都不能算“多品种同时挂机”）：

1. **扫描清单被写死**：`_pick_scan_symbols()` 只返回“当前选中品种 + 已有持仓”（`runner.py:630`），关注列表里的其它品种不会被扫描开仓。
2. **行情层已支持多合约，但尚未接入交易扫描**：49.24.0 起 `subscribe_many()` 可以一次订阅多个合约并按合约分发 tick，天勤 `fetch_frames()` 也可以批量拉取；但交易调度仍只把“当前品种 + 持仓”放进扫描清单，关注列表里的其它品种不会自动开仓。
3. **未订阅品种仍无盘口**：下单报价优先按合约调用 `md.latest_for()`，订阅了就有盘口；没订阅或还没收到 tick 时才退回 K 线最新价，成交质量和滑点不可控。
4. **交易时段只取第一个品种**：`live_symbol = scan_symbols[0]`（`runner.py:183`），不同夜盘时段的品种会被一起开关。
5. **GUI 模式只交易选中品种**：GUI 通道只对当前选中品种开仓，关注列表可以留多个，不会因为扫描清单超过 1 个而拒绝启动；清单里的其它品种只用于给已有持仓止损/清仓（`runner.py:630`）。多品种组合只在 CTP 通道做。
6. **没有资金/保证金分配**：每个品种各自按账户权益算手数，组合层只有净/总手数上限，没有按品种的风险预算与保证金约束。

因此升级路径不是“改一行清单”，而是：扫描策略 + 多合约行情 + 分品种时段 + 资金分配 + GUI 确认，五项一起做。多线程仍然不是必需项；十几个品种、15 分钟一轮，单线程串行足够，拆线程反而破坏“风控与报单同线程、顺序确定”的契约。

**49.24.0 已完成其中“多合约行情”这一项的基础设施**：CTP 行情支持多合约订阅与按合约取价，天勤 K 线支持批量拉取与序列复用；剩余的是扫描清单、分品种时段、资金分配和 GUI 确认。

## 1. 已具备的能力（先看清家底）

### 1.1 回测与撮合

- 单品种回测入口 `run_backtest()`，信号按已收线 K 线评估，默认下一根开盘成交，支持滑点跳数、手续费、保证金与手数上限（`src/backtest/engine.py:1714`、`src/backtest/fill.py:14`）。
- 涨跌停一字板不成交、挂单等待、单根成交量上限（`src/backtest/liquidity.py:34`）。
- 平今/平昨、跨日加仓逐 lot 计费（`src/backtest/engine.py:86`）。
- 换月回测按主力时段分段，段末平仓、新主力重新评估（`src/backtest/rollover.py:1`）。
- 回测与实盘共用 `PositionSizer`、`RiskGuardian`，不是两套仓位逻辑（`src/backtest/limits.py:31`）。

### 1.2 优化与防过拟合

项目在这块的完整度明显高于一般自建系统，已有六道闸：

1. **训练/检验切分**：前段打分、后段只验收（`src/backtest/optimizer.py:332`）。
2. **滚动前进**：检验段拆成多段，走一步验一步，最后一段参数才考虑写入（`src/backtest/optimizer.py:1`）。
3. **多品种验收**：本合约过关后，拿其它关注品种跑一遍，不重新挑参数；大半大亏则拒绝（`src/backtest/optimizer.py:382`）。
4. **最终半年冻结**：搜索碰不到，看过一次就不能再当验收（`src/backtest/frozen_oos.py:1`）。
5. **成交打乱/重抽**：净盈亏靠少数几笔撑起来的，拒绝写入（`src/backtest/monte_carlo.py:1`）。
6. **评估门槛**：盈利因子、Calmar、回撤、样本数、连亏、滑点压力、参数扰动断崖（`src/backtest/evaluation.py:67`）。

此外，接近出厂参数时优先保留更稳的一组，避免“参数刚好卡在最优点”。

### 1.3 实验管理与可复现

- 每次回测/优化生成不可变实验快照：配置快照与 SHA、数据文件 SHA、git commit 与是否 dirty、运行清单（`src/backtest/experiment.py:96`）。
- `research_runs` 记录策略版本、参数哈希、数据哈希与耗时；`tools/rebuild_experiment_index.py` 可重建索引。
- 交叉测试、优化、回测统一走同一份运行清单，结果页共用 `result_summary` 口径。

### 1.4 实盘验证与生命周期

- CTP 四阶段上线：手工仿真 → 手工真实 → 策略仿真 → 策略真实（`src/trader/go_live.py:1`）。
- 上线评审单：数据门禁、样本外、镜像差异率、仿真滑点、人工签字，五项收成一页；签字只表示“允许小资金挂机”，不会自动开仓（`src/review/release_sheet.py:1`）。
- 策略健康：拿最近实盘已平仓与 `data/backtest_last.json` 的胜率、盈利因子对照，口径不一致时标“未对照”；连续偏离可按配置停开新仓（`src/ops/health.py:2`、`src/ops/health.py:261`）。
- 仿真/影子盘、滑点日志、告警、审计、`trace_id` 均已接入。

## 2. 现有功能的主要缺陷

### P0：直接影响研究结论可信度

1. **没有组合回测**
   `run_backtest()` 明确是“对单个品种跑完整回测”（`src/backtest/engine.py:1732`）。多品种只是循环各跑一遍，不能回答：
   - 同一账户同时持有多个品种时，保证金峰值和组合回撤是多少；
   - 品种之间同涨同跌时，组合风险是否被低估；
   - 资金不够时先保哪个品种。
   交叉测试也按固定手数、忽略账户权益比较（`src/screen/picker.py:954`），排名是“信号质量排名”，不是“资金效率排名”。

2. **没有组合优化与资金分配**
   优化器是单合约、单策略参数搜索；组合层只有净/总手数上限，没有相关性、风险预算、资金分配和再平衡。实盘当前又只对一个品种开新仓，所以单品种回测与实盘是匹配的；一旦改成多品种同时开仓，现有研究工具就无法给出资金与保证金层面的结论。

3. **缺少统计显著性检验**
   有盈利因子、Calmar、回撤，但没有 Sharpe/Sortino、bootstrap 置信区间、Deflated Sharpe、PBO（回测过拟合概率）。网格搜索跑了多少组、挑出最好一组带来的选择偏差，目前只靠冻结样本外兜底，没有量化。

4. **执行模型未与实盘校准**
   滑点固定跳数、下一根开盘成交、流动性按比例限制，属于合理近似；但没有用 `slippage_log` 的实盘滑点反推回测参数，也没有限价排队、部分成交概率、延迟。小资金阶段问题不大，资金放大后回测会偏乐观。

### P1：影响研究效率与策略寿命

5. **指标不够完整**
   `Performance` 只有胜率、盈亏比、期望值、盈利因子、最大回撤；年化与 Calmar、回撤持续期在评估层另算。缺 Sharpe/Sortino、Ulcer、持仓暴露、换手率、成本占比、分品种/分时段归因。
6. **健康对照维度偏少**
   只用最近 N 笔的胜率和盈利因子对照最近一次回测，没有对照盈亏分布、滑点、分品种/分时段表现；停开仓需显式开启，默认仍以提醒为主。
7. **没有策略状态机**
   只有启停和上线阶段，没有“草稿 → 仿真 → 小资金 → 正常 → 观察 → 退役 → 复活”的状态与准入/退出条件；参数变更与实盘表现的关联靠人工追溯。
8. **没有 A/B 与多账户对照**
   同一策略无法同时跑两套参数/两本账做并行对照，变更效果只能上线后看历史。

### P2：锦上添花但迟早要做

9. 主连换月只做分段平仓，不计算展期收益与价差成本；不同复权/拼接方式对结论的影响没有对比。
10. 没有 tick 级回放与盘口容量估计；大资金容量上限无法量化。
11. 组合风险指标缺 VaR/CVaR、压力测试、相关性聚类。
12. 研究档案偏“实验记录”，缺“研究假设与决策记录”。

## 3. 完整策略研究闭环（可直接执行）

下面按“立项 → 研究 → 组合与上线 → 运行 → 复认证”五个阶段走。标“已有”的可以直接用现有页面/工具；标“待补”的对应第 4 节规划。与上一版相比，补了 9 个环节：候选来源、试验预算、基准与泄漏检验、统计显著性与多重检验、执行可行性与容量、执行校准、变更审批与回滚、定期再认证、负面结果库。

**一页速览**：0 候选来源 → 1 预注册 → 2 数据门禁 → 3 基准/泄漏 → 4 原型 → 5 初筛 → 6 优化 → 7 稳健性 → 8 统计检验 → 9 冻结样本外 → 10 多品种样本外 → 11 组合回测 → 12 执行容量 → 13 上线审批 → 14 仿真 → 15 小资金 → 16 监控 → 17 执行校准 → 18 变更 → 19 退役 → 20 再认证。

### 阶段 A：立项

#### 第 0 步 候选来源与经济逻辑（新增）

- 来源可以是复盘异常、品种特性、公开研究或执行摩擦；先写清“谁在什么情况下、为什么愿意亏钱给你”。
- 产出：一页假设卡，包含市场、周期、信号、预期持有期、失效条件。
- 门禁：一句话说不清赚什么钱，不进入回测。

#### 第 1 步 预注册与试验预算（扩展）

- 先定评估指标、验收阈值、参数范围、最多尝试多少组；登记到研究档案，看到结果后不再改标准。
- 产出：预注册记录 + 试验预算（组数、轮数）。
- 门禁：没有验收标准不跑优化；超出预算的尝试必须记录，并在最终评估时降权。

#### 第 2 步 数据、合约规则与成本假设（扩展）

- 数据覆盖与缺口、主力换月规则、交易时段与节假日、涨跌停、手续费、保证金、滑点初值。
- 产出：数据门禁结论 + 成本假设表（每个数字写来源）。
- 门禁：数据不达标就缩短区间，不伪造完整性；成本假设缺失不允许进入优化。

### 阶段 B：研究

#### 第 3 步 基准、泄漏与安慰剂检验（新增）

- 基准：买入持有、随机入场、简单均线，同成本、同周期、同品种。
- 泄漏：特征只用已收线数据，检查时间戳对齐与未来函数。
- 安慰剂：信号整体平移一根 K 线，或随机打乱信号日期，收益应明显下降。
- 门禁：跑不赢基准，或安慰剂与真信号无差异，说明没有 alpha，停止。

#### 第 4 步 单品种原型与成本基线（已有）

- 固定一组“出厂参数”，先看信号逻辑是否成立，不调参。
- 加成本、加滑点、加涨跌停与流动性限制后再看，仍为正期望才继续。

#### 第 5 步 交叉初筛（已有，需补资金口径）

- 策略 × 品种 × 周期矩阵，固定手数，先筛掉明显不适配的组合。
- 看净盈亏、盈利因子、回撤、成交笔数、评估结论，不看单一胜率。
- 初筛只回答“值不值得进入优化”，不直接作为上线依据。

#### 第 6 步 参数优化（已有）

- 训练段搜索、检验段验收；开启滚动前进。
- 不同时使用冻结段；最终半年留到最后只跑一次。
- 参数范围要有经济含义，不做无边界网格；记录实际尝试组数，交给第 8 步校正。

#### 第 7 步 稳健性压力（已有 + 待补）

- 已有：滑点 +N 跳、参数 ±10% 扰动、成交打乱/重抽、多品种验收。
- 待补：参数平原热力图、多参数联合扰动、成本倍增、资金容量上限。
- 参数平原判定：最优点周围必须连续多组仍为正；只有单点突出、邻域塌陷的，视为孤峰，直接拒绝，不进入下一步。
- 门禁：邻域略变收益就塌陷的组合，不进入下一步。

#### 第 8 步 统计显著性与多重检验（新增）

- 用 bootstrap 给收益与回撤置信区间，算 Deflated Sharpe 与 PBO（回测过拟合概率）。
- 按第 6 步的实际试验次数校正；不能只报最好一次，失败组合也要留记录。
- 门禁：PBO 超阈值，或收益置信区间跨 0，拒绝；不能因为样本外一次好看就放行。

#### 第 9 步 冻结样本外（已有）

- 冻结段只验收一次；不过关就放弃这组参数，不回到训练段继续微调。
- 再过一次就必须等新行情长出来。

#### 第 10 步 多品种、多周期样本外（已有）

- 参数固定，换品种、换周期跑；大面积失效说明是拟合了特定历史，不是策略。
- 记录每个品种的通过/观察/拒绝，不取平均掩盖失败品种。

### 阶段 C：组合与上线

#### 第 11 步 组合构建与组合回测（待补，是否先做取决于路线）

- 入选品种放进同一账户，共享资金与保证金。
- 输出：组合权益曲线、组合最大回撤、保证金峰值、品种贡献、相关性矩阵、同时持仓数。
- 组合层再决定权重：等权、波动率倒数、风险预算或固定上限；不做无约束的最优权重搜索。
- 同时约束两层风险：单品种风险上限 + 组合风险预算；高相关品种合并计算，不能各按满额分配。
- 验收：组合回撤和保证金占用可接受，且不是靠单一品种贡献绝大部分收益。

#### 第 12 步 执行可行性与容量（新增）

- 核对单笔手数相对成交量的占比、涨跌停、交易时段、最小变动、券商规则、延迟与人工干预。
- 做资金放大 2 倍、5 倍、10 倍的压力：滑点与成交率如何变化，策略容量上限是多少。
- 门禁：容量上限低于计划资金，降规模或放弃，不能靠“先跑起来再说”。

#### 第 13 步 上线评审、变更审批与回滚（扩展）

- 生成上线评审单：数据门禁、样本外、镜像差异率、仿真滑点、人工签字。
- 同时准备回滚预案：旧参数、停用步骤、恢复仿真、通知对象；变更记录原因与生效时间。
- 门禁：没有回滚方案不上线；评审单只允许“继续观察 / 允许小资金挂机”，不自动放宽风控。

#### 第 14 步 仿真与影子盘（已有）

- 策略仿真跑通下单、回报、记账、对账；影子盘只观察不真实发单。
- 对照回测与仿真的成交价、滑点、成交率；差异过大先修执行，不急着上真钱。

#### 第 15 步 小资金实盘与阶梯加仓（部分已有）

- 先最小手数，确认成交、风控、账本、告警都正常。
- 加仓按预设阶梯，不因为短期盈利临时跳级；加仓前复核保证金与组合回撤。

### 阶段 D：运行

#### 第 16 步 监控、退化判定与归因（部分已有）

- 已有：健康对照、连续偏离计数、可配置停开仓、告警。
- 待补：分品种/分时段/分市场状态的退化归因；滑点与拒单率监控。
- 市场状态分层：至少按趋势/震荡、高波动/低波动、日盘/夜盘分组统计胜率、盈利因子、回撤；某一状态贡献了全部收益，要在结论里单独标注。
- 退化判定要能回答“是策略失效、执行变差，还是行情状态变了”，不能只有一个总分。

#### 第 17 步 执行校准与回测反哺（新增）

- 定期拿实盘成交价、滑点、拒单率、成交率，对照回测假设；差异超出容忍范围就更新成本假设表。
- 用校准后的滑点与成交率重跑关键回测，确认结论是否仍成立；如果结论翻转，回到第 6～10 步重新评估。
- 产出：校准记录（实盘值、回测值、差异、更新后的假设、生效日期）。
- 门禁：长期不校准的策略，不得扩大资金规模。

#### 第 18 步 变更管理与再优化节奏（新增）

- 上线后设冻结期；冻结期内不改参数，短期亏损先归因，不把噪声当信号。
- 变更用 A/B 或多账户对照，小流量验证后再全量；再优化按固定节奏，不随时开跑。
- 门禁：任何参数变更都要重新走第 9、10 步样本外；变更记录写进决策日志。

#### 第 19 步 退役、复活与事故复盘（扩展）

- 提前写退役标准（回撤、连续偏离、样本外失效）与复活条件（重新通过样本外，不直接恢复旧参数）。
- 异常交易单独复盘：滑点异常、拒单、断线、重复报单，不混在绩效里。
- 退役策略保留参数、实验与实盘记录；失败原因写进负面结果库。

### 阶段 E：复认证

#### 第 20 步 定期再认证（新增）

- 按固定周期用新数据重跑冻结外验证，检查策略是否仍成立。
- 同步核对交易所规则、手续费、保证金、合约乘数、交易时段是否变化。
- 资金规模变化后重做容量评估。
- 独立复现：用冻结数据重跑关键实验，结果应与原记录一致；不一致先查数据版本、配置哈希与代码 commit。
- 门禁：再认证不过，降规模或退役；不能靠“历史一直赚钱”继续挂着。

## 4. 缺失部件的完善规划

### 规划 A：组合回测最小闭环（是否先做取决于路线）

**先做判断**：如果近期仍维持“单品种开仓”，规划 A 可以后置，先做规划 B/C；如果准备多品种同时挂机，规划 A 必须先做，否则没有上线依据。

**做什么**

- 新增组合回测编排：复用 `run_backtest()` 的单品种结果，按交易日对齐权益，共享初始资金，汇总保证金峰值、组合回撤、品种贡献。
- 交叉测试增加“资金口径”开关：按组合权益与保证金约束重排，不再只看固定手数收益。
- 输出相关性矩阵与同时持仓统计。

**验收**

- 单品种结果与现有回测完全一致；
- 组合权益 = 各品种盈亏累加，组合回撤可复算；
- 能回答“这 8 个品种同时跑，保证金峰值多少、最大回撤多少、是否过度集中”。

### 规划 B：统计稳健性与参数平原

**做什么**

- 指标补 Sharpe、Sortino、Ulcer、暴露、换手、成本占比。
- 增加 bootstrap 置信区间、Deflated Sharpe、PBO（组合对称交叉验证）。
- 优化结果增加参数邻域热力图、多参数联合扰动、成本/滑点二维压力表。
- 评估门槛接入 PBO 与置信区间，不只看单点盈利因子。

**验收**

- 同一批实验能输出“过拟合概率”和“收益置信区间”；
- 参数最优点周围明显塌陷的组合被自动拒绝；
- 报告能区分“策略有效”和“这组参数刚好有效”。

### 规划 C：研究治理

**做什么**

- 研究假设登记表（YAML/JSON）：假设、品种、周期、参数范围、验收标准、结论。
- 实验与假设关联；失败实验保留并标记失败原因。
- 决策日志：为什么选这组参数、为什么上线、为什么退役。
- 变更冻结：上线后一段时间内不改参数；再优化按固定节奏，不随时调。

**验收**

- 任一上线策略都能追到“假设 → 实验 → 样本外 → 评审单 → 实盘”；
- 失败实验可检索，避免重复研究；
- 参数变更都有理由和时间点。

### 规划 D：实盘闭环增强

**做什么**

- 用实盘滑点日志反推回测滑点与成交率，定期校准。
- 健康对照扩展到盈亏分布、分品种/分时段、滑点与拒单率。
- 策略状态机与退役/复活条件；连续偏离达到阈值默认停开（可配置）。
- 多账户/多参数 A/B，小流量对照后再全量切换。
- 上线变更必须带回滚预案；定期再认证，核对交易所规则、手续费、保证金与合约乘数变化。
- 按资金规模重做容量评估，给出每个策略的资金上限。

**验收**

- 回测滑点与实盘滑点差异有量化记录；
- 退化能在品种/时段维度定位，而不是只有一个总分；
- 每次参数变更都能用 A/B 或前后对照说明效果；
- 规则或资金规模变化后，策略要么通过再认证，要么降规模/退役。

### 5.2 新增环节的必要性

| 新增环节 | 缺了会出现的错误 | 最小判定 |
|---|---|---|
| 候选来源与经济逻辑 | 先跑数据再找理由，容易把噪声解释成规律 | 一句话说清谁为什么亏钱；说不清停止 |
| 预注册与试验预算 | 看到结果后改标准，永远“通过” | 先写指标、阈值、参数范围、最多试几组 |
| 基准、泄漏与安慰剂 | 信号来自未来数据，或本来就不如买入持有 | 跑赢同成本基准；平移一根后收益明显下降 |
| 统计显著性与多重检验 | 试了几百组，挑出最好一组当结论 | 置信区间不跨 0，PBO 低于阈值 |
| 执行可行性与容量 | 小资金能跑，资金放大后滑点吃掉利润 | 资金放大 2/5/10 倍后仍可接受，给出容量上限 |
| 执行校准闭环 | 回测滑点与实盘越差越远，结论早已失真 | 实盘与回测差异有记录，并按校准值重跑关键回测 |
| 变更审批与回滚 | 上线后改参数，出问题无法恢复 | 有回滚预案、变更原因和生效时间 |
| 定期再认证 | 行情、手续费、合约规则变了，策略早失效还在跑 | 按周期重跑冻结外验证并核对规则变化 |
| 负面结果库 | 半年后重复研究同一个失败想法 | 失败假设可检索，写清失败原因 |

仍然容易漏的四项：

- **异常交易复盘**：滑点异常、拒单、断线、重复报单要单独查，不能只看盈亏。
- **独立复现**：隔一段时间用冻结数据重跑同一实验，确认结果不是偶然。
- **规则变更监控**：手续费、保证金、交易时段、合约乘数变化会直接改变策略有效性。
- **策略相关性监控**：多个品种或多个策略同向时，组合风险会被低估。

## 6. 现在就能执行的最小 SOP

不写新代码，先用现有功能跑一轮完整研究：

1. 选 1 个策略、3～5 个品种、1 个周期，登记假设、验收标准，以及“最多试几组参数”。
2. 数据门禁通过后，列出成本假设表（手续费、保证金、滑点、交易时段）。
3. 先跑基准：买入持有、随机入场、简单均线；再把自己的信号整体平移一根 K 线。跑不赢基准或平移后没变差，直接停止。
4. 固定一组出厂参数跑基准回测，确认不是靠调参才成立。
5. 交叉测试初筛，保留净盈亏、盈利因子、回撤、笔数都过关的组合。
6. 对入围组合做参数优化：训练/检验 + 滚动前进，不碰冻结段；记录实际尝试组数。
7. 看滑点压力、参数扰动、成交打乱结果；任何一项红线不过就放弃。
8. 冻结样本外只跑一次；不过关直接放弃，不回头微调。
9. 参数固定，换品种、换周期做样本外；失败品种单独记录。
10. 核对执行可行性：单笔手数相对成交量、交易时段、涨跌停；粗估资金放大后的容量。
11. 通过后生成上线评审单，写清回滚预案，再进仿真/影子盘对照成交与滑点。
12. 小资金实盘，开启健康对照；连续偏离达到阈值就停开新仓。
13. 每周复盘执行质量，每月复盘策略有效性；结论写进决策日志。
14. 达到退役条件按预案停用，保留全部实验与参数记录；定期做再认证。

## 7. 判断标准：什么叫“真正实盘可用”

不是回测收益最高，而是同时满足：

- 跑赢同成本基准，且通过泄漏与安慰剂检查；
- 成本、滑点、涨跌停、流动性全算进去后仍为正期望；
- 参数邻域稳定，不是孤峰；
- 统计上不像是从大量试验里挑出来的（置信区间不跨 0，PBO 可接受）；
- 冻结样本外与多品种样本外都过关；
- 组合回撤与保证金占用可承受，收益不依赖单一品种；
- 容量上限高于计划资金；
- 仿真/影子盘成交质量与回测差距可解释；
- 实盘退化有明确判定与停手条件；
- 研究过程可复现、可追溯、失败有记录。

满足前五条可以进仿真；满足前八条可以小资金；全部满足才谈正常资金。

## 8. 实施顺序与优先级

### 8.1 排序原则

1. 先修“会误导决策”的，再做“提高收益上限”的。
2. 先做能复用现有数据与接口的，低成本高杠杆。
3. 只读分析先上，收紧门槛后上；任何一项都要能单独回退。
4. 组合层放在指标、样本外、执行校准之后；多品种实盘放在组合回测之后。
5. 不改交易主链路的研究工具优先，避免研究与实盘互相牵连。

### 8.2 优先级矩阵

| 优先级 | 工作包 | 价值 | 依赖 | 风险 |
|---|---|---|---|---|
| **P0** | 指标补齐：Sharpe/Sortino/Ulcer、暴露、换手、成本占比 | 所有报告与门槛的共同底座 | 无 | 低，只读 |
| **P0** | 试验全量留痕：保存全部 trial、试验次数、失败组合 | PBO、参数平原的前提 | 优化器已有 `trials`，补持久化 | 低 |
| **P0** | 稳健性报告：bootstrap 置信区间、DSR、PBO、参数平原热力图 | 直接回答“是不是运气” | 上两项 | 低，先只读 |
| **P0** | 执行校准：实盘滑点/拒单回填，重跑关键回测 | 防止回测长期偏乐观 | 滑点日志已有汇总 | 低，不改发单 |
| **P1** | 健康归因扩展：分品种/时段/市场状态、滑点与拒单 | 退化时能定位原因 | 指标补齐 | 低 |
| **P1** | 研究治理：假设登记、决策日志、失败库、变更冻结 | 防止重复研究与反复调参 | 无 | 低，流程为主 |
| **P1** | 组合回测：共享资金、保证金、相关性、品种贡献 | 决定是否多品种挂机 | 指标补齐 | 中，新增模块 |
| **P1** | 交叉测试资金口径 | 排名从“信号质量”变“资金效率” | 组合回测 | 中 |
| **P2** | 多品种实盘：关注列表扫描、多合约行情、分品种时段、资金/风险预算、GUI 确认 | 真正多品种同时开仓 | 组合回测 + 人工确认 | 高，动交易链路 |
| **P2** | 多账户/参数 A/B | 变更效果可对照 | 状态机与治理 | 中高 |
| **P2** | tick 回放、容量上限、VaR/CVaR、压力测试 | 大资金与极端行情 | 数据与组合层 | 中 |

### 8.3 建议实施批次

#### 批次 1：可信度底座（先做，全部只读）

1. 扩展 `src/backtest/metrics.py`：补 Sharpe、Sortino、Ulcer、暴露、换手、成本占比；`result_summary` 与结果页同步。
2. 确认 `src/backtest/optimizer.py` 的 `trials` 全量进入实验快照与索引；补“试验次数、失败组合数”。
3. 新增稳健性分析模块（建议 `src/backtest/robustness.py`）：bootstrap 置信区间、Deflated Sharpe、PBO、参数平原热力图；先从现有实验回放，不改优化流程。
4. 评估页增加“稳健性”分区，先只展示、不拦截。

**验收**：任一历史实验能生成置信区间、PBO 和参数热力图；同一实验重复计算一致；现有回测与优化结果不变。

#### 批次 2：执行校准

1. 用 `src/account/slippage_log.py` 的汇总结果生成校准记录（实盘值、回测值、差异、生效日期）。
2. 回测成本假设支持读取校准值；未校准时仍用配置默认值，报告里标明“未校准”。
3. 上线评审单引用最近一次校准记录；长期未校准的策略在评审单上标红。
4. 健康报告增加分品种、分时段、分市场状态的滑点与拒单统计。

**验收**：能回答“回测滑点比实盘乐观多少”；用校准值重跑关键回测后，结论变化有记录；评审单不再使用无来源的假设值。

#### 批次 3：研究治理

1. 新增研究假设登记（YAML/JSON）与决策日志（追加式 JSONL）。
2. 实验创建时关联假设编号；失败实验标原因并保留。
3. 上线变更记录：改了什么、为什么、谁批准、何时生效、回滚方案。
4. 变更冻结期与再优化节奏写进流程，不依赖记忆。

**验收**：任一上线策略能追到“假设 → 实验 → 样本外 → 评审单 → 实盘 → 变更”；失败实验可检索。

#### 批次 4：组合层（先做决策，再动手）

**决策点**：是否要在近期支持多品种同时开仓。

- 若“是”：先做组合回测与资金分配，再做多品种实盘；多品种实盘需单独评审，涉及扫描清单、分品种交易时段、风险预算与界面确认。
- 若“否”：跳过组合回测，把精力放在批次 1～3 与批次 5 的容量、再认证上；组合回测只作为选品种的辅助工具。

组合回测最小范围：

1. 复用单品种回测结果，按交易日对齐权益，共享初始资金。
2. 汇总保证金峰值、组合回撤、品种贡献、相关性矩阵、同时持仓数。
3. 交叉测试增加资金口径开关。
4. 权重只做等权、波动率倒数、风险预算、固定上限，不做无约束最优搜索。

**验收**：单品种结果与现有回测一致；组合权益可复算；能回答“这组品种一起跑，保证金和回撤是否可承受”。

#### 批次 5：规模化与复认证

1. 多账户/多参数 A/B。
2. tick 回放与容量上限。
3. VaR/CVaR、压力测试、相关性聚类。
4. 定期再认证自动化：规则、手续费、保证金、合约乘数变化检查。

**验收**：资金规模变化后有容量结论；规则变化能触发再认证；变更效果可用 A/B 说明。

### 8.4 依赖关系

```text
指标补齐 ──> 稳健性报告 ──> 评估门槛收紧
   │                │
   │                └──> 参数平原/联合扰动
   ├──> 健康归因扩展
   └──> 组合回测 ──> 交叉测试资金口径 ──> 多品种实盘
滑点日志 ──> 执行校准 ──> 上线评审单校准值
研究治理（独立，可与批次 1/2 并行）
```

### 8.5 不建议现在做

- 一上来就改多品种实盘：没有组合回测与执行校准，等于把单品种结论直接放大。
- 用复杂权重优化器替代简单分配：样本不够时，最优权重本身就是过拟合。
- 先上 tick 级回测再补日线/分钟级稳健性：投入大，且当前瓶颈不在撮合精度。
- 为了“指标好看”放宽评估门槛：门槛一旦可以商量，整套流程就失效。

### 8.6 第一迭代建议

只做四件事，全部不碰交易链路：

1. 指标补齐；
2. 试验全量留痕；
3. 稳健性报告（只读）；
4. 滑点校准记录。

四件事完成后，再决定是否收紧评估门槛、是否启动组合层。
