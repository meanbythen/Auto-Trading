# 期权交易可行性评估

> 结论：**现有基座支持期权交易，但必须做低侵入改造（B 档）；架构不需要大改。**
> 详细方案见 [spec.md](spec.md)，任务分解见 [tasks.md](tasks.md)。

## 0. 一句话回答

不做任何代码修改，**不能**直接交易期权；新增 4 个期权模块 + 修改 8 处现有小逻辑（不动主循环、执行抽象、对账、告警），
即可在现有期货基座上跑买方期权策略（黑天鹅对冲 + 末日投机）。卖方保证金与组合保证金列为二期。

三项硬性前置：

1. **合约代码解析统一**：现有十几处按「去掉数字、剩下全是品种」解析，`rb2601C3500` 会变成品种 `rbc`。
2. **期权保证金/权利金口径**：`PositionSizer` 只有「价格 × 乘数 × 保证金比例%」的期货公式。
3. **到期/行权生命周期**：全代码没有到期日、最后交易日、行权、被指派处理。

## 1. 当前项目是否适合添加期权自动交易功能？

适合。原因是现有基座的可复用面很大：

- **数据层**：`KlineProvider` 以合约为键取 K 线、写本地库，天然支持任意合约名。
- **策略层**：`REGISTRY` 注册即生效；`LegStrategyRouter` 支持一品种一条腿、期货与期权混排。
- **风控层**：`calc_open` 统一取「意图 / 保证金上限 / 单笔上限」的最小值，结构本身与品种无关。
- **执行层**：CTP 报单只填 `InstrumentID / Direction / CombOffsetFlag / LimitPrice / VolumeTotalOriginal`，
  期权标准限价单用同一套字段。
- **运维层**：挂单检测、三方对账、冻结、告警、账本、调度全部与品种无关。

不适合的部分集中在三处：合约解析、卖方保证金、到期行权。都是可隔离的新模块，不牵连主链路。

## 2. 不修改基座能否加期权策略？架构是否需要大改？

### 2.1 判定：B 档（低侵入），不需要大改

| 档位 | 判定 |
| --- | --- |
| A 零改动，填代码即可 | 否 |
| **B 新增模块 + 少量改动，不动架构** | **是，推荐** |
| C 必须重写数据/执行/账本主链路 | 否 |

## 3. 期权交易缺失哪些必要功能？

| 能力 | 现状 | 影响 | 本期处理 |
| --- | --- | --- | --- |
| 期权合约解析 | 无，按去字母处理 | 合约表、乘数、tick 全错 | 新增 `domain/options.py` |
| 期权元数据 | 品种表无期权列 | 无法知道到期/行权价/方向 | 新增 5 列 + `option_contract.py` |
| 权利金口径 | 只有期货保证金公式 | 买方算仓失真 | 买方按 100% 比例等价权利金 |
| 卖方保证金 | CTP 可查，未接入口径 | 卖方无法安全开仓 | 新增 `option_margin.py`，缺数据拒开 |
| 到期/行权/被指派 | 完全缺失 | 到期会行权或作废 | 新增 `option_lifecycle.py`，到期前强平 |
| 希腊值 | 完全缺失 | 无法做 delta 对冲/IV 策略 | 二期本地 B-S |
| 期权回测 | 无权利金历史 | 无法回测 | 二期独立回测器 |
| 交易权限 | 柜台/交易所开通 | 非代码问题 | 实盘前确认 |

## 4. 期权 Tick、K 线、希腊值数据是否齐全？

- **K 线 / Tick**：天勤（tqsdk）支持期权合约行情，格式为 `交易所.合约`，例如 `SHFE.rb2601C3500`、
  `DCE.m2601-C-3000`、`CZCE.SR605C6000`、`CFFEX.IO2512-C-4000`。
  本项目已用天勤做主源，修好 `tq_symbol()` 即可拉取；本地库存、断流检测、stale 判定全部复用。
  新浪备用源没有商品期权分钟线，必须显式拒绝，不能静默回退。
- **希腊值**：**不齐全**。天勤不直接下发 Greeks，项目内也没有 B-S 计算。
  本期策略只用权利金价格和隐含波动率阈值，不依赖 Greeks；delta/gamma/theta/vega 列为二期。
- **合约静态信息**：CTP `ReqQryInstrument` 已返回乘数、最小变动、上市日、到期日、产品类型，
  `ReqQryInstrumentMarginRate` 已返回保证金比例，数据源齐备，只差落表和读取。

## 5. 两个交易方向的落地方式

### （1）期权对冲期货，防黑天鹅

- 新增 `option_hedge` 策略腿，读取现有期货持仓与名义金额，按保护比例买入虚值 put（多头保护）或 call（空头保护）。
- 复用 `BUY_OPEN`、对手价限价、组合腿配额、告警与对账。
- 权利金单独设预算上限（`risk.option_premium_budget_pct`），不挤占期货保证金配额。
- 到期前 3 个交易日提示，最后交易日收盘前强平，避免行权。

### （2）赌末日期权大幅回报

- 新增 `option_long` 策略腿，选剩余 1-5 天、平值附近合约，按权利金突破/IV 变化入场。
- 入场价即权利金，止损价按权利金回撤比例；单笔最大亏损 = 权利金 + 手续费，天然符合「以损定开」。
- 合约表把买方 `margin_rate_pct` 配成 100，`margin_for()` 结果正好等于权利金，算仓与仓位上限零改动。
- 到期日当天只平不开，收盘前强平。

## 6. 参考资料的使用

- 赫尔《期权、期货及其他衍生产品》第 11 版：用于确定无套利定价、希腊值定义、组合保证金与行权规则；
  本期只落地「买方 + 到期强平」，Greeks 与组合保证金在二期按书中公式实现。

## 7. 实施顺序与验收

1. 阶段 A：本评估文档（已完成）。
2. 阶段 B：符号解析 + 数据源 + 合约元数据 + tick。
3. 阶段 C：权利金/保证金风控口径。
4. 阶段 D：两个策略 + 到期生命周期 + 执行钩子。
5. 阶段 E：单测、回归（pytest/ruff/mypy）、仿真冒烟、CHANGELOG/README/VERSION。

验收口径：期权仿真账户能查到合约、下 1 手虚值期权限价单、撤单、对账、告警、账本留痕；
缺保证金/缺到期日/缺 tick 时一律拒开并告警，风控仍是最高优先级拦截。
