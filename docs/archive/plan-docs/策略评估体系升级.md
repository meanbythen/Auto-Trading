# 策略评估体系升级（v44.4.0）

## 一、目标

把现有「回测出一堆数字、人自己看着判断」升级成一套统一、可复用、有明确结论的评估体系，覆盖四个场景：

1. **历史回测**：结果出来就给「通过 / 观察 / 淘汰」三档结论，并列出不达标项。
2. **交叉测试 / 策略筛选**：每一行（策略×合约×周期）带评估结论，表格标红/标黄。
3. **策略优化**：不达红线直接 `accepted=False`，不写入参数；保留现有三道门槛。
4. **复盘**：新增「当日重放评估」和「最近实盘 vs 最近回测」两节。

评估口径综合现有程序指标（盈利因子、收益期望、盈利覆盖、回撤）与用户新增的 [评估指标.md](file:///d:/Auto-Trading/docs/策略评估标准/评估指标.md)：补上 Calmar、最大连续亏损、回撤持续期、ADX 趋势/震荡分组、滑点压力测试、参数扰动鲁棒性。用户已确认：**做指标+门槛+界面展示、加参数扰动、加滑点压力、优化不达标拦截写入、回测统一记录 ADX、复盘两种口径都要**。

## 三、方案

### 3.1 新建 `src/backtest/evaluation.py`（核心）

只依赖 `src.backtest.metrics` 与标准库；**不 import engine**（engine 反向 import 本模块），类型注解用 `from __future__ import annotations` + `TYPE_CHECKING` 规避循环。

**门槛数据类**（字段名即 YAML 键）：

```python
@dataclass(frozen=True)
class EvaluationThresholds:
    enabled: bool = True
    adx_period: int = 14
    adx_trend_min: float = 20.0
    stress_on_backtest: bool = True
    gate_on_optimize: bool = True

    profit_factor_min: float = 1.3
    profit_factor_excellent: float = 1.5
    r_expect_min: float = 0.12
    r_expect_excellent: float = 0.20
    calmar_min: float = 1.0
    calmar_excellent: float = 1.5
    calmar_red: float = 0.8
    max_drawdown_pct: float = 0.15
    max_drawdown_pct_excellent: float = 0.10
    max_drawdown_pct_red: float = 0.20
    profit_cover_min: float = 0.0
    trades_min: int = 150
    trades_observe: int = 100
    trades_excellent: int = 250
    max_consecutive_losses: int = 8
    max_consecutive_losses_excellent: int = 5
    range_pf_max: float = 1.0
    range_trade_share_max: float = 0.30
    slippage_extra_ticks: float = 1.0
    slippage_pf_min: float = 1.2
    slippage_pf_red: float = 1.0
    perturbation_step_pct: float = 0.10
    perturbation_pf_ratio: float = 0.80
    perturbation_pf_min: float = 1.10
    stress_min_trades: int = 30

    @classmethod
    def from_cfg(cls, cfg: dict) -> "EvaluationThresholds": ...
    def to_cfg(self) -> dict[str, Any]: ...
```

`from_cfg` 读 `cfg["evaluation"]`，缺键/非法值一律回落默认值并做上下限夹紧（PF≥0、回撤 0~1、笔数≥0、扰动步长 0~0.5）。

**检查项与报告**：

```python
@dataclass
class EvaluationCheck:
    key: str          # profit_factor / r_expectancy / calmar / ...
    label: str        # 盈利因子 / R期望 / 卡尔玛 / ...
    value: float | str
    threshold: str
    status: str       # pass / watch / fail / skip
    note: str = ""

@dataclass
class EvaluationReport:
    checks: list[EvaluationCheck] = field(default_factory=list)
    metrics: dict[str, float] = field(default_factory=dict)
    conclusion: str = "watch"   # pass / watch / reject
    skipped: str = ""           # 整份跳过时的原因

    def recompute(self) -> None: ...          # 有 fail→reject；否则有 watch→watch；否则 pass
    def failed_labels(self) -> list[str]: ...
    def failed_text(self) -> str: ...         # “盈利因子、卡尔玛、滑点”
    def to_dict(self) -> dict[str, Any]: ...
    def add_check(self, check: EvaluationCheck) -> None: ...
```

结论规则（严格遵守用户文档红线）：

- `fail`（红线）：PF < 1.3；Calmar < 0.8；回撤 > 20%；样本 < 100；滑点+1 后 PF < 1.0；参数扰动出现断崖（任一扰动点净亏或 PF < `max(perturbation_pf_min, ratio×基准PF)`）；震荡组 PF > 1.0 且震荡组开仓占比 > 30%（“震荡大量开仓持续亏钱”）。
- `watch`（勉强/观察）：PF 在 1.3~1.5；R 期望 0.12 以下（但 >0）；Calmar 0.8~1.0；回撤 15%~20%；盈利覆盖 ≤ 0；样本 100~149；最大连亏 6~8；滑点后 PF 1.0~1.2；震荡组 PF > 1.0 但占比 ≤ 30%。
- `pass`：全部达最低门槛；达标且达到 excellent 的在 note 写“优秀”。
- `skip`：数据不足无法计算（例如没有 ADX 快照、回测本身 0 笔、压力测试未启用），不参与结论。

**指标计算**（放在本模块，供评估与测试复用）：

- `max_consecutive_losses(trades)`：按 `exit_time` 排序后数连续 `pnl<=0` 的最长串。
- `drawdown_duration(equity, times)`：权益新高到最后一次见到低点之间的自然日跨度，只展示不设门槛。
- `annual_return`：`(net_pnl / capital) × (252 / days)`；`days = max(1, (末日-首日).days)`，日期取 `equity_times` 首尾，缺失时退回 `data_from/data_to`；`capital` 取 `result.params_snapshot["capital"]`，≤0 时用 `margin_used`，再不行用 1。
- `calmar = annual_return / max_drawdown_pct`；回撤为 0 时记 `inf`，展示为“—”。
- `r_expectancy`：直接复用 `metrics.unit_expectancy(win_rate, avg_win, avg_loss)`，不重复扣手续费（成交已扣）。
- `profit_cover = net_pnl - max_drawdown`。
- `adx_groups(trades, trend_min)`：按 `TradeRecord.adx_at_entry` 分组，`>= trend_min` 为趋势组，`< trend_min` 为震荡组；用 `calc_performance` 计算各组笔数、PF、净盈亏、胜率，并算震荡组笔数占比。**全部成交都没有 ADX 值时返回 `None`，该检查 skip。**

**对外函数**：

```python
def evaluate_backtest(result: Any, *, thresholds: EvaluationThresholds | None = None) -> EvaluationReport
def evaluate_day(quality_trades: list[Any], *, thresholds: EvaluationThresholds | None = None) -> EvaluationReport
def evaluate_perf(perf: dict[str, Any], *, trades: list[Any] | None = None, ...) -> EvaluationReport
def format_evaluation_lines(report: EvaluationReport, *, title: str = "策略评估") -> list[str]
def verdict_text(report: EvaluationReport) -> str        # 通过 / 观察 / 淘汰
def verdict_tag(report: EvaluationReport) -> str         # 一行短标签：通过(0项观察)
```

`evaluate_backtest` 通过 duck typing 读 `result.performance/trades/equity/equity_times/params_snapshot`，不 import engine。
`evaluate_day` 用 `profile="day"` 的口径：只检查 PF、R 期望、最大连亏、ADX 分组（有 ADX 时），把样本/Calmar/盈利覆盖/滑点/扰动标 skip，避免当天几笔交易被“样本不足”误判为淘汰。

### 3.3 新建 `src/backtest/stress.py`（滑点 + 扰动）

模块只 import `src.backtest.engine`（`run_backtest`、`fill_bars_by_range` 如需要）；**不 import optimizer**，参数名由调用方传入，避免与 optimizer 循环依赖。

```python
def run_slippage_stress(cfg, *, symbol, start_date, end_date, engine,
                        extra_ticks=1.0, chain_capital=False, runner=None) -> dict[str, Any]
def perturb_param_set(cfg, param_keys: list[str], *, step_pct=0.10,
                      max_points=4) -> list[tuple[str, float, dict[str, Any]]]
def run_perturbation(cfg, *, symbol, start_date, end_date, engine,
                     param_keys, base_pf: float, thresholds,
                     chain_capital=False, runner=None,
                     on_step=None, cancel=None) -> dict[str, Any]
```

- `run_slippage_stress`：`copy.deepcopy(cfg)`，把 `backtest.slippage_ticks` 提高 `extra_ticks`（基准取当前值），调 `runner`（默认 `run_backtest`；换月开关由调用方传 `runner=run_backtest_rollover` 的封装），返回 `{ok, base_ticks, stress_ticks, profit_factor, net_pnl, trades, error}`。
- `perturb_param_set`：只挑**数值型**参数，跳过布尔/字符串/日期；优先用 `param_keys`（优化器传入 `default_grid_for_engine` 的键）；不足 4 个时从当前配置数值键补齐；每个键生成 `× (1±step_pct)` 两个方向，最多取 4 个点（2 键 × 2 方向），整数参数四舍五入到 ≥1。
- `run_perturbation`：逐点跑回测，记录每点 PF/净盈亏/参数；判定 `cliff=True` 当任一点 `net_pnl<=0` 或 `pf < max(thresholds.perturbation_pf_min, thresholds.perturbation_pf_ratio * base_pf)`；返回 `{ok, points, cliff, worst_pf, error}`。
- 所有函数支持注入 `runner`，测试时用假回测，避免真的跑行情。

## 六、假设与决策

- **门槛来源**：默认值完全照 `评估指标.md` 第三节；用户可在配置页改，但默认值与文档一致。
- **Calmar 的 capital**：优先回测快照里的起始资金；为 0（如部分筛选场景）时退回峰值保证金，保证不除零。
- **ADX 分组只做评估**：不改变任何策略自己的 ADX 过滤逻辑；`adx_at_entry` 只是记录。
- **无 ADX 数据**：老结果文件、或 ADX 预计算失败时，分组检查 `skip`，不判淘汰。
- **压力测试范围**：只在历史回测和策略优化里跑；交叉测试不跑，避免组合数乘 5。
- **扰动参数范围**：只扰动当前策略的数值参数，最多 4 个点；参数名优先取优化网格（`default_grid_for_engine(engine, "标准").keys()`），不全时从当前配置数值键补齐。
- **拦截范围**：仅优化结果 `accepted` 被置 False；历史回测/交叉测试只标红，不阻止查看或导出，符合用户选择。
- **复盘当日重放**：用点数口径算 PF/R/连亏，样本与资金类门槛 skip，避免几笔交易被误判“淘汰”。
- **不改现有三道优化门槛**，评估是叠加层。
