# 策略评估模块详细说明

适用版本：44.6.3  
更新日期：2026-11-14  
核心实现：`src/backtest/evaluation.py`、`src/backtest/stress.py`

## 一、模块解决什么问题

评估模块把历史回测、交叉测试、策略优化和复盘放入同一套检查框架，统一回答四个问题：

1. **盈利能力是否足够**：利润是否只是很薄的一层，能否承受费用、滑点和行情变化。
2. **回撤是否可承受**：历史最大亏损区间有多深，净利润能否覆盖这段回撤。
3. **结果是否可信**：样本是否足够，是否只在一个参数点或一种行情下碰巧有效。
4. **样本外是否保持**：训练段有效的规则，在检验段、滚动窗口和其他品种上是否仍然成立。

模块输出“通过 / 观察 / 淘汰”，同时列出每一项检查的实际值、门槛、状态和原因。

> “通过”只表示历史结果达到当前研究门槛，有资格继续模拟盘和样本外验证；不代表未来一定盈利。“淘汰”表示当前证据触及红线，不等于用数学证明策略永远无效。

## 二、设计原则

### 2.1 红线和观察项分开

- **红线（fail）**：利润缓冲不足、极端回撤、压力后失去盈利能力、参数轻微变化就崩塌等。
- **观察项（watch）**：尚未触碰红线，但还没有达到交付要求，例如 R 期望偏薄、样本不足、盈利覆盖不足。
- **跳过（skip）**：数据不足或该场景不适合计算，不能把“算不出”当成达标。

### 2.2 综合得分不能抵消红线

`Performance.score` 主要用于参数和组合排序。评估结论由各项检查独立决定：

- 盈利因子高，不能抵消样本不足带来的不确定性。
- 净盈利高，不能抵消最大回撤红线。
- 训练段得分高，不能抵消检验段或压力测试失败。

### 2.3 不同场景使用不同严格程度

- **历史回测、交叉测试**：展示结论和原因，不因为淘汰就自动修改配置。
- **策略优化**：保留原样本外门槛，再叠加新评估；出现红线且开启拦截时，不允许写入。
- **当日复盘**：样本天然很少，只观察信号质量，不套用长期样本和资金曲线门槛。


## 四、结论和检查状态

### 4.1 检查项状态

每个 `EvaluationCheck` 都有以下字段：

| 字段 | 含义 |
|---|---|
| `key` | 稳定的程序标识，如 `profit_factor` |
| `label` | 界面显示名称，如“盈利因子” |
| `value` | 本次实际值，已格式化为便于阅读的字符串 |
| `threshold` | 该项门槛的文本说明 |
| `status` | `pass`、`watch`、`fail`、`skip` |
| `status_text` | “达标”“仅够观察”“不达标（红线）”或“—” |
| `note` | 优秀、低于门槛、缺少数据等补充原因 |

### 4.2 总体结论

`EvaluationReport.recompute()` 使用以下优先级：

```text
任一检查 fail    → conclusion = reject，显示“淘汰”
否则任一 watch   → conclusion = watch，显示“观察”
否则             → conclusion = pass，显示“通过”
skip 不参与优先级判断
```

注意命名差异：单项失败状态叫 `fail`，总体淘汰结论叫 `reject`。

如果评估未启用或完全没有成交，`skipped` 会记录原因，表格显示“未评估”，不能把报告默认的 `watch` 字段当成有效结论。

## 五、基础指标定义与门槛

### 5.1 成交分类约定

基础绩效按已平仓成交计算：

- `pnl > 0`：盈利笔。
- `pnl <= 0`：亏损笔；因此零盈亏也计入亏损笔和连续亏损。
- 胜率 = 盈利笔数 ÷ 总成交笔数。
- 总亏损金额取亏损笔盈亏绝对值之和。
- 平均亏损在公式中用正数表示。

回测成交盈亏通常已经计入手续费和回测滑点，计算 R 期望时不会再次重复扣费。

### 5.2 指标总表

| 指标 | 计算与含义 | 默认合格线 | 默认红线/观察规则 | 设定依据 |
|---|---|---|---|---|
| 样本量 | 已平仓成交笔数，反映结果所依据的观测数量 | 参考 ≥150 笔 | <100 笔为 watch，说明“统计显著性不足”；100～149 笔为 watch；≥250 笔记“优秀”；不判 fail | 笔数少代表不确定，不代表策略无效。100/150/250 是研究筛选经验线，系统同时给出覆盖年限和每年笔数，供人工判断样本密度 |
| 盈利因子 PF | 总盈利 ÷ 总亏损绝对值，表示利润对成本、滑点和行情漂移的缓冲 | ≥1.30 | <1.30 直接 fail；≥1.50 记“优秀” | PF 只略大于 1 时，少量额外成本即可吞掉利润；1.30 用作最低缓冲，1.50 作为更充足缓冲 |
| R 期望 | 胜率 ×（平均盈利÷平均亏损）−（1−胜率），表示每承担 1 单位平均亏损，历史平均期望收益 | ≥0.12R | <0.12 为 watch；≥0.20R 记“优秀”；没有亏损笔时 skip | 0 附近是薄期望，容易被执行误差吞掉；0.12/0.20 是日内策略研究门槛，不是收益保证 |
| 卡尔玛 Calmar | 简化年化收益率 ÷ 最大回撤比例，衡量收益与回撤的交换效率 | ≥1.00 | <0.80 为 fail；0.80～0.99 为 watch；≥1.50 记“优秀”；无回撤时 skip | CTA 评估需要同时看收益和回撤，不能只看净盈利 |
| 最大回撤 | 权益从历史峰值到后续低点的最大金额下跌；同时记录该最大金额回撤发生处的峰值相对跌幅 | 合格 ≤15% | >20% 为 fail；>15%且≤20%为 watch；≤10%记“优秀” | 小资金账户对深回撤更敏感；回撤越深，恢复所需收益越高 |
| 盈利覆盖 | 净盈亏 − 最大回撤金额 | >0 | ≤0 为 watch，不是独立 fail | 要求整个区间最终利润至少能覆盖历史最深回撤，避免“赚得很辛苦且曾亏得更多” |
| 最大连续亏损 | 按平仓时间排序，最长连续 `pnl<=0` 的成交串 | ≤8 笔 | >8 笔为 watch；≤5 笔记“优秀” | 用于描述执行和心理压力，辅助检查仓位与连续止损承受能力 |
| 震荡组 | 开仓 ADX 低于趋势线的成交组，检查组内 PF 和成交占比 | 默认 PF≤1.00、占比尽量低 | PF>1.00 且占比>30%为 fail；PF>1.00但占比≤30%为 watch；无 ADX 时 skip | 当前规则用于发现“策略设计要过滤震荡，但震荡组却大量交易且持续盈利”的异常归因 |

#### 5.2.1 样本为什么用笔数，不用采样率

采样率（笔数 ÷ K线数，或笔数 ÷ 年）描述的是交易频率，不是估计精度：

- 同一个策略在 1 分钟周期上采样率很高，但大量开平共享同一段行情，独立观测并没有变多。
- 长线策略一年只有几次开仓，采样率很低，但跨 5 年、覆盖多轮涨跌后，样本仍然有参考价值。
- 统计显著性取决于独立观测数 N 和每笔结果的离散度，不取决于“占了多少根K线”。

因此系统保留笔数作为提示，不把采样率做成门槛。低于观察线时：

- 状态为 watch，综合结论最多到“观察”，不判红线，不会单独把策略淘汰。
- 说明里同时给出覆盖年限和每年笔数，例如“样本偏少，覆盖 3.2 年约 9 笔/年，参考 100～150 笔；统计显著性不足，结论仅供参考”。
- 样本密度交给人工判断：日内策略可用历史回测页换更长区间，长线策略结合多品种、多周期和样本外结果一起看。

如果确实希望样本完全不参与结论，可以把 `evaluation.trades_observe` 和 `evaluation.trades_min` 都设为 0。

### 5.3 盈利因子的特殊情况

`calc_performance()` 对“有盈利、没有任何亏损笔”的结果使用 PF=99 作为程序约定，避免除零。它不表示真实存在无限利润缓冲：

- R 期望仍会因为平均亏损为 0 而 skip。
- 样本量只提示，不判红线；笔数少时结论最多压到观察。
- 少量全胜交易不能仅凭 PF=99 获得可信结论。

### 5.4 R 期望与盈亏比的区别

- **盈亏比**：平均盈利 ÷ 平均亏损，只看盈利单和亏损单的平均幅度。
- **R 期望**：在盈亏比之上再加入胜率，表示长期平均每笔的风险单位收益。
- **盈利因子**：总盈利 ÷ 总亏损，还受到盈利笔数和亏损笔数影响。

三者不能混用。胜率和盈亏比本身没有独立硬门槛，因为低胜率高盈亏比与高胜率低盈亏比都可能成立。

### 5.5 年化与卡尔玛的实际口径

当前实现采用简单折算，不做复利：

```text
自然日天数 = max(1, 结束时间 − 开始时间的自然日数)
年化收益率 = 净盈亏 ÷ 评估本金 × 252 ÷ 自然日天数
Calmar = 年化收益率 ÷ 最大回撤比例
```

口径细节：

1. 时间优先取 `equity_times` 首尾；缺失时使用快照中的 `data_from/data_to`。
2. 评估本金优先取 `params_snapshot.capital`；为 0 时退回峰值保证金，再为 0 时使用 1，避免除零。
3. 不足一天按一天计算，短区间的年化可能被显著放大。
4. 252 是程序当前采用的年化系数，但天数按自然日差计算；比较外部平台结果前必须先统一口径。
5. 最大回撤为 0 时，Calmar 检查记 skip，而不是把无限大当作优秀。

### 5.6 最大回撤与回撤持续期

最大回撤金额和比例来自权益曲线：

```text
每个时点：回撤 = 此前权益峰值 − 当前权益
最大回撤：所有时点中的最大回撤金额
回撤比例：该最大金额回撤 ÷ 对应此前权益峰值
```

`drawdown_days` 记录最大金额回撤从峰值到谷底相隔的自然日数：

- 有完整 `equity/equity_times` 时计算。
- 缺少时间轴或长度不一致时返回 0。
- 当前只写入 `metrics`，**不参与通过、观察或淘汰判定**，也没有修复期门槛。

因此，不能把 `drawdown_days=0` 直接理解为“当天修复”。

### 5.7 盈利覆盖不是亏损概率

例如：

```text
净盈亏 = 6,000
最大回撤 = 13,000
盈利覆盖 = 6,000 − 13,000 = -7,000 → 观察
```

它只比较历史总利润和历史最大回撤，不表示未来一定还能修复，也不是最大可能亏损。

## 六、ADX 趋势/震荡分组

### 6.1 数据如何产生

历史回测会基于信号 K 线的 high/low/close 单独计算评估用 ADX：

- 默认周期：`evaluation.adx_period=14`。
- 默认趋势线：`evaluation.adx_trend_min=20`。
- 开仓时把当前信号位置的 ADX 写入 `open_meta.adx_at_entry`。
- 平仓生成 `TradeRecord` 时保留该字段。
- 它用于评估分组，不等同于各策略自己的 ADX 过滤开关。

### 6.2 分组规则

```text
adx_at_entry >= 20 → 趋势组
adx_at_entry < 20  → 震荡组
adx_at_entry 缺失  → 不参与分组
```

每组可计算笔数、净盈亏、胜率和 PF。全部成交都缺少 ADX 时，震荡组检查为 skip；只有部分成交有 ADX 时，分组只基于有快照的成交。

### 6.3 当前震荡组规则应怎样理解

当前代码判定的是：

```text
震荡组有成交
且震荡组 PF > 1.0
且震荡组成交占全部有 ADX 成交的比例 > 30%
→ 红线
```

PF>1.0 但占比未超过 30%时为观察。该规则的目的，是提示“原以为 ADX 会过滤的行情却贡献了大量利润”，需要检查策略归因和过滤假设。

它不是所有策略都适用的普遍定律：

- 震荡组亏损不会让这一项单独失败，但整体 PF、净盈亏和回撤仍可能失败。
- 对专门做震荡反转的策略，应在解读时结合策略设计，不能机械追求震荡组亏损。
- 这项检查不替代人工抽查成交和分行情验证。

## 七、压力测试

压力测试只在历史回测和策略优化中接入，交叉测试不自动执行。

### 7.1 触发条件

同时满足以下条件才执行：

1. `evaluation.enabled=true`。
2. `evaluation.stress_on_backtest=true`。
3. 基准回测成交笔数 ≥ `stress_min_trades`，默认 30 笔。

样本不足时，历史回测页显示“压力测试 跳过”。不会用少量交易强行给出压力结论。

### 7.2 滑点压力

执行方式：

```text
压力滑点 = 当前 backtest.slippage_ticks + slippage_extra_ticks
默认基准滑点 1 跳，压力再加 1 跳，然后完整重跑一次回测
```

基准滑点为 0 时，审计会提示压力结果不能当作含真实滑点的绩效。

判定：

| 加压后 PF | 状态 |
|---|---|
| <1.00 | fail |
| ≥1.00 且 <1.20 | watch |
| ≥1.20 | pass |

默认阈值依据：日内策略对成交价格敏感，基准 PF 合格但加压后跌破 1，说明利润无法覆盖最基本的价格误差；1.20 用作加压后的最低缓冲。

注意：

- 如果基准已经是 1 跳，默认压力就是 2 跳，不是仍然测 1 跳。
- 行情或回测失败时，该项为 skip，并记录错误，不能当作压力通过。
- 返回结果还包含加压后的净盈亏和笔数，但当前检查只直接判定 PF。

### 7.3 参数扰动

默认从当前策略数值参数中选取前两个参数，分别做 +10% 和 −10%，最多形成 4 个扰动点：

- 优先使用调用方传入的 `param_keys`，再按策略参数顺序补足。
- 只处理 int/float，不处理布尔、字符串、日期和时间。
- 整数四舍五入，最小保留 1；如果扰动后值没有变化，该点跳过。
- 每个点都使用同一套回测重新运行。

任一有效扰动点满足以下任一条件，即判定为“断崖”：

```text
净盈亏 <= 0
或
PF < max(perturbation_pf_min, perturbation_pf_ratio × 基准PF)
```

默认：

```text
perturbation_pf_min = 1.10
perturbation_pf_ratio = 0.80
扰动下限 = max(1.10, 0.80 × 基准PF)
```

例如基准 PF=1.60，则扰动下限为 `max(1.10,1.28)=1.28`；基准 PF=1.30，则下限为 `max(1.10,1.04)=1.10`。

设定依据：真正稳健的参数通常应处在一个相对平滑的区域，而不是只有孤立参数点盈利。默认最多两个参数、四个点是成本可控的局部检查，**不是完整参数曲面证明**。

扰动执行中若出现错误，评估项会记 skip；不能只看已经成功的一部分点就认定通过。

### 7.4 压力结果如何合并

`apply_stress()` 会：

1. 删除报告中已有的滑点、参数扰动检查，避免重复调用时叠加旧项。
2. 加入最新压力检查。
3. 把压力 PF、最差扰动 PF等写入 `metrics`。
4. 重新计算总体结论。

压力测试可能把原来的“通过”改为“观察”或“淘汰”。

## 八、历史回测接入流程

### 8.1 单合约回测

`run_backtest()` 的流程为：

1. 运行策略并生成已平仓 `TradeRecord`。
2. 开仓时记录 ADX，平仓时透传到成交。
3. 每根 K 线更新权益，同时追加 `equity_times`。
4. 记录本金、实际数据区间、滑点、保证金等 `params_snapshot`。
5. 用成交和权益计算 `Performance`。
6. 创建 `BacktestResult`。
7. 评估启用时调用 `evaluate_backtest()`，生成基础八项检查。

历史回测页和策略优化的冠军复跑都调用 `evaluate_with_stress()`（`src/backtest/stress.py`）。这个入口负责：

1. 读取 `EvaluationThresholds.from_cfg(cfg)`，判断评估是否启用。
2. 检查压力开关和 `stress_min_trades` 样本门槛，返回“关”或“跳过”的说明。
3. 先执行滑点压力并合并评估，再执行参数扰动并合并评估。
4. 把最终报告写回 `result.evaluation`，并返回滑点结果、扰动结果和压力说明。

因此压力门槛、执行顺序和提示文案只维护一份，历史回测页与策略优化不会各自演化出不同口径。

历史回测页随后在同一个后台任务中：

1. 调用 `evaluate_with_stress()`。
2. 保存 `data/backtest_last.json`。
3. 在结果区显示基础绩效、压力说明和完整评估明细。

因此，新版历史回测保存的是**合并压力检查后的评估**；重新打开旧版 JSON 时，如果没有 `evaluation`，只能视为历史遗留结果，不能声称已经完成新版评估。

### 8.2 主力换月回测

`run_backtest_rollover()` 不对各段评估取平均，而是：

1. 拼接各合约段的成交。
2. 按资金口径平移并连接权益曲线。
3. 同步拼接 `equity_times`，去除分段边界重复点。
4. 用合并后的成交和权益重新计算整体绩效。
5. 对整体结果重新执行 `evaluate_backtest()`。

历史回测页执行压力测试时，会通过注入 runner 继续使用换月回测，而不是退化为单合约回测。

## 九、交叉测试接入流程

交叉测试的每个“策略 × 合约 × 周期”组合都是一次普通历史回测：`_run_cross_backtest()` 按选定条件准备配置和手数后调用同一个 `run_backtest`，再由 `_fill_backtest_row()` 把成绩写入结果行。单品种优选、比策略和交叉测试共用这套写入逻辑。

结果行除原有胜率、盈利因子、盈亏比、收益期望、最大回撤、净盈亏、盈利覆盖、收益率、交易频率和笔数外，还补齐：

| 字段 | 内容 |
|---|---|
| `evaluation` | “通过 / 观察 / 淘汰 / 未评估 / 评估失败” |
| `verdict` | 程序结论，如 `pass/watch/reject/skip` |
| `fail_items` | 红线名称，供界面或导出进一步说明 |
| `r_expectancy` | R 期望，与历史回测同一指标 |
| `calmar` | 卡尔玛比率 |
| `consecutive_losses` | 最大连续亏损笔数 |
| `eval_checks` | 完整检查项列表，含实际值、门槛和状态 |
| `eval_metrics` | 评估报告中的全部指标 |

界面和导出新增“R期望”“卡尔玛”“最大连亏”“未通过项”列；“评估”列按通过绿色、观察黄色、淘汰红色显示。

边界：

- 交叉测试直接使用 `run_backtest` 按当前配置门槛生成的 `result.evaluation`，不再在表格层用默认门槛另算一套；评估未启用或没有成交时显示“未评估”，与历史回测页一致。
- 交叉测试默认只使用单次回测产生的基础评估，**不自动跑滑点和参数扰动**，避免组合数量放大回测次数。
- 评估结论用于提示，不会单独修改“入选/名次”的原有排序逻辑，也不会自动改实盘配置。

## 十、策略优化接入流程

### 10.1 旧门槛仍然保留

新评估不是替换样本外检验，而是在原有流程最后叠加。

#### 第一关：训练与检验段

`judge_holdout()` 当前规则：

- 训练段净盈亏≤0：不写入。
- 检验段没有成交：旧规则允许继续，但明确提示不能据此证明样本外盈利。
- 检验段净盈亏≥0：通过这一关。
- 检验段亏损超过训练段盈利的一半：不写入。
- 检验段小亏但未超过一半：旧规则允许继续并提示复核。

#### 第二关：滚动前进

仅在滚动前进模式且有效段数至少 2 段时额外拦截：

- `oos_win_rate`：检验段净盈利为正的滚动段占比，至少 50%。它不是逐笔交易胜率。
- `walk_efficiency`：拼接检验净盈亏 ÷ 最后一段训练净盈亏，至少 0.30。
- 段数少于 2 时只展示稳健性信息，不用这两项拦截。

一次切断模式也会计算检验效率供查看，但不套用滚动段数门槛。

#### 第三关：多品种验收

最优参数不再重新搜索，直接用于其他关注品种：

- 某品种亏损绝对值超过训练盈利的一半，记为“大亏”。
- 大亏品种超过可用验收品种的一半时，不写入。
- 大亏品种不到一半时，旧规则允许继续，但保留人工复核提示。
- 没有可用其他品种时只提示，不以这一项拦截。

### 10.2 新评估与写入拦截

完成上述流程后：

1. 保留最后训练段的 `best_result`，其 `params_snapshot` 继续用于 `best_limits`，训练成绩、检验成绩和旧验收结论不被全区间结果覆盖。
2. 通过 `_apply_params(cfg, best_params, engine_name)` 生成冠军配置 `eval_cfg`，在完整请求 `start_date/end_date` 上独立复跑，得到 `eval_result`。
3. 对 `eval_result` 调用 `evaluate_backtest()`；压力样本门槛也读取全区间成交笔数。
4. 随后调用与历史回测页相同的 `evaluate_with_stress()`：滑点和扰动均使用同一个 `eval_cfg`、品种和完整日期区间；扰动基准 PF 取 `eval_result.performance.profit_factor`。
5. 合并压力检查，重算结论。
6. 若结论为 `reject`，或全区间评估失败、没有成交等原因导致报告 `skipped`：
   - `evaluation_ok=false`；
   - `evaluation_reason` 记录红线或评估失败原因；
   - 当 `gate_on_optimize=true` 时，强制 `accepted=false`，追加“不写入”原因。
7. 若结论为 `watch`，当前不会仅因观察项强制拦截，最终仍结合旧门槛决定 `accepted`。

`gate_on_optimize=false` 只关闭写入拦截，不会把红线或评估失败改成通过；`evaluation_ok=false`、失败原因和评估明细仍会保留。

### 10.3 优化评估的同口径复跑

从 44.5.0 起，主评估、滑点和参数扰动统一为“**冠军参数 + 完整请求区间 + 全区间基准 PF**”：

- 不再拿最后训练段的主评估搭配原始配置、完整区间的压力结果。
- 扰动是在冠军参数基础上继续做 ±10%，不是从优化前的原始参数出发。
- 压力是否达到样本门槛由全区间成交决定，不能由训练段笔数代替。
- 全区间复跑失败时明确记为未评估，不回退到训练段结果冒充评估成功。
- 每次启用优化评估会增加一次完整区间冠军回测；达到压力样本门槛后，还会按原规则增加滑点和扰动回测。

统一口径只消除参数、区间和基准 PF 的错配，不代表全区间评估取代了样本外检验。正式交付仍须结合保留检验段、滚动前进、多品种结果和后续模拟成交共同判断。

### 10.4 优化结果保存与展示

`OptimizationResult` 新增：

- `evaluation`：完整评估报告字典。
- `slippage`：滑点压力原始结果。
- `perturbation`：扰动点明细和最差结果。
- `evaluation_ok`：评估是否已完成且没有红线；报告 skipped 时也为 false。
- `evaluation_reason`：红线、评估失败原因，以及本次是拦截写入还是仅提示。

优化页追加完整评估文本；导出的“优化结果”工作表增加“评估”和“未通过项”两列。“未通过项”当前来自 `failed_items`，即红线项，不包含全部观察项。

## 十一、复盘接入流程

复盘报告新增“十、当日重放评估”和“十一、最近实盘 vs 最近回测”，原综合章节顺延为第十二节。

### 11.1 当日重放评估

流程：

1. 从 `QualityReport.trades` 取已经闭合的重放交易，排除 `still_open`。
2. 转成评估共用的 `TradeRecord` 结构，并把重放时记录的 `adx_at_entry` 一并透传。
3. 调用 `evaluate_day()`，使用 `profile="day"`。
4. 格式化后写入复盘，不让单次评估异常阻断整份复盘。

当日模式只实际判定：

- 盈利因子；
- R 期望；
- 最大连续亏损；
- ADX 震荡组。

以下项目显式 skip：

- 样本量；
- 卡尔玛；
- 最大回撤资金门槛；
- 盈利覆盖。

也不执行压力测试。这样是为了避免用一天几笔交易套用长期交付标准。

当前重放伪成交的 `pnl` 来自 `pnl_points`，固定 1 手、手续费为 0。所以：

- 它主要用于比较信号质量，不是真实资金收益评估。
- 开仓 ADX 由重放按 `evaluation.adx_period` 计算并透传，震荡组检查与历史回测同口径；早期保存的复盘结果没有该字段时会显示 skip。
- 当日“通过”绝不能替代长期样本验收。

### 11.2 最近实盘 vs 最近回测

该部分复用 `ops.health.evaluate_health()`，展示：

- 实盘最近若干笔的胜率、PF；
- 最近回测的胜率、PF；
- 胜率差（实盘−回测）；
- 实盘 PF ÷ 回测 PF；
- 原有健康检查结论；
- `backtest_last.json` 中已有的评估结论；
- `backtest_last.json` 中的 R 期望、卡尔玛、最大连亏。

若最近回测 PF 低于当前 `profit_factor_min`，报告追加提醒。

当前实盘账本对照**暂不按品种拆分**，最近回测也未必与当前复盘品种、策略相同。因此这一节用于发现执行衰减和数据异常，正式归因前必须先核对品种、策略、周期和时间区间。

## 十二、配置说明

### 12.1 配置页可直接修改的字段

配置页“策略评估”卡片提供：

- `enabled`：是否启用评估。
- `stress_on_backtest`：历史回测及优化达到样本条件后是否执行压力测试。
- `gate_on_optimize`：优化出现红线时是否强制不写入。
- `profit_factor_min`。
- `r_expect_min`。
- `calmar_min`。
- `max_drawdown_pct`，使用小数，例如 0.15 表示 15%。
- `trades_min`、`trades_observe`。
- `max_consecutive_losses`。

保存时，非法数字回退默认值并限制在界面允许范围内。高级门槛和优秀线可直接在 `config.yaml` 的 `evaluation` 块维护。

### 12.2 完整默认门槛参考

```yaml
evaluation:
  enabled: true
  adx_period: 14
  adx_trend_min: 20
  stress_on_backtest: true
  gate_on_optimize: true
  stress_min_trades: 30

  profit_factor_min: 1.3
  profit_factor_excellent: 1.5
  r_expect_min: 0.12
  r_expect_excellent: 0.20

  calmar_min: 1.0
  calmar_excellent: 1.5
  calmar_red: 0.8

  max_drawdown_pct: 0.15
  max_drawdown_pct_excellent: 0.10
  max_drawdown_pct_red: 0.20
  profit_cover_min: 0

  trades_min: 150
  trades_observe: 100
  trades_excellent: 250
  max_consecutive_losses: 8
  max_consecutive_losses_excellent: 5

  range_pf_max: 1.0
  range_trade_share_max: 0.30

  slippage_extra_ticks: 1.0
  slippage_pf_min: 1.2
  slippage_pf_red: 1.0

  perturbation_step_pct: 0.10
  perturbation_pf_ratio: 0.80
  perturbation_pf_min: 1.10
```

`EvaluationThresholds.from_cfg()` 对缺项使用默认值，对非法数字和非法布尔值进行回退，并对部分字段夹取合理范围。修改门槛时应保持以下关系，避免结论难以理解：

```text
trades_observe <= trades_min <= trades_excellent
calmar_red <= calmar_min <= calmar_excellent
max_drawdown_pct_excellent <= max_drawdown_pct <= max_drawdown_pct_red
slippage_pf_red <= slippage_pf_min
```

### 12.3 调整门槛的依据

默认值面向国内期货日内、小资金账户的研究交付筛选，属于审慎的经验起点。调整时应依据：

1. 策略类型：趋势、反转、套利的合理胜率和行情分组不同。
2. 交易频率：高频策略更受滑点影响，低频策略更需要长时间和事件样本。
3. 合约成本：手续费、最小跳动、流动性和实际成交偏差。
4. 账户风险预算：可承受回撤和连续亏损，而不是为了通过结果反向放宽红线。
5. 多样本稳定性：门槛应在多个品种和时间区间保持一致，不能为某一组冠军参数临时定制。

不建议把“提高样本交付线”理解为自动提高统计显著性，也不建议为让策略通过而把 PF、回撤或压力红线调松。

## 十四、开发者接入方法

```python
from src.backtest.evaluation import EvaluationThresholds, evaluate_backtest

thresholds = EvaluationThresholds.from_cfg(cfg)
report = evaluate_backtest(result, thresholds=thresholds)
```

适用于已经有 `performance/trades/equity/equity_times/params_snapshot` 的回测结果。

### 14.2 对已有 Performance 评估

```python
from src.backtest.evaluation import evaluate_perf

report = evaluate_perf(
    perf,
    trades,
    snapshot={"capital": 30000, "data_from": start, "data_to": end},
    thresholds=thresholds,

```

适用于训练段、检验段等已经计算好绩效的场景。没有原始权益时间轴时，回撤持续期等数据不完整，不应补造。

### 14.3 对当日成交评估

```python
from src.backtest.evaluation import evaluate_day

report = evaluate_day(trades, thresholds=thresholds)
```

只用于当日信号质量观察，不适用长期资金门槛。

### 14.4 合并外部压力结果

```python
from src.backtest.evaluation import apply_stress

report = apply_stress(report, slippage=slippage, thresholds=thresholds)
report = apply_stress(report, perturbation=perturbation, thresholds=thresholds)
```

`apply_stress()` 会原地修改并返回同一个报告对象。重复合并不保留旧压力检查。

### 14.5 展示和序列化

```python
from src.backtest.evaluation import format_evaluation_lines, verdict_tag

lines = format_evaluation_lines(report)
short_text = verdict_tag(report)
payload = report.to_dict()
```

- `format_evaluation_lines()` 同时支持报告对象和 `to_dict()` 字典。
- `verdict_text()` 只返回短结论。
- `verdict_tag()` 会附加红线或观察项数量。

### 14.6 新增一个评估指标的建议步骤

1. 在 `EvaluationThresholds` 增加门槛、默认值和配置读取。
2. 在 `_evaluate_core()` 计算原始值，并写入 `report.metrics`。
3. 编写独立 `_check_xxx()`，明确 pass/watch/fail/skip 的边界。
4. 决定该指标是否适用于 `profile="day"`，不要直接套长期门槛。
5. 在配置页和 YAML 中增加入口；高级指标至少要有默认值。
6. 补充 `tests/test_evaluation.py`，覆盖等于门槛、缺失数据、无穷值和结论变化。
7. 如涉及压力测试，补充 `tests/test_stress.py`，使用注入 runner，避免测试依赖真实行情。
8. 最后接入界面、JSON 和导出，确认旧结果没有该字段时仍能显示“未评估”。

### 14.7 只读审计旧结果与人工复核项

`src/backtest/audit.py` 提供 `audit_results(backtest, optimize, config)` 和 `format_audit_text(report)`。`tools/audit_evaluation.py` 是薄命令行入口，默认读取：

- `data/backtest_last.json`；
- `data/optimize_last.json`；
- `config/config.yaml`。

```powershell
python tools\audit_evaluation.py
python tools\audit_evaluation.py --root "D:\Auto-Trading" --json
python tools\audit_evaluation.py --strict
```

脚本直接通过 `json` 和 `yaml.safe_load` 读取字典，不调用会创建运行目录的 `load_config()`，不下载行情，也不改写输入文件。`--json` 输出结构化 `findings/metrics`，便于接入其他检查；文本模式适合人工复核。

审计严重级别：

| 级别 | 含义 |
|---|---|
| `critical` | 明确红线、验收冲突等必须优先处理的问题 |
| `warning` | 评估或压力证据缺失、样本与口径异常、需要人工复核的启发式提示 |
| `info` | 普通事实、合理 skip 和辅助说明 |

主要检查：

1. 旧结果缺少 `evaluation`、报告级 skipped，以及逐项 fail/watch/skip 展开。
2. `accepted=true` 却 `evaluation_ok=false` 或结论为 reject。
3. holdout 零笔、少于 30 笔、PF 低于当前配置门槛。
4. 达到压力样本条件但缺少有效压力证据；执行错误与有效执行的 `cliff=true` 分开处理。
5. top1 盈利占总正盈利比例：成交至少 30 笔且超过 50% 时提示复核盈利集中度。
6. 剔除最大 5 笔盈利后的净盈亏：至少 5 笔盈利且剔除后不大于 0 时提示复核盈利依赖。
7. ADX 非空覆盖率：ADX=0 是有效值；成交至少 30 笔且覆盖率低于 80% 时提示补齐或重跑。
8. 当前配置与结果的策略、品种不一致，以及 `data_from/data_to` 缺失。
9. 有盈利、无亏损且 PF=99 时提示这是占位值，不能当作真实可实现的高 PF。

集中度、剔除头部盈利和 ADX 覆盖率都是**人工复核提示，不是统计显著性判断**。优化顶层压力块为空但评估 checks 已有有效压力结果时，不重复误报；`cliff=true` 也不等于脚本执行失败。

退出码：正常完成返回 0；`--strict` 下发现 critical 返回 1；文件缺失、解析失败、根节点不是字典或参数错误返回 2，并写入 stderr。

## 十五、推荐阅读顺序与常见误判

### 15.1 推荐验收顺序

```text
先确认策略/品种/周期/区间和成交成本一致
→ 看样本是否足够
→ 看 PF、R 期望和回撤
→ 看盈利覆盖、Calmar、连亏和 ADX 分组
→ 看滑点和参数扰动
→ 看保留检验段、滚动前进、多品种
→ 运行只读审计，复核证据缺失、盈利集中和 ADX 覆盖率
→ 用多日复盘和模拟成交验证执行
```

### 15.2 常见误判

| 现象 | 正确理解 |
|---|---|
| 净盈亏为正 | 只能说明该区间最终盈利，不能抵消 PF、样本和回撤问题 |
| PF 很高 | 先检查是否只有少数成交、是否没有亏损笔、是否存在成本低估 |
| 胜率很高 | 仍需结合平均亏损、盈亏比和 R 期望 |
| 当日评估通过 | 当日模式跳过长期样本和资金门槛，不能交付 |
| 某项显示 skip | 表示没算或无法算，不表示通过 |
| 压力测试没出现 | 检查评估开关、压力开关和成交是否达到 30 笔 |
| 优化 accepted=true | 还要确认是否使用新版结果、评估是否启用、是否存在旧版遗留文件 |
| 交叉测试淘汰 | 是研究提示，不会自动改配置；组合也未自动完成压力测试 |
| 回测通过 | 只代表进入后续模拟和样本外验证，不等于实盘收益保证 |

## 十六、当前实现边界

1. 样本笔数只作提示，不判红线，也不提供置信区间或统计显著性检验；笔数少时综合结论最多到“观察”。
2. 参数扰动最多检查两个参数、四个点，不代表完整参数曲面鲁棒性。
3. 滑点压力只按配置增加固定跳数，不模拟排队、部分成交和流动性枯竭。
4. 回撤持续期只记录，不设门槛；夏普比率未纳入本模块的结论判定。
5. ADX 分组只按开仓时快照划分，不描述持仓期间行情状态变化。
6. 当日重放不反映真实手续费和合约乘数，不能当作资金绩效；ADX 已透传，但只反映开仓那根K线的快照。
7. 实盘与回测对照的账本暂未按品种过滤，必须先核对可比性。
8. 优化主评估与压力已统一为冠军参数全区间口径，但全区间包含训练数据，不能代替保留检验段、滚动前进或新的样本外验证。
9. 审计中的集中度和覆盖率提示是启发式复核线索，不提供置信区间，也不自动得出策略可交付或应停用的结论。
10. 旧版 JSON 可能没有 `evaluation/equity_times/adx_at_entry`，应重新回测，不能根据缺失字段推断通过。
