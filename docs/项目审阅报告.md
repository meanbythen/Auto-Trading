### P0-1 CTP 通道 `dry_run` 默认 False，缺键即可能实盘下单
- 位置：`src/trader/ctp_trader.py:63`、`:100`、`:259`
- 事实：三处均为 `self.cfg.get("dry_run", False)`；而 GUI/模拟/Runner 全部用默认 `True`，配置加载也未强制注入该键。
- 影响：配置丢失或被裁剪后，`_arm_ctp` 因默认 True 不主动连接，但一旦出信号，`place_order` 会自行 `connect()` 并按实盘发单。
- 修复：统一改为默认 `True`，并在 `load_config` 中 `setdefault("dry_run", True)`，作为最后一道保险。
- 复核：已确认代码原文。

### P0-2 无进程级单实例锁，`run_once` 可与常驻并发下单
- 位置：`app_entry.py:26-48`、`src/ui/bot_worker.py:84-104`、`src/scheduler/runner.py:1188-1195`
- 事实：`run_once` 只判断 `self.running`，单次扫描期间从不置 `_alive`；连点两次或“试跑一轮”与“启动常驻”同时点，会各起一套 `TradingBot` + `GuiTrader`。整个程序也没有文件锁/命名互斥。
- 影响：两套 pyautogui 同时操作同一个同花顺窗口，重复开仓、重复平仓、焦点抢占。
- 修复：进程级文件锁（或 Windows 命名 Mutex）；`run_once` 复用同一 busy 标志并在 `finally` 释放；所有会点同花顺的入口统一读该状态。
- 复核：已确认。

### P0-3 崩溃熔断会在交易日切换时被自动解除，运行期也不复查意图文件
- 位置：`src/scheduler/runner.py:634`、`:258`、`src/utils/state_store.py:72-73`
- 事实：`_rollover_trading_day` 无条件 `risk.clear_halt()`；`load_state` 在交易日变化时也把 `halted` 清 False。`order_intent*.json` 只在启动时 `_check_pending_intent` 检查一次。
- 影响：存在“已点击但未记账”的未核对委托时，只要跨过 21:00 就自动恢复交易，违反“崩溃熔断必须人工对账后解除”的既定规则。
- 修复：熔断原因分类持久化（日亏 / 崩溃 / 对账不符）；意图文件未清时任何自动路径不得解除；每个新交易日先复查意图文件。
- 复核：已确认。

### P0-4 账本拒记时仍会清空内部持仓，产生“幽灵仓/反向仓”
- 位置：`src/scheduler/order_executor.py:360-381`、`:931-955`、`src/account/signal_book.py:421-424`
- 事实：`_apply_fill_accounting` 先写账本（`balance` 可能为 `None`），随后**无判断**直接 `strategy.on_filled(...)`。时钟清仓的 `StrategyDecision(CLOSE, ...)` 不带 `entry_price`，当 `kline.fetch` 返回 `None`/空表时不会进入 `except`，`fill_price` 保持 0；账本因 `px<=0` 拒记，但策略仓位已被清零。
- 影响：真实已平仓、账本仍显示持仓，重启后 `_reconcile_books` 以账本为真相恢复出已不存在的仓，后续止损/清仓会对空仓发平仓单（GUI 可能点成反向开仓）。
- 修复：平仓取不到价时必须回退持仓开仓价/最新价；`balance is None` 时不得改策略/风控仓位，并置 `_ledger_failed` 暂停开仓。
- 复核：已确认。

### P0-5 手工开仓/平仓先改内存后写账本，且不做价格校验
- 位置：`src/scheduler/order_executor.py:151-221`、`:256-284`
- 事实：`manual_open` 先 `strategy.on_filled`、`risk.on_order_filled`，再 `_record_signal_account`；`manual_close` 同样先清仓位再记账，价格无效时账本拒记。UI 线程直接调用，与后台扫描无同一把交易锁。
- 影响：与 P0-4 同类的账实分叉；手工单与扫描并发时可能互相覆盖仓位。
- 修复：校验价格 > 0；先记账成功再改内存；手工操作与扫描共用交易锁。

### P0-6 账本读取失败时风控 fail-open，回撤与日亏熔断同时失效
- 位置：`src/risk/dynamic.py:230-252`、`:25-33`、`:226-227`
- 事实：`live_equity_and_peak()` 裸 `except Exception: return 0.0, 0.0`；`drawdown_frac()` 在 `peak<=1e-12` 时返回 `None`，`adjust_open()` 对 `None` 直接放行原手数。
- 影响：账本损坏/磁盘满/权限错误时，回撤减半、暂停开仓、日亏熔断同时失效，且无 error 日志。
- 修复：读取失败显式返回错误并 fail-closed（按“已触发暂停”处理）+ `logger.error`。
- 复核：已确认。

### P0-7 委托意图落盘失败仍继续下单
- 位置：`src/scheduler/order_executor.py:49-55`
- 事实：`_write_order_intent()` 失败仅 `logger.warning("...不影响下单...")`，随后照常点击。
- 影响：磁盘满/杀软锁文件时，点击后崩溃将无任何痕迹，同一根 K 线可能重复开仓。
- 修复：意图写失败直接拒绝本笔并熔断；意图文件按笔独立命名，禁止覆盖。
- 复核：已确认（日志文案即代码原文语义）。

### P0-8 只扫描单一品种，未在扫描清单内的持仓无止损/无收盘清仓
- 位置：`src/scheduler/runner.py:352-360`、`:396-404`、`src/scheduler/flatten_manager.py:60`、`:130`
- 事实：`_pick_scan_symbols` 只返回当前 `trade.symbol`；启动时对“在关注列表但不在扫描清单”的持仓仅打一条 warning。若品种被移出关注列表，连 warning 都没有。
- 影响：无人值守时旧仓裸奔，可能带夜、进交割月。
- 修复：扫描清单 = 当前品种 ∪ 程序账所有非空持仓；清仓待办同理；无法处理时升级为告警并阻断新开仓。
- 复核：已确认。

1. **GUI 点击后异常被当作“未发单”，会重复下单**
   `src/trader/gui_trader.py:957-991`、`src/scheduler/order_executor.py:898-905`。点击买/卖成功后，`_dismiss_confirm` 或恢复窗口若抛异常，`place_order` 返回 `ok=False`，上层 `_release_signal_mark` 释放标记，下一轮再点一次。点击之后任何异常必须按“已发出”处理并保留意图文件。

2. **运行期遗留的 `order_intent` 不触发熔断，且会被下一笔单覆盖**
   `order_executor.py:73-76`、`:108-110`、`:92-96`。运行中记账异常只被 `scan_once` 记日志（`runner.py:1118-1122`），内存不熔断，下一笔 GUI 单覆盖同一文件，成功后再删除，未核对委托永久丢失。

3. **CTP 部分成交存在重复记账风险**
   `order_executor.py:1044`（回调 key=`ref|action|累计volume`）与 `:1123`（补记 key=`ref|side|filled`，side 字符串不同）；`:1102` 用累计量算 `leftover` 却用累计量做键。回调与补记两条路径都跑时会重复入账，导致内部仓位大于柜台。建议统一为 `ref|成交明细id|本次增量`。

4. **CTP 未知委托（带合约代码）被认作本程序委托并记账**
   `src/trader/ctp_gateway.py:610-623`、`:670-686`。只把“无 symbol 的未知回报”当外部单；共享账号/手工单通常带合约代码，其成交会写入本程序账本。未知 `order_ref` 应一律视为外部单。

5. **对账异常被吞，`_books_match` 保持上一次 True（fail-open）**
   `src/scheduler/login_flow.py:113-117`、`src/trader/ctp_trader.py:109-128`。刷新/比对抛异常时不会置 False，仍允许开新仓。任何对账异常都应置“未知/不匹配”。

6. **清仓时钟不识别交易日：周五后定时器失效；周末/节假日可能对已收盘市场平仓**
   `src/scheduler/flatten_manager.py:132-153`、`:55`、`src/utils/session_clock.py`。`_next_flatten_at` 只顺延 1 天，周六/周日策略 `is_flatten_time` 为 False 时返回 `None`，定时清仓兜底失效；反向地，不判星期的策略会在周六 22:55 触发平仓。建议向后搜索到下一个交易日，并在非交易时段禁止下单。

7. **GUI 不校验合约切换是否成功**
   `src/trader/gui_trader.py:846-858`、`:889`。`_ensure_symbol` 只输入不回读，也不核对交易面板当前合约；未标定时完全不切换。信号品种可能被点到另一个品种上。

8. **CTP 平仓限价用“已收线收盘价”**
   `order_executor.py:1006-1016`。止损/收盘清仓在快速行情中挂不上，`submit` 超时自动撤单，下一轮才重试，止损被延迟。建议平仓用对手价/最新价加保护性滑点。

9. **`strategy.on_filled` 无异常保护**
   `order_executor.py:375-381`。异常会打断“账本已写、状态未写”的中间态；CTP 路径还会因 `order.accounted` 未置位而再次记账。应单独 try 并在失败时置 `_ledger_failed`。

10. **CTP 回调线程内执行完整记账（写账本 + 读写 config + 读 Excel）**
    `src/trader/ctp_gateway.py:1000-1014`、`src/account/signal_book.py:563`。报单/撤单/查询回调被阻塞，`submit` 容易超时撤单；配置写入与 UI 保存互相覆盖。建议回调只投事件到队列，记账放独立线程。

11. **上线阶段 `_stage` 会连平仓/强制清仓一起拦**
    `src/kernel/risk_chain.py:84-87`、`src/scheduler/login_flow.py:152-167`。阶段未批准时，持仓的止损、反手、定时清仓全部被拦且不连接柜台。`_stage` 应只拦开仓，平仓与 `force` 清仓必须放行。

12. **手数计算缺止损价时回退固定手数**
    `src/risk/sizing.py:266-268`、`runner.py:520-528`。`risk_pct` 模式下 `entry/stop` 任一缺失就退回 `fixed_volume`，可能开出无止损仓位。开仓必须有有效止损，否则拒单。

13. **CTP 启动连接失败后不再重试**
    `runner.py:1190-1193`、`:1088-1093`。先置 `logged_in=True` 再 `_arm_ctp()`，失败后后续扫描不会再次登录/连接，启动权益同步也不会执行。

14. **对账线程 `push_gateway_account` 无锁读改写，且每轮扫描都写账本**
    `src/account/ctp_sync.py:137-169`、`src/trader/ctp_trader.py:117`。与成交记账线程交错时，可能用旧账本覆盖刚追加的成交行。

## 四、P1：回测 / 优化 / 评估可信度（14 条全部已修）

> 2026-11-14 复核：4-1~4-14 全部已修。
> - 4-1 收盘清仓当根收盘成交并让滑点（`engine.py` `flatten_close` 分支）；4-2 止损用上一根快照 `stop_before`；4-3/4-4 carry 用后清空且所有策略段首通用。
> - 4-5 holdout 从切分点独立重跑；4-6 样本外 0 笔判不通过；4-7 walk 按同参数同区间判定。
> - 4-8/4-9 PF、Calmar 用 SKIP 不参与 PASS/FAIL；4-10 压力测试参数节有映射表；4-11 开仓当根浮盈记 0；4-14 盈利覆盖按各 fold 天数汇总。
> - 4-12（44.8.6 已文档化）：`review/replay.py` 的价格口径本来就是近似（信号价/当根收盘、止损按止损价），
>   不含滑点、手续费、下一根开盘；现已在 `docs/日内实体操作说明书.md` 盘后复盘一节明确写出。
> - 4-13（44.9.0 已修）：`backtest/liquidity.py` 增加一字板不成交与按成交量限开仓手数，
>   配置在 `backtest.liquidity`，默认关闭；结果快照会记录口径。

> 这一组不直接造成资金损失，但会系统性误导“策略能不能上实盘”的决策，优先级等同于 P0。

1. **收盘清仓按“下一根开盘价”成交，15m 及以上周期会跨夜**
   `src/backtest/engine.py:1379`、`:269-282`、`src/utils/session_clock.py:394-401`。只有 `delivery_flatten` 用当根收盘；收盘清仓走 `next_open`。15m 最后一根标签 15:00 落在 `[14:55,15:05]` 窗口，下一根是 21:00 夜盘首根，导致“日内清仓”变成隔夜持仓。5m 因存在 14:55 那根，问题被掩盖。
   **建议**：收盘清仓与交割强平同口径，用当根收盘价 + 方向滑点。

2. **止损位在当根收盘后才更新，却按当根 low/high 判定触发（未来函数）**
   `src/backtest/engine.py:316-329`、`:1372-1388`、`src/strategy/trend_base.py:280-287`、`src/strategy/supertrend.py:232`、`src/strategy/macd_swing.py:384`。`_manage` 先 `trail_stop()`（直接写 `pos.trail_stop`），再用当根 low/high 判 `stop_triggered`；引擎随后又用同一新止损回判当根。SuperTrend 翻向时新 ST 常在当根最高价之上，`low <= stop` 恒真，直接按当根开盘价平仓。
