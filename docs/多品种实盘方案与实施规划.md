# 多品种实盘方案与实施规划

对应版本：49.40.0（2026-11-22）

本文回答一件事：**同一个 CTP 账户同时跑多个品种，怎么下得去、管得住、算得清、回得来。**

阅读顺序建议：先看第 1 节的结论和第 2 节的现状核对，再看第 4～7 节的规则设计，最后看第 10 节的实施阶段和第 12 节需要拍板的选项。本文只做方案与规划，**本轮不改任何交易链路、下单逻辑或风控阈值**。

---

## 1. 结论摘要

1. **现在还不能算多品种实盘。** 常驻扫描清单是「当前选中品种 + 已有持仓的品种」，第二个品种只有在已经持仓后才会被扫描；它永远等不到第一笔开仓信号。GUI 通道已经明确只做单品种，多品种只能在 CTP 通道做。
2. **共享资金已经有基础，但预占刚补齐。** 手数计算会扣掉各品种已占用的保证金，并和柜台可用资金取小；49.40.0 起组合闸门在开仓通过时先记在途风险预留，同一轮里第一笔还没成交、第二笔也会被这笔风险挡住。预留默认 60 秒过期，成交即释放。
3. **交易时段、清仓钟点目前只认「扫描清单第一个品种」。** 燃油有夜盘、生猪没有夜盘。选中燃油时，生猪的持仓在 21:00 之后仍会被扫描，且时钟清仓用的是燃油的 23:55，不是生猪的 14:55。这是多品种实盘前必须修的第一道口子。
4. **今昨仓、平今平昨、部分成交入账已经做了。** 但「部分成交后剩余手数怎么办」「目标仓位与实际仓位的差怎么补」还没有成文规则，当前偏保守：先按已成交部分记账，剩余交给后续扫描/对账。
5. **组合回测是最小闭环，不是共享资金闭环。** 各腿各自用完整资金跑、再按权重缩放相加；保证金是事后汇总和 +50% 压力检查，没有腿间竞争、拒开、优先级排队。相关性只做提示和聚类，没有回灌到权重或实盘闸门。
6. **建议路线：先修调度与状态，再做资金预占与再平衡，最后补组合回测的保证金竞争。** 依次经过「仿真双品种 → 仿真跑满一周 → 真实账户 1 手小仓 → 双品种 1 手」四道门，任何一道不达标就回滚到单品种。

## 3. 单账户多品种状态模型

### 3.1 三层对象

```
账户（一个 CTP 资金账号）
 ├─ 品种槽（symbol slot）：fu2701 / lh2701 ...
 │   ├─ 净持仓：long_vol / short_vol（当前模型互斥，不做双向锁仓）
 │   ├─ 今仓 / 昨仓：long_today / long_yesterday / short_today / short_yesterday
 │   ├─ 目标仓位：target_vol（策略输出，经手数与资金闸门后）
 │   ├─ 在途委托：working orders（含部分成交剩余）
 │   └─ 状态机：flat → opening → open → reducing → pending_close → frozen
 └─ 资金池：动态权益 / 可用资金 / 已用保证金 / 在途预占 / 现金缓冲
```

### 3.2 关键口径

1. **一合约一净仓。** 同一合约不做多空双向同时持有。策略腿只用于回测，实盘同一合约只允许一个方向、一个止损归属。
2. **目标仓位与净持仓分离。** 策略只输出「想做几手」，执行层维护「已成交几手 + 在途几手」。两者之差才是本轮要补的量。
3. **在途预占独立记账。** 报单发出即从资金池扣除预占保证金；全部成交、撤单、拒单后释放，再按实际成交重算占用。预占只用于开仓，平仓不占用。
4. **冻结态。** 出现「柜台有仓、程序无仓」的未认领持仓时，该品种冻结自动交易，只允许人工处理；冻结不阻断其它品种的平仓。
5. **账户级与品种级分开。** 日亏熔断、可用资金、总保证金是账户级；净仓、今昨仓、止损、交易时段是品种级。账户级失败默认全局停开仓，品种级失败只停该品种。

### 3.3 状态迁移

| 当前 | 事件 | 下一状态 | 说明 |
| --- | --- | --- | --- |
| flat | 开仓信号通过闸门，报单发出 | opening | 计入在途预占 |
| opening | 全部成交 | open | 释放预占，按成交价重算占用 |
| opening | 部分成交后撤单/超时 | open（按已成交）或 flat | 剩余手数按第 6 节规则处理 |
| opening | 全部拒单/撤单 | flat | 释放预占，记录原因 |
| open | 反向信号/止损/减仓 | reducing | 平仓单不占新保证金 |
| reducing | 全部成交 | flat | 释放该品种占用 |
| 任意 | 対账不一致/账本失败 | frozen | 只平不开，必须人工解冻 |

## 4. 调度模型与下单优先级

### 4.1 扫描清单

目标规则：

1. 扫描清单 = `strategy.symbols` 中「启用且未进交割月」的全部合约，不再只取选中品种。
2. 已有持仓但已移出关注列表的合约，仍然追加到清单末尾，只允许平仓、止损、清仓。
3. GUI 通道保持现状：只对选中品种开仓；CTP 通道才允许多品种开仓。
4. 每个品种独立缓存行情、独立判断时段；账户级锁只保护「报单 + 记账」临界区。

### 4.2 单轮顺序

```
刷新交易日 → 刷新各品种时段 → 对账（账户级一次）
  → 品种 A：取K线 → 策略 → 风控链 → 报单/等待回报 → 记账
  → 品种 B：同上
  → 汇总在途、预占、健康状态 → 落盘
```

- 单轮内仍按固定顺序串行，避免并发改同一份资金与持仓。
- `order_wait_sec` 是每笔等待上限；两品种各 8 秒会超过 5 秒扫描间隔。多品种阶段建议把扫描间隔与等待上限一起重算（见第 12 节决策项 D3）。
- 任何一个品种抛异常只跳过该品种，不中断整轮。

### 4.3 跨品种同时触发的优先级

同一轮里多个品种都要动作时，按下面顺序排，不按代码字典序：

| 优先级 | 动作类型 | 理由 |
| --- | --- | --- |
| P0 | 账户级熔断/对账不一致 | 先停止所有开仓，再谈其它 |
| P1 | 收盘清仓、强制平仓 | 不留隔夜裸仓 |
| P2 | 止损、通用止损 | 控制单笔最大亏损 |
| P3 | 反手（先平后开） | 平仓部分按 P2，开仓部分按 P4 |
| P4 | 减仓 | 降低敞口 |
| P5 | 新开仓 | 最后分配剩余资金 |

同一优先级内再按以下键排序：

1. **风险预算占用率**：预计亏损 ÷ 单笔风险预算，高的先做。
2. **保证金效率**：单位保证金能带来的预期收益（交叉测试已有该口径），高的先做。
3. **相关性惩罚**：与已持仓高相关（日收益相关 ≥0.7）的排后，避免同一风险来源叠满。
4. **滑点余量**：预计滑点 ÷ 允许滑点，余量小的先做，避免开盘急拉后失效。
5. **固定种子随机**：以上仍相同的，用「交易日 + 品种」做稳定哈希，保证同一天可复现，不用真随机。

### 4.4 同品种多腿信号冲突

- 实盘一个合约只允许一条有效腿。若配置里同一合约出现两条腿，启动时直接报错并要求删掉一条，而不是静默取第一条。
- 同一合约同一根 K 线只允许一次开仓决策；反向信号必须先平后开，且平仓成交后才允许开新仓。
- 策略腿（不同引擎/周期）在实盘落地前，执行层需要支持「按腿取行情、按腿算信号、合并到同一净仓」。这是 G4，放在阶段 2，不与调度改造混在一起。

## 5. 资金与保证金分配、再平衡

### 5.1 资金池公式

```
动态权益 E        = 柜台动态权益（优先）/ 信号账权益（兜底）
保证金预算 B      = E × margin_usage_pct（当前 50%）
已用保证金 U      = Σ 各品种 |净持仓| × 该品种每手保证金
在途预占 R        = Σ 已发出未终结开仓单 × 该品种每手保证金
剩余预算          = B − U − R
单笔可开手数      = min(风险预算手数, 剩余预算 ÷ 每手保证金, 单笔上限, 柜台可用资金 ÷ 每手保证金)
```

- 每手保证金优先用 `margin_rate_pct / 100 × 开仓价 × 乘数`，没有比例才退回表内固定金额。
- 柜台可用资金是账户级硬约束，永远与本地估算取小，避免两边各扣一次。
- 预占按下单时的价格计算；成交后按实际成交价重算，差额退回资金池。

### 5.2 分配顺序

1. **先保平仓与止损**，不占新预算。
2. **再保已有持仓**：权益下降导致 `U > B` 时，不强制砍仓，但停止所有新开仓，并告警「保证金占用超上限」。
3. **新开仓按第 4.3 节优先级**依次分配剩余预算，分完为止；后面的品种记录「预算不足，跳过」事件，不排队等下一轮自动补。
4. **现金缓冲**：建议保留至少 1 手最贵品种的保证金作为缓冲，避免盘中保证金上调直接触发风险度告警。

### 5.3 再平衡规则

再平衡只处理「目标仓位」与「实际净仓」的差，不主动预测行情。

| 场景 | 动作 | 约束 |
| --- | --- | --- |
| 目标 > 实际，且资金够 | 补开差额 | 仍需过完整风控链；同一根 K 线最多补一次 |
| 目标 < 实际 | 减仓差额 | 优先平今/平昨按品种规则；不因减仓触发新开仓 |
| 部分成交后剩余挂单超时 | 撤单，按实际成交重算目标 | 不自动追单，等下一根已收盘 K 线 |
| 权益变化导致预算变化 | 只影响新开仓，不强制减已有仓 | 除非触发账户级熔断或风险度红线 |
| 相关性突变（≥0.7） | 不自动减仓，只提示并降低新开仓排序 | 避免因统计噪声来回砍仓 |

再平衡频率：与扫描同频检查，但**同一品种两次补单至少间隔一个已收盘 K 线周期**，避免盘中反复追。

## 6. 部分成交与滑点差异

### 6.1 部分成交

现有实现：成交回报按「累计成交量 − 已入账量」增量记账，拆平今/平昨时按每笔报单分别补记；同一 `fill_key` 只入一次。

需要补的成文规则：

1. **开仓部分成交**：已成交部分立即入账并计入保证金；剩余部分保持挂单，账户进入「有在途」状态，期间其它品种的新开仓是否放行由决策项 D2 定。默认建议：**有在途开仓时，账户级暂停其它品种新开仓**，但平仓、止损不受影响。
2. **开仓剩余未成交**：到达 `order_wait_sec` 后仍未全部成交，撤单；撤单后按已成交手数作为本次开仓结果，不自动追剩余。下一根已收盘 K 线若信号仍在，按再平衡规则补差额。
3. **平仓部分成交**：已成交部分减仓；剩余继续挂，直到全部平掉或收盘清仓兜底。平仓不允许因为部分成交而提前把程序仓位清零。
4. **部分成交 + 反向信号**：先等当前委托终结（成交/撤单/拒单），再处理反向，禁止在旧单还在时发反向单，避免自成交或超仓。
5. **记账顺序**：发件箱 → 信号账 → 策略/风控持仓 → 事件与滑点。任何一步失败，保留程序仓位不动并停开新仓，等对账修复。

### 6.2 滑点按品种校准

- 回测的 `slippage_ticks` 是全局值，不能直接套到所有品种。多品种阶段应支持「品种级滑点跳数」，至少允许燃油、生猪分别配置。
- 实盘已有滑点记录（`src/account/slippage_log.py`），按「理论价 − 实际成交价」折成跳数。建议每月用实盘滑点中位数回填品种级参数，但**只改回测口径，不改实盘下单价格规则**。
- 滑点闸门（`max_entry_slip_atr`、`max_entry_slip_points`）当前是账户级；多品种时至少按品种的每跳价值换算，避免生猪 50 点等于 10 跳、燃油 50 点等于 50 跳却用同一阈值。
- 评估口径：单品种回测必须同时给出「1 跳 / 2 跳 / 实盘中位数」三档，避免只在最乐观滑点下过关。

## 7. 你未提到、但必须提前处理的风险

下面这些不在你列的五个问题里，但任何一条处理不好，多品种实盘都会以「账实不一致」或「该平的没平」收场。

### 7.1 交易时段与夜盘差异（最高优先）

- 燃油有夜盘 21:00–23:00，生猪没有夜盘。当前时段只按扫描清单第一个品种取，选中燃油时生猪会在夜间被扫描。
- 夜盘属于下一交易日：周五夜盘、周一凌晨、节假日前的夜盘，交易日归属与结算价都不是自然日。
- 收盘清仓钟点也按品种不同（燃油 14:55/22:55，生猪 14:55）。当前时钟清仓用选中品种的钟点，生猪的 14:55 兜底会失效。
- 建议：时段、清仓钟点、交易日归属全部下沉到品种槽，账户级只做「当前是否有任一品种可交易」的判断。

### 7.2 换月与交割月

- 已有 `apply_delivery_gate`：进入交割月禁开并平仓。多品种时换月不同步，资金计划会出现「某品种突然不能用」。
- 换月窗口内新旧合约价格不同，保证金和每跳价值都变；再平衡规则必须以新合约的合约参数重算，不能沿用旧合约。
- 建议：每个品种维护「主力合约 + 可交易合约」映射，换月前 N 个交易日只减不加，换月当天不新开。

### 7.3 涨跌停、强平与风险度

- 涨跌停时平仓可能成交不了，止损会失效；多品种同时反向时，账户风险度上升，期货公司可能强平。
- 建议：账户级增加「风险度 = 已用保证金 ÷ 动态权益」监控；超过券商预警线（常见 80%）只平不开，超过强平线前人工介入。不要等柜台强平。
- 涨跌停封板时，记录「平仓未成交」并保持待办，不要因为一次失败就把程序仓位清掉。

### 7.4 今昨仓与平今手续费

- 已有平今/平昨拆分，但只对上期所、能源中心、大商所的部分品种生效；郑商所、中金所用普通平仓。
- 生猪平今手续费 48 元/手，是开仓 24 元的两倍。日内频繁反手会显著吃掉 1% 风险预算。
- 建议：反手与再平衡前先算「本次平今费用 + 预计滑点」，超过本笔风险预算的一定比例就放弃本次动作，等下一根 K 线。

### 7.5 盘中保证金上调

- 交易所节假日前、极端行情时会临时上调保证金。本地 `margin_rate_pct` 是静态配置，盘中不会自动变。
- 后果：下午还能开的仓，晚上就超预算；已持仓可能直接顶到上限。
- 建议：每日开盘前用柜台合约参数刷新一次；无法刷新时按「配置值 × 1.2」做压力预算；组合回测已有 +50% 压力检查，实盘至少要接一个 20% 的日常缓冲。

### 7.6 断线重连与状态重建

- CTP 断线后本地委托表可能是空的，重连后必须先查委托、再查持仓、再做三方对账，顺序不能反。
- 多品种时对账要按品种逐个比对，不能只比总手数；「A 多 1 手、B 空 1 手」总手数为 0，但两个品种都错。
- 重启后扫描清单、在途预占、目标仓位都要能从磁盘恢复；恢复未完成前保持暂停报单。

### 7.7 重复报单与幂等

- 同一根 K 线只发一次开仓单，已有 `_sent_bar` 与 `order_dedup` 闸门。
- 多品种时要去重键带品种：`symbol + bar_id + action`，不能只用 bar_id。
- 柜台回报可能重复、可能晚于报单函数返回；已有 `fill_key` 幂等，但预占释放也要幂等，否则一次成交释放两次会把预算放大。

### 7.8 组合止损与单腿止损

- 现在只有单腿止损、通用止损、收盘清仓。没有「组合回撤达到 X% 全部减半」这类规则。
- 多品种同向时，单腿各自止损可能在同一根 K 线连续触发，实际组合亏损远大于单笔 1%。
- 建议分两步：先做「账户级日亏熔断」（已有），再做「组合回撤阈值只减不加」，不要一上来就做组合强平。

### 7.9 交易所/账户限仓与程序化报单限制

- 交易所对单合约、单品种有投机持仓限额；期货公司对程序化报单有笔数、频率要求。
- 多品种会放大报单笔数与撤单笔数，华泰的 8 笔预警要按账户统计，不是按品种。
- 建议：把「每日报单/撤单笔数」做成账户级硬闸门，接近阈值时只允许平仓。

### 7.10 结算价与盯市

- 期货按结算价盯市，不是按收盘价。回测用收盘价，实盘权益用柜台动态权益，两者在结算时点会有差异。
- 多品种组合权益如果按各自收盘价合成，遇到不同夜盘收盘时间会对不齐。
- 建议：组合权益统一用「交易日 + 结算后权益」做日频对齐；盘中组合回撤另算，并明确标注是「盘中估算」。

### 7.11 模拟盘与实盘差异

- 仿真柜台成交快、滑点小、部分成交少；实盘挂单可能长时间不成交。
- 仿真环境的合约参数、保证金比例可能与真实账户不同。
- 建议：上线门槛必须包含「仿真连续 5 个交易日、至少 20 笔真实回报」和「真实账户 1 手小仓至少 10 个交易日」，不能只用仿真结果判定通过。

### 7.12 其它容易漏的

- **数据时间戳与收线**：多品种各自周期不同，不能共用一份「最后一根 K 线」判断新鲜度。
- **合约乘数与每跳错误**：生猪乘数 16、每跳 5 元；燃油乘数 10、每跳 1 元。参数错一位，手数和止损全错。
- **同账号被挤下线**：交易台与常驻不要同时登录同一账号；多品种挂机时更要固定只跑一个进程。
- **手续费计提**：开仓手续费也应由资金池扣，不能只算平仓盈亏，否则组合权益会系统性偏高。
- **策略腿与实盘不一致**：`strategy.legs` 目前只影响组合回测，实盘仍是全局引擎。若直接按回测结果上实盘，会得到完全不同的信号。

## 8. 组合回测最小闭环：覆盖度评估

### 8.1 已覆盖

| 项目 | 现状 | 可信度 |
| --- | --- | --- |
| 共享资金（权重） | 等权 / 波动率倒数 / 风险预算 / 固定上限 | 可用，但只是资金缩放 |
| 组合权益 | 按交易日对齐，缺失日延续 | 可逐日复算 |
| 组合回撤 | 基于组合权益 | 可用 |
| 品种贡献 | 各腿盈亏按权重还原 | 可用 |
| 相关性矩阵 | 日收益相关，分档 + 聚类 | 只提示 |
| 同时持仓数 | 按交易日统计 | 可用 |
| 保证金峰值 | 按开仓价 × 乘数 × 比例，或表内金额 | 事后汇总 |
| 保证金压力 | 比例上调 50% 重算 | 事后检查 |
| 风险指标 | VaR95/99、CVaR95、最差单日/5日/20日 | 样本 ≥20 日才给 |
| 交叉测试资金口径 | 净盈亏 ÷ 保证金占用排名 | 已上线 |

### 8.2 没有覆盖（必须说清楚）

1. **没有腿间保证金竞争。** 每条腿都用「完整初始资金」跑，最后按权重缩放。A 腿占满保证金时，B 腿在回测里仍然能开，实盘会被拒。
2. **没有共享现金约束。** 回测不会因为 A 腿浮亏导致 B 腿开不起仓。
3. **没有优先级与排队。** 同一天多腿同时触发时，回测各开各的；实盘只有一个报单通道和账户级间隔。
4. **没有部分成交与滑点差异。** 回测按整手成交、全局滑点；实盘可能只成交一部分。
5. **没有盘中保证金上调、涨跌停封板、强平。**
6. **没有账户级日亏熔断在组合层的模拟。** 单腿回测有风控参数，组合层没有把「日亏 1,660 停止开仓」串起来。
7. **相关性没有回灌。** 高相关只提示，不会自动降权或限制同时持仓。
8. **没有换月。** 组合回测按给定合约跑，不模拟主力切换。

> 49.36.0/49.38.0 已用组合层共享资金账、优先级重放和品种级滑点补上第 1～4 条的回测模拟口径；实盘侧仍按阶段 5 的门逐项验收。

### 8.3 补齐方案（P0/P1 已落地）

按投入产出排序：

1. **P0：组合资金账户模拟器。** 在现有单腿结果之上加一层「共享资金账」：逐日按腿的信号顺序尝试开仓，检查现金、保证金预算、账户级日亏，开不起就记「拒开」。输出「理论收益」与「资金约束后收益」两条曲线，差额就是资金竞争成本。*（49.36.0 已落地：`simulate_shared_capital()`）*
2. **P1：优先级重放。** 用第 4.3 节规则对同日触发排序，再跑资金账，验证优先级是否改变结论。*（49.38.0 已落地）*
3. **P1：品种级滑点。** 每腿单独配置滑点跳数，组合结果按品种加权。*（49.38.0 已落地：`backtest.slippage_by_symbol`）*
4. **P2：相关性约束。** 高相关簇内限制合计风险预算，先做「提示 + 上限」，不做自动优化。
5. **P2：换月模拟。** 用主力映射表拼接连续合约，单独标出换月成本。
6. **P3：盘中路径。** 用分钟级权益估算盘中回撤与保证金峰值，日频只做收盘口径。

验收标准：同一组品种、同一组参数，补齐后的「资金约束后收益」不得高于「理论收益」；两者差额要能逐日解释到「哪一天、哪个品种、被什么约束拒开」。

## 9. 回测—仿真—实盘一致性口径

| 口径 | 回测 | 仿真 | 实盘 | 要求 |
| --- | --- | --- | --- | --- |
| 成交时点 | 下一根开盘 | 柜台回报 | 柜台回报 | 回测与实盘都不得用信号当根收盘价成交 |
| 成交价 | 开盘价 + 滑点跳数 | 实际回报 | 实际回报 | 滑点按品种校准 |
| 手数 | 风险 % + 保证金上限 | 同一 `PositionSizer` | 同一 `PositionSizer` | 三处必须同一函数 |
| 保证金 | 开仓价 × 乘数 × 比例 | 本地估算 + 柜台可用 | 本地估算 + 柜台可用 | 比例优先，金额兜底 |
| 日亏熔断 | 单腿参数 | 账户级 | 账户级 | 组合层必须能重放 |
| 平今平昨 | 手续费区分 | 按品种拆分 | 按品种拆分 | 三处同一张合约表 |
| 收盘清仓 | 按周期最后一根 | 时钟 + 策略 | 时钟 + 策略 | 按品种各自的清仓钟点 |
| 交易日 | 自然日切分 | 期货交易日 | 期货交易日 | 夜盘归属下一交易日 |

一致性检查建议做成一个只读脚本：输入一份配置和一个回测结果，输出「手数、保证金、手续费、清仓时点」四项差异；差异不为零就不允许进入下一阶段。

### 12.1 实施状态

- **已完成（49.35.0）**：多品种白名单开关、扫描清单补齐空仓品种、各品种独立交易时段与清仓钟点、按品种的时钟清仓、多品种扫描间隔、真实账户二次放行、同一合约多腿启动报错。
- **已完成（49.36.0）**：阶段 3 策略腿实盘化——`src/strategy/leg_router.py` 按 `strategy.legs` 为每条腿建独立策略实例，共享 `positions`、信号去重、待成交、平仓方向与止损基准；扫描、评估、成交回填、平仓记账、ATR 滑点、下单时段检查按品种分派。阶段 4 组合回测共享资金账——`simulate_shared_capital()` 按逐笔成交重放同一保证金池，按「净盈亏 ÷ 保证金」排队，预算不足记拒开，日亏达到 `risk.max_daily_loss` 后当天后续开仓拒绝；结果写在 `combined["shared_capital"]`，不改原组合权益与绩效。
- **已复核，无需新增代码**：D2 的「有在途就全局停开仓」由 `blocks_new_opens()` 覆盖；D5 的「撤单不追」由超时撤单 + 同 K 线去重覆盖。
- **单品种兼容**：只支持单品种的 CTP 权限把 `live.multi_symbol.enabled` 设为 false 即可，程序不建腿路由、不回放共享资金账，交易链路与 49.35.0 之前的单品种口径一致。
- **界面入口（49.37.0）**：交易配置页新增「多品种策略腿」编辑区，可改启用开关、真实账户放行、扫描间隔，并逐行编辑合约、策略、信号周期和止损周期；保存写回 `live.multi_symbol` 与 `strategy.legs`，白名单按腿自动生成。常驻启动时多品种会保留完整名单，不再裁成当前选中品种一个。
- **已完成（49.38.0）**：阶段 4 剩余两项。共享资金账改为按第 4.3 节完整优先级逐笔重放——风险预算占用率（预计亏损 ÷ 单笔风险预算）→ 资金效率 → 相关性惩罚（与已持仓日收益相关 ≥0.7 排后）→ 滑点余量（预计滑点 ÷ `allowed_slip_ticks`）→「交易日 + 品种」稳定哈希；每接受一笔就按最新已持仓重排。品种级滑点 `backtest.slippage_by_symbol` 支持合约、品种代码、小写三种键，未配置时退回全局 `slippage_ticks`，默认配置下既有回测数值不变。
- **已完成（49.40.0）**：P2 组合风险热度与在途预留——组合检查从总手数改为「持仓到止损的最大亏损 ÷ 权益」，开仓通过时写入内存预留、成交释放、超时过期；持仓读取失败或权益未知时开仓失败关闭。回测共享资金账按同一 `max_heat_pct` 累计拒开并输出热度峰值。P3 精简闸门——回测 `allow_open` 直接调用实盘 `RiskGuardian.allow`，`sizing_mode: fixed` 降级为策略上限。
- **对照脚本（49.41.1）**：`tools/sim_p2_heat_compare.py` 对比不同热度上限，`tools/sim_p3_gate_compare.py` 按 `strategy.legs` 逐腿跑主力连续，对比动态/ATR 开关、固定手数上限，并对健康停开做成交级影子重放。
