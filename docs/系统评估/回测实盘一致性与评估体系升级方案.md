# 回测–实盘一致性与评估体系升级方案

日期：2026-11-19  
对照版本：**49.0.6**  
状态：规划（未改开仓、止损、反向规则）

这份文件回答三件事：

1. 现在这套程序，回测和实盘到底差在哪、稳不稳。  
2. 每个策略该用同一套什么标准来打分、晋级、退役。  
3. 接下来分几步做、每步验收什么、和已有研究计划怎么衔接。

读者按初中生能懂的原则写人话；实施段落给以后改程序的人看文件名。  
不替代、不作废已有的 [策略研究与回测可信度升级实施计划.md](策略研究与回测可信度升级实施计划.md)（下称「研究计划 P0–P6」）。本文是：**系统自评估 + 策略评估闭环 + 一致性专项**，研究计划继续管数据准入和 Tick 复核。

配套打分底表仍用本目录 [系统评估.md](系统评估.md)、[系统评估指标.md](系统评估指标.md)。

## 〇、先说结论（给挂机的人看）

**回测和实盘现在不是同一台摄像机。** 策略公式尽量共用同一份 `evaluate`，但「什么时候算现在、什么价成交、什么情况允许开」两边不一样。所以：

- 回测成绩只能当「规则在历史上大致赚不赚钱」；  
- **不能**直接当过夜或今早那笔该不该开的依据；  
- 今天多因子空单：09:15 信号被滑点闸门拦住、09:30 新K 再开，这在回测里会变成「09:30 那根收盘才开」，时间对得上，开仓价和止损距离对不齐。

**程序稳定性：能挂、能重启捡仓、能止损，但还不是「研究级可复现」的实盘对照。** 账本偶发读锁、对账超时熔断、天勤历史不够 200 根，都不改变开平规则，但会让人对「系统好不好」产生噪音。

**策略评估：回测侧已经有通过 / 观察 / 淘汰。** 缺的是：每个引擎一份书面规则卡、实盘与回测逐笔对照、衰减到什么程度必须停手。不要自动换策略。

下面分六章：对标行业 → 现在有什么 → 自评估打分 → 一致性缺口清单 → 每个策略怎么评 → 分阶段实施。

## 一、优秀系统在这方面通常怎么做

借鉴对象：同一套策略代码跑回测和实盘（vn.py / QuantConnect Lean）、成交模型宁可偏严（Ernest Chan、Lopez de Prado）、样本外冻结与多重检验、影子账户、逐笔 intended vs fill、衰减退役。不照搬他们的终端。

| 成熟做法 | 人话 | 本程序已经有的 | 还缺的 |
|---|---|---|---|
| 同一份策略函数 | 回测和实盘不要各写一套买卖点 | 引擎 `evaluate` 共用 | 调度层实盘有影线止损、滑点闸、过期K、启动补开，回测没有一一镜像 |
| 成交模型偏严 | 回测成交价不要比实盘更便宜 | 「下一根开盘 + N 跳滑点」 | 未按品种用 `slippage_log.csv` 自动校准；OHLC 同根顺序仍有保守处理（P2.1） |
| 只认已收盘开仓 | 防止用还在走的 K 偷看 | 回测 `drop_forming_bar` | 实盘止损看影线（有意更安全），开仓默认收盘；触发开仓例外 |
| 样本外只看一次 | 调参碰不到最后一段 | 优化默认冻最后半年、打乱重抽 | 完整趋势对照矩阵仍等数据门禁（研究计划 P3） |
| 影子盘 / 仿真 | 真钱前先对成交质量 | CTP 仿真通道、上线四步 | 影子盘与实盘同信号并排记账未做 |
| 逐笔对照 | 信号价、委托价、成交价三列 | 复盘 gap、订单时间线、假定成交单独分类 | 没有「这一根回测会成交 vs 实盘拦了/追了」的日表 |
| 衰减监测 + 退役 | 活策略会坏 | 运行台近 20 笔对照最近回测，只告警 | 连续偏离禁开总闸在 TODO，未做；无书面退役线 |
| 系统分 vs 策略分 | 程序宕机和策略亏钱分开管 | 看门狗、熔断、对账 | 没有一张「程序 SLA」周报；评估清单把 CIS 思想项和本程序现状混在一张表里 |
| 多重检验 | 扫很多参数会假装赚钱 | 扰动、滑点加压、交叉测试 | 未做 Deflated Sharpe / 组合相关性引擎 |

原则（写进以后每一期验收）：

1. **先解释差异，再优化收益。** 对不上的笔先归类（过期K、追价、人工、换月），不准靠改参数把曲线画平。  
2. **研究不进实盘配置。** 优化通过 ≠ 改挂机策略。  
3. **人批准上线、人批准退役。** 程序只给红黄绿和证据。  
4. **不做震荡专用引擎**（项目已定）。震荡里现有趋势策略应当少开，评估里「震荡组还在赚钱」继续当红线，不当新需求。

## 二、程序里已经有的评估体系（复用，不另起炉灶）

```
可靠数据 → 保守回测 → 样本外淘汰 → 模拟/实盘执行 → 成交质量回流 → 复盘对照 → 人工批准
     │           │            │              │                │            │
  quality/    engine.py    optimizer     CTP/GUI/sim      slippage_log  review/
  inventory    fill.py     evaluation     时间线           人点确认填跳   gap.py
               P2.1/P2.2    交叉测试                                      health.py
```

| 层 | 现在做什么 | 关键位置 |
|---|---|---|
| 门槛打分 | 盈利因子、R 期望、Calmar、回撤、连亏、ADX 震荡组、滑点加压、参数扰动 → 通过 / 观察 / 淘汰 | `src/backtest/evaluation.py`，配置 `evaluation:` |
| 回测成交 | 默认下一根开盘、跳数滑点、跳空止损、同根顺序不明则保守 | `fill.py`、`engine.py` |
| 1 分钟复核 | 只检查已有仓是否更早碰到止损，不开新仓 | 回测页「1 分钟复核」；研究计划 P2.2 |
| 优化门禁 | 冻最后半年验收一次、打乱成交、不达标不写入 | `optimizer.py` |
| 交叉测试 | 策略×合约×周期，得分看盈利因子和回撤覆盖 | `src/screen/picker.py` |
| 复盘 | 当日重放 vs 事件 vs 账本；缺陷归固定类 | `src/review/` |
| 运行健康 | 近 20 笔实盘 vs `data/backtest_last.json`，只提醒 | `src/ops/health.py` |
| 实验快照 | `experiment_id`、配置哈希、数据版本 | 研究计划 P0 |
| 审计脚本 | 同根开平、滑点为 0 等 | `src/backtest/audit.py` |

**不要再做一套平行的评估库。** 升级 = 把「实盘一致性」和「每策略档案」接到上面这些出口上。

## 四、回测 vs 实盘：已知差异清单（一致性核心）

差异要分类，才能知道是 bug 还是有意保护。

| 编号 | 现象 | 回测 | 实盘 | 归类 | 今天例子 |
|---|---|---|---|---|---|
| G1 | 用哪一根当「现在」 | 只已收盘 | 止损拼正在走的影线；开仓默认识收盘 | 有意：实盘更早止损 | README 已写，回测不能当过夜依据 |
| G2 | 成交价 | 下一根开盘 ± 跳数 | 对手价让 1 跳 | 模型不同 | 09:30 限价 9445，信号收 9450 |
| G3 | 追价 | 滑点跳数已含在成交里，仍成交 | 反向偏移超 ATR 或点数则 **放弃这一根** | 有意保护 | 09:15 信号 9495、现价 9450，空单追 45 点 > 10 点 |
| G4 | 过期 K | 历史没有「现在」 | 超约 90 分钟禁开 | 有意 | 09:01 用昨 15:00 |
| G5 | 启动补开 | 无 | 最近 3 根且不超过 20 分钟 | 有意 | 隔夜启动不补 |
| G6 | 同一根重复处理 | 逐根一次 | 「这一根已经处理过」 | 应对齐 | 09:15 被滑点放弃后等到 09:30 新根 |
| G7 | 收盘清仓 | 跟回测页开关 | 跟交易配置/公共开关；长线引擎可不听 | 已修抄配置 bug | 49.0.1–49.0.3 |
| G8 | 手数 | 回测页权益与限制 | 柜台权益、保证金、凯利 | 环境不同 | 凯利封顶 10%→1 手 |
| G9 | 换月 | 主力表分段 | 实盘具体合约 | 研究计划补 as-of | — |
| G10 | 数据根数 | 可拼本地历史 | 实盘只要最近约 200 根 | 可接受 | lh2701 195/200 |
| G11 | 假定成交 | 无 GUI | GUI 点单 `assumed_fill` | 已分类，勿混 CTP | P0.3 |
| G12 | 健康对照 | — | 近 20 笔 vs **最近一次**回测，品种/周期可能不一致 | 口径弱 | 需改成「同策略同品种同周期」 |

**一致性目标（可验收，不是曲线重合）：**

- **开仓集合**：同一段已收盘 K，关掉实盘闸门后，回测开仓 bar_id 与重放一致。  
- **闸门集合**：打开与实盘相同的滑点/过期规则后，回测应能标出「若当时挂机将被放弃」。  
- **止损时点**：有 1 分钟时，实盘止损不应晚于 1 分钟复核给出的最早触及（允许更早）。  
- **差异率**：按 G1–G6 分类占比进复盘；未分类差异 < 5% 笔数（人工抽查）。

不允许的目标：要求回测净值曲线和实盘逐点重合。

## 五、每个交易策略的评估体系

### 5.1 三层档案（每个正式引擎一份，含自定义规则文件）

正式引擎：日内实体、趋势跟随、SuperTrend、双均线、均线波段、布林突破、以损定开、凯利突破、SAR、多因子 CTA、长线趋势加减仓、长线箱体、双周期通道、双周期分型、规则 DSL。

**A. 规则卡（人能读完）**

- 开仓、持有、平仓、反向、收盘清仓听谁。  
- 信号周期 / 止损周期是否允许不同。  
- 是否隔夜。  
- 公共 ADX 过滤接不接。  
- 禁止项：不写震荡反向单。

**B. 回测量尺（机器打分，沿用 `evaluation.py`）**

必过：盈利因子、R 期望、Calmar、回撤红线、连亏、震荡组不开或不开赚钱、滑点加压、参数扰动。  
样本：观察档允许笔数不足；红线仍一票否决。  
优化：不达标不写入（已有）。  
交叉：同门槛，标「较好」仍只是相对历史。

**C. 实盘量尺（新，按自然周）**

- 同品种同周期：实盘已平仓 vs 最近一次 **同配置** 回测的胜率、PF、平均滑点（点）。  
- 闸门命中：过期K、追价放弃、日亏、暂停报单各多少次。  
- 健康：现有 20 笔对照，改为同配置；连续 5 个交易日 `watch` → 建议停开（人点）。  
- 退役：样本外回测已淘汰，或实盘 PF 相对回测腰斩且笔数≥20。

### 5.2 晋级门（人批准，程序只给灯）


**做什么**

### S5 — 影子盘与上线单（与 P4.2 一起，按柜台时间）

**做什么**

### 明确不做（避免范围膨胀）

- 不为震荡做高抛低吸引擎。  
- 不自动改实盘 `engine`。  
- 不要求 Tick 全品种两年（P2.4 只复核入围）。

- 不在有仓时强制升级；S1 以后的代码按平时「关掉再打开」。

6. S5 跟仿真演练，不卡 S1。
