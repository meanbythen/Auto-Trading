# 49.8.0 阶段性验收报告

日期：2026-11-20
验收范围：实盘与回测一致性可信度、系统稳定性与资金安全、架构合理性与耦合、功能/接口完整性、冗余代码与测试文档。
方法：四条线并行静态审查 + 关键路径抽查 + 现有测试与真实数据核对。审查期间未修改业务代码。

---

## 一、总评

**结论：有条件通过。**

可以继续做 CTP 仿真和人工盯盘下的小资金实盘；**不建议在 P0 修复前无人值守挂机**。

| 维度 | 结论 | 主要依据 |
|---|---|---|
| 实盘 / 回测一致性 | 有条件可信 | 规则同源、成交近似偏保守；但证据窗口、健康对照过滤、口径字段仍不完整 |
| 系统稳定性 | 有条件稳健 | 登录闸门、对账失败停开、成交幂等、原子落盘扎实；仍有 2 个「未知当已知」的资金缺口 |
| 架构合理性 | 基本合理，需收敛 | 分层方向正确、核心规则单实现；但 OrderExecutor 过大、导入环、UI 跨线程改运行状态 |
| 功能与接口完整性 | 通过 | R1–R5 均有 UI 入口与数据落盘；审计等能力已有调用方 |
| 可维护性 / 冗余 | 需清理 | 参数标签漏项导致优化少搜两维、4 个测试红、工具脚本绕过风控、文档漂移 |

**放行门槛**：4 个 P0 清零；P1 中与对账、重连、证据窗口相关的项修复；再用同一策略跑满 2 周 CTP 仿真并签一份评审单。

## 四、P2：应排期，但不阻断本轮验收

- 收盘清仓：回测在 14:55 强平，实盘在 15:00 前收盘清仓，最后 5 分钟行情未纳入对照（`config` 的收盘清仓时间 vs `engine.py` 14:55 判断）。
- 品种时段表把 `lh`、`jd` 标成有夜盘；交易所实际无夜盘，夜盘时段统计会混入错误分组。
- 影子盘按「同品种 + 同方向 + 同开仓日」整组对齐，一天内多段开仓会被合并；建议加时间邻近与手数校验，或明确只做分布对照。
- `OrderExecutor` 约 2500 行，同时负责价格、报单、撤单、重试、账本、快照；建议拆出 `order_pricing`、`order_state`、`fill_reconcile`。
- 9 组导入环、`account ↔ trader`、`data ↔ backtest` 反向依赖；位置状态有「账本 / 柜台快照 / 运行缓存」三份真相。
- 品种乘数与默认 10 三处、删除引擎名单两份、参数节映射两处、胜率/PF 三套口径。
- 文档漂移：README 仍写 49.3.0 和已删除的 `preflight_check.py`；配置说明书停在 45.0.0；规划表仍把「影子盘 / 评审单」标成「缺」，R2 标题仍写「下一步」。
- 对账/快照无锁；单次扫描可能残留 CTP 会话；对账告警无节流。
- `unknown_working` 只在新交易日结算确认时清空；当天的单即使已撤或已终态也不会从列表移除，可能一整天停开新仓。方向保守，但缺「终态即清」与告警升级。
- 断线自愈依赖 CTP 柜台重连后重新登录；`runner.logged_in` 不随断线复位，当前靠 `session.ready` 兜底。需做一次断网/长时间重连失败演练，并补回归用例，确认不会半连接空转。

## 五、已验证做得好的地方

1. 回测与实盘共用同一份 `evaluate`、止损、手数、收盘清仓规则，不是两套复制逻辑。
2. 回测成交近似偏保守：下一根开盘、`min(止损, 开盘)`、同根歧义取劣价，方向正确。
3. 稳定性底座扎实：登录闸门、成交幂等、对账失败即停开仓、下单前意图落盘、原子替换、看门狗。
4. R1–R5 均有从 UI 到落盘的闭环；审计能力已被评审单复用，不是孤立脚本。
5. 15 个正式引擎的中文名与档案有单一来源，别名映射集中管理。

范围：P1-1、P1-2、P1-3、P1-4、P1-5、P1-6、P1-7、P1-8；统一「回测 / 实盘」同窗口、同品种、同账户口径；评审单签名绑定证据摘要；滑点表头迁移；补全快照口径字段。
验收：评审单任一项为「未记录」时不能签「允许小资金挂机」；今日一致性只比同一时间窗；老滑点文件自动迁移。

### R8 — 可维护性与发版门禁

范围：P0-3、P1-14、P1-13；删除或硬门禁 `quick_order`；修测试隔离；文档冲刷（README、配置说明书、规划状态表）；去重乘数/参数节/胜率口径。
验收：`pytest` 全绿；配置说明书与 `config.example.yaml` 键一致；规划表状态与代码一致。

### R9 — 架构收敛

范围：拆分 `OrderExecutor`；建立 UI→命令层接口，禁止 UI 直接改运行对象；用 import-linter 固定依赖方向；位置状态收敛为单一真相 + 只读快照。
验收：`ui` 不再直接写 `bot.sizer/cfg`；核心模块无环；`OrderExecutor` 单文件职责可测试。

### R10 — 成本与成交现实性

范围：补齐在跑品种费率与合约乘数；把超时撤单、部分成交、锁板、止损滑点纳入回测默认模型；收盘清仓 14:55/15:00 口径统一；修正品种夜盘表。
验收：回测净盈亏含全部费用；同一策略的仿真滑点不高于压力档；时段统计不再把无夜盘品种算进夜盘。

### R11 — 性能专项（已启动，49.9.0）

范围：先解决交叉测试卡界面，再做数据缓存与图表终端试点。

- 已完成第一阶段：交叉测试改多进程（spawn，默认最多 4 个），主进程只收进度；开跑前统一预取 K 线，当下行情由主进程补；组合少于「进程数 × 8」自动回退单进程。
- 实测 34 个组合：三进程 29.9 秒，单进程 37.8 秒；逐组成交笔数、净盈亏一致。18 个组合并行仍略慢，已由阈值挡住（少于「进程数 × 8」走单进程）。
- 待做：组合按「品种 × 周期」分块以减少重复加载；结果表批量刷新；事件总线接入；K 线图表窗口试点。
