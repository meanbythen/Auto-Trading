## 过夜挂机前先处理

这些会直接影响真金白银。

### 1. 真实演练清单还空着（紧急）

代码里的 P0（成交去重、关窗等待、三方对账、看门狗）有单测，但 TODO 里仍是空勾：

- 启动常驻 → 手工开仓 → 关窗重启 → 核持仓 / 账本 / 告警
- 柜台有仓、程序无仓（幽灵仓）补记只发生一次
- 冷备守护：任务管理器杀掉主进程后，仿真账号 1 手仓是否被平掉
- 断线、重连、重启后的持仓对账

**建议**：先用仿真账号把上面几条跑完，再考虑④过夜。

### 2. 交易台和常驻是两条柜台连接（紧急）

两边各建一个 `CtpTrader`。同一资金账号、同一流文件目录。柜台会踢线。

- 常驻已跑时，交易台再点「连接登录」会被拦住。
- **反过来没有拦**：交易台还登着就点启动常驻，可能把一边踢掉。

**建议**：测完关掉交易台，再开常驻。程序里应把反向也拦住。

### 3. 没有交易所原生止损单（高）

`CtpNativeStopAdapter` 明确不支持。程序被杀、电脑断电时，仓上没有券商条件单。冷备守护也救不了整机断电。

**建议**：问华泰是否开放条件单 / 预埋单。没开就不要无人值守过夜。

### 4. 「暂停报单」说明和实现不一致（高）

- `runner.py` 注释写：开平仓、止损、清仓都不发出去。
- `order_executor.py` 实现：只停开新仓，止损和清仓仍发。

这是保护持仓的合理实现，但注释会让人以为已经全停。应改注释和按钮说明。

### 5. 模拟开着时假装已登录（高）

`dry_run` 为真时，常驻把 `logged_in` 直接设成成功、不连柜台、跳过对账。扫描还在跑。看顶部「执行通道」：应出现「不连柜台」，不要当实盘。

### 6. 实盘和回测最后一根 K 线口径不同（高）

- 回测丢掉还在走的那根。
- 盘中：有仓时可能把未收完的影线拼进去做止损；若去掉未收完后一张表都空了，会把整段（含未收完）当已收盘。

对照成绩时记住：回测偏「收盘确认」，盘中偏「碰到就走」。不要用回测胜率直接当过夜依据。

## 架构和代码质量（不是今晚改）

能跑，但改一处容易扯到别处。

| 味道 | 现象 |
|------|------|
| 上帝对象 | 主窗口 15 个 mixin 叠在一个类；常驻四个 mixin 拼一个机器人。`runner.py`、下单 mixin 都在 2000 行以上 |
| 读界面会写盘 | 克隆配置、回测、启动常驻都会先采集表单；采集路径会写密钥和环境变量 |
| 配置就地改 | 上线阶段改执行通道和档案名；柜台资金写回 yaml 权益 |
| 双会话语义 | 交易台可多挂单、超时不自动撤；常驻一次一单并超时撤 |
| 半成品内核 | 事件总线、K 线快照生产零引用；条件单适配器占位 |
| 全局资源 | 拉 K 线全进程一把锁；sqlite 连接进程内不关 |
| 日志名过时 | 交易台仍打「仿真测试」，真实账号也这样刷 |
| 文档落后 | TODO 抬头仍写 45.9.0；`docs/测试报告/`、长线箱体说明书、策略迭代说明被引用但文件缺失 |

CTP 单测很厚，**全部是假客户端，不加载柜台动态库**。盖不到：结算单、流文件、席位互踢、部分成交乱序、前置切换、断线后补单。
