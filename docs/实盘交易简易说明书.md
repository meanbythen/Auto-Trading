# 自动交易系统操作指南

适用版本：**49.18.2**（2026-11-20）
适用对象：本机单账户、华泰期货 CTP、同花顺下单、日线/分钟级趋势策略。
说明：本文按当前界面写成。界面文字可能随版本微调，但流程不变。

---

## 最短路径（十分钟跑起来）

> 下面是首次练习的最安全路径。已经在实盘运行的，不要为了试流程去改执行通道；直接看第三、五节。

1. `python app_entry.py` 启动，确认顶部版本 49.18.2。
2. 账号页 → 执行通道选 `sim`（只练习时改）→ 保存。
3. 交易配置 → 选策略、信号周期、关注品种 → 保存。
4. 历史回测 → 同策略同品种跑一遍，确认信号和成交约束。
5. 运行页 → 启动常驻，看日志里的扫描、算仓、清仓时刻。
6. 复盘页 → 生成复盘；有真实成交再生成上线评审单。
7. 确认没问题后，再按第五节走 `gui` 或 `ctp`。

## 一、先分清三条通道

程序不是只有一种“下单”。三条通道的执行方式完全不同，先选对通道，后面的设置才有意义。

| 通道 | 界面叫法 | 是否连柜台 | 是否点同花顺 | 典型用途 |
|---|---|---|---|---|
| `sim` | 模拟 | 否 | 否 | 只按行情和策略算账，验证信号、复盘、回测对照 |
| `gui` | GUI | 否 | 是 | 用同花顺模拟账号练手，验证坐标、点击、登录；不要用真实账号练 |
| `ctp` | CTP | 是 | 否 | 华泰柜台直连，分仿真账号和真实账号 |

选择位置：**账号页 → 执行通道**。
- 选 `sim`：不连柜台，不点软件。
- 选 `gui`：需要同花顺已登录，且坐标标定过。
- 选 `ctp`：下面必须再选“CTP 操作账”（仿真账号 / 真实账号）和券商档案（`huatai_sim` / `huatai_live`）。

## 二、启动与配置来源

### 2.1 启动

在项目根目录执行：

```powershell
python app_entry.py
```

也可以 `python -m src.main --gui`。程序只允许开一个实例。

### 2.2 四个关键文件

| 文件 | 作用 | 要不要手改 |
|---|---|---|
| `config/config.yaml` | 程序运行配置（策略、品种、风控、通道） | 一般不用，界面保存即可 |
| `config/secrets.local.yaml` | 密码、认证码等密钥 | 首次填写，之后不要提交 |
| `config/品种与合约.xlsx` | **品种唯一权威表**：乘数、每跳、保证金、手续费、交易时段、清仓时刻 | 改品种时改这里 |
| `data/` | K 线、账本、滑点、日志、上线进度 | 不手改 |

规则：**品种与合约表是唯一权威**。界面保存配置时会按表回写 `config.yaml`；表里空着的格子才回退到代码默认值。不要在两处各改一半。

### 2.3 首次启动检查

1. 顶部版本号是否与 `VERSION` 一致。
2. 运行页顶部 6 张卡：运行状态、策略引擎、信号周期、执行通道、关注品种、程序持仓。
3. 账号页“测试前置”是否通。
4. 运行日志有没有“配置已加载”“交易时段……”这类启动行。

## 三、页面地图与各模块操作逻辑

程序共 11 个页签。下面按“什么时候用”说明。

### 3.1 运行

日常主页面。

- **启动常驻 / 停止常驻**：启动后按信号周期扫描、下单、对账；停止只停调度，不自动平仓。
- **暂停报单 / 恢复报单**：只停“开新仓”；止损、收盘清仓照发。
- **核对委托**：崩溃或断线后，用来解除“重复报单”熔断；不改持仓。
- **上线阶段**：四步上线菜单，详见第五节。
- **打开交易台**：CTP 手工测试工具（资金、合约、委托、柜台必测）。
- **本阶段完成**：勾选当前阶段已通过，写入 `data/go_live.json`。
- **测试工具**：试跑一轮、点击下单、完整自检。
- **手工单（只改程序账本）**：你在手机/软件上成交后，把品种、价格、手数、止损价录进来。它**不会**去点交易软件，也不会报柜台。止损价可留空，留空时由策略按 2×ATR 补（见 5.3“手动开仓后，程序为什么会自动平仓”）。
- **持仓卡**：显示程序账与柜台差异；可认领、平掉、忽略。
- **导出全部到一个 Excel**：把当天账本、成交、拒单、日志摘要导出。

### 3.2 账号

所有“连谁”的设置都在这里。

- 执行通道：`sim` / `gui` / `ctp`。
- CTP 操作账：仿真账号 / 真实账号；只换账号，策略不变。
- 券商档案：`huatai_sim` / `huatai_live`；填前置地址、BrokerID、资金账号、AppID、密码环境变量、认证码环境变量。
- 测试前置：验证 CTP 前置能否连上。
- 同花顺软件：路径、窗口标题、启动等待、自动登录、账号密码、验证码。
- 华泰仿真：仿真资金号、仿真密码（写 `huatai_sim`，不要填真实资金号）。
- 天勤行情：行情账号。
- **保存**：账号页和交易配置页都要各保存一次。

密码不写进 `config.yaml`，只写 `secrets.local.yaml`。默认环境变量：`CTP_PASSWORD`（仿真）、`CTP_LIVE_PASSWORD`（真实）、`CTP_AUTH_CODE`（认证码）。

### 3.3 交易配置

策略与风控的核心页面，逐块说明见第四节。

### 3.4 策略编辑器

- 写/改规则 DSL（YAML）。
- 保存前会做语法检查；保存后在“策略引擎”里选中才会生效。
- 改完先跑历史回测，不要直接挂实盘。

### 3.5 历史回测

- 选引擎、品种、周期、日期、行情来源。
- **结束日期按期货交易日截止**：结束日只算到当天 20:59，当晚 21:00 的夜盘属于下一交易日。要看结束日当晚夜盘，勾「含当晚夜盘」，只把这一次回测的结束日往后推一个交易日（会连下一交易日的日盘一起算），日期框本身不改、不会被越推越远。
- 成交近似：下一根开盘、滑点跳数、开仓滑点上限。
- **成交现实性默认开启**：一字板不开、部分成交按 10% 成交量、锁板挂单最多等 1 根。要复现旧成绩，在 `config.yaml` 的 `backtest.liquidity` 整组关掉。
- 跑完看：交易次数、净盈亏、胜率、盈亏比、最大回撤、成交约束说明、拒单原因。
- 可导出结果，供复盘页“上线评审单”引用。

### 3.6 数据管理

- 下载/补 K 线、下载 tick。
- 从同花顺读取本地数据。
- 数据质量检查、库存查看。
- 回测前先确认目标品种、周期、日期范围的数据齐全。

### 3.7 交叉测试

- 一次跑“多策略 × 多品种 × 多周期”。
- 日期口径和历史回测一致：结束日只算到当天 20:59；要看当晚夜盘，勾「含当晚夜盘」。
- 用“当下行情”验证某套参数在当前环境是否还站得住。
- 结果是横向对照，不替代单品种详细回测。

### 3.8 策略优化

- 网格搜索参数。
- 日期口径和历史回测一致：结束日只算到当天 20:59；要看当晚夜盘，勾「含当晚夜盘」。
- 样本外冻结、参数扰动、压力测试。
- 优化结果只作候选；上线前仍要回到历史回测和复盘页走一遍。

### 3.9 复盘

- 选日期、品种、看哪段（日盘/夜盘/前夜盘+日盘）、信号周期、止损周期、策略对照。
- **生成复盘**：用当天真实行情给策略打分，算 MAE/MFE/R，对照挂机记录。
- **保存当天基线**：把“策略会不会开、程序有没有下单、账本有没有记”收成一份对照，以后同一天可重跑。
- **生成上线评审单**：数据门禁、今日一致性、健康对照、风控、签字证据；零费率品种会被标“注意”。
- 页面下方“成交质量”：真实滑点按方向、按品种、按时段给建议；没样本会明说“不足 3 笔”。

### 3.10 账户分析

四本账：GUI 真实 / GUI 模拟 / CTP 真实 / CTP 仿真。

- 选账本、刷新柜台、看权益/可用/持仓/成交。
- 支持手工补录入账。
- 分账目的：GUI 和 CTP、真实和仿真不混算。

### 3.11 因子挖掘

- 按因子扫描全市场，生成候选池（`data/因子挖掘候选池.json`；旧 `data/规律候选池.json` 只读迁移）。
- 日期口径和历史回测一致：结束日只算到当天 20:59；要看当晚夜盘，勾「含当晚夜盘」。
- 用于找品种，不直接产生交易信号。
- 候选进关注列表前，仍要看流动性和回测。

## 四、交易配置页逐块说明

### 4.1 品种与合约表 / 账户 / 品种

- **品种与合约表**：交易配置页有独立一块，显示路径、摘要，按钮“打开表格”“重新读取”。
- 改品种：先“打开表格”，在表里改乘数、每跳、保证金、手续费、交易时段、清仓时刻；关掉 Excel 后点“重新读取”，再保存配置。
- 关注品种：运行页和复盘页共用这一份；添加/移出会同步进品种与合约总表。
- 换月、换品种：先改表，再保存配置。

### 4.2 开仓设置（所有策略共用）

- **信号周期**：开仓用哪根 K 线。当前 15 分钟。
- **开仓触发方式**：收线确认 / 盘中触发。回测天然只有收线口径。
- 回测页的“下一根开盘成交”只影响回测，不影响实盘。

### 4.3 止损设置（所有策略共用）

- 止损周期、触发方式。
- 通用止损：关闭 / SAR / 前高低点 / Chandelier 吊灯 / 盈利 1ATR 后保本。
- 策略自身止损优先；通用止损是额外一层。
- 止损平仓不受“下单最小间隔”限制。

### 4.4 风控与资金管理

当前实际值（可在界面改）：

| 项目 | 当前值 | 作用 |
|---|---|---|
| 凯利公式 | 开 | 按本腿最近净平仓动态算目标，固定风险仍封顶 |
| 凯利占用 | 四分之一凯利 | 全凯利再乘 0.25 |
| 凯利每笔最多% | 1 | 与固定风险 1% 再取更小值 |
| 凯利胜率% / 盈亏比 | 66 / 3.98 | 仅供 `auto_from_ledger=false` 手工兼容模式；自动模式不用 |
| 每笔风险% | 1 | 固定风险硬上限；不足 30 笔净样本时也按它算 |
| 仓位上限% | 80 | 权益里最多拿这么多交保证金 |
| 日最大亏损(元) | 3000 | 触发后只拦开新仓 |
| 动态减仓 | 开 | 回撤 5% 减半新开仓、10% 停开；不强平已有仓 |
| 下单最小间隔秒 | 60 | 平仓后再开新仓要等够；止损/清仓不受限 |
| 每日最多下单 | 5 | 按**开仓次数**计，平仓不占额度 |
| 单笔最大手数 | 5 | 本机保护上限；算仓时直接取小 |
| 组合风控模式 | observe | off=关；observe=只记录本应拦截；enforce=真正拦开仓 |
| 组合风险热度上限% | 0 | 所有持仓到止损的最大亏损 ÷ 权益；0=不限。开仓通过后先记在途预留，同轮不会重复占用 |
| 品种净手数上限 | 0 | 组合内同一品种净持仓上限；0=不限 |

动态凯利默认取本腿最近 50 笔净平仓，至少 30 笔才启用；样本不足退回固定风险，样本足够但无正期望则拒绝新开仓。每手风险按「止损距离×合约乘数 + 开平手续费 + 双边预计滑点」计算，再与保证金/可用资金和单笔手数上限取小。回测与实盘使用同一公式。

`sizing_mode: fixed` 只是策略上限：仍先按风险%和止损距离算仓，再和固定手数取小；缺止损不会开裸仓。组合持仓读不到时，开新仓按失败关闭，平仓照常发出。

算仓顺序：

```
凯利/风险% → 仓位上限 → 单笔最大手数 → 策略指定手数 → 动态减仓
```

每一步只往下压，不会把风控算出的手数放大。日志会写“意图 N 手 / 仓位上限 N / 单笔上限 N”，能看出最后为什么是这个手数。

### 4.5 同花顺软件与坐标

- 路径、窗口标题、启动等待。
- 自动登录：账号、密码、验证码。
- “标定下单坐标”：给当前窗口保存一套坐标，命名后可切换。
- 换主题、换分辨率、换显示器后必须重新标定，否则 `gui` 通道会点错。

### 4.6 配置存档

- 把当前整套配置存成一份存档。
- “一键应用选中的配置”会覆盖当前配置，应用前先确认。
- 建议至少保留：当前实盘、仿真、回测三套。

## 五、三条通道从零到实盘

### 5.1 `sim` 通道（只算账）

1. 账号页 → 执行通道选 `sim` → 保存。
2. 交易配置 → 选策略、信号周期、关注品种 → 保存。
3. 历史回测跑同一策略同一品种，确认信号逻辑。
4. 运行页 → 启动常驻。
5. 看日志：有信号、有手数、有“模拟成交”，但没有柜台回报。
6. 复盘页生成复盘，和回测对照。

适合：验证策略、验证手数、验证清仓时刻，不涉及任何真实资金。

### 5.2 `gui` 通道（点同花顺模拟）

前置：同花顺已安装、已登录模拟账号、窗口标题与账号页一致。

1. 账号页 → 执行通道选 `gui`；填同花顺路径、窗口标题、启动等待。
2. 打开同花顺，登录模拟账号。
3. 交易配置 → “标定下单坐标”，按提示点完买多/卖空/平仓/确认。
4. 运行页 → 测试工具 → **试跑一轮**，看是否只读不点。
5. 确认无误后 → **点击下单**，用 1 手验证。
6. 检查同花顺委托列表和程序账本是否一致。
7. 正式试跑：启动常驻，`dry_run` 先保持开启观察，再关闭。

限制：`gui` 一次只适合一个品种；多品种请用 `ctp`。

### 5.3 `ctp` 通道（华泰柜台，四步上线）

四步在运行页“上线阶段”菜单里，顺序不能跳：

| 阶段 | 界面名称 | 谁在下单 | 账户 |
|---|---|---|---|
| ① | 手工仿真（华泰外接测试） | 人，交易台 | 仿真 |
| ② | 手工真实账户 | 人，交易台 | 真实 |
| ③ | 策略自动仿真 | 策略 | 仿真 |
| ④ | 策略自动真实账户 | 策略 | 真实 |

**只有 ③④ 允许策略向柜台发单。①② 即使点“启动常驻”，策略也不会自动下单。**

#### 准备（按阶段填对应账号）

账号页按你要走的阶段填，不用把仿真和真实都填满：

1. **CTP 操作账**：当前这一步用仿真还是真实。
2. **券商档案**：仿真填 `huatai_sim`，真实填 `huatai_live`；前置地址、BrokerID、AppID 按档案填。
3. **资金账号**：真实档案填真实资金号；仿真档案填仿真号。
4. **密码环境变量**：仿真 `CTP_PASSWORD`，真实 `CTP_LIVE_PASSWORD`；认证码 `CTP_AUTH_CODE`。
5. **华泰仿真**：只在走仿真阶段时填仿真资金号和仿真密码，不要填真实资金号。
6. 点“测试前置”，通过后再进交易台。

#### ① 手工仿真

1. 上线阶段选“① 手工仿真”。
2. CTP 操作账选“仿真账号”，券商档案选 `huatai_sim`。
3. 打开交易台 → 登录。
4. 柜台必测逐项做：连通性、开/平/撤、连接状态、报撤单笔数、阈值预警、错误合约/价位/超手数、资金不足/持仓不足、暂停交易、日志、连续 10 分钟、看穿式 IP/MAC。
5. 每项在交易台勾选，最后点“本阶段完成”。

通过标准：能开、能平、能撤、能反手，回报和柜台一致，错误能显示，10 分钟不崩。

#### ② 手工真实账户

1. 上线阶段选“② 手工真实账户”。
2. CTP 操作账切“真实账号”，券商档案切 `huatai_live`。
3. 打开交易台 → 登录真实资金。
4. 用最小手数手工开一笔、平一笔、撤一笔。
5. 核对：成交价、手续费、保证金、可用资金、持仓。
6. 点“本阶段完成”。

通过标准：真实柜台能完成最小手数开平撤，费用和保证金与结算单口径一致。

#### ③ 策略自动仿真

1. 上线阶段选“③ 策略自动仿真”。
2. 账号页确认：执行通道 `ctp`、操作账“仿真账号”、档案 `huatai_sim`。
3. 交易配置确认：策略、周期、品种、风控、单笔最大手数。
4. **关闭交易台登录**，避免同一账号互踢。
5. 运行页 → 启动常驻。
6. 观察：信号 → 算仓 → 风控 → 报单 → 成交 → 账本 → 止损/清仓。
7. 建议连续跑满 **2 周**，覆盖日盘、夜盘、清仓、断线重连、人工干预。
8. 复盘页生成“上线评审单”，确认数据门禁、今日一致性、健康对照、风控都通过。

通过标准：信号、报单、成交、账本、持仓连续多日一致；滑点样本足够；无未解释的拒单或冻结。

#### ④ 策略自动真实账户

1. 上线阶段选“④ 策略自动真实账户”。
2. 账号页：操作账“真实账号”、档案 `huatai_live`。
3. 交易配置：单笔最大手数、日最大亏损、仓位上限先按最小资金设置。
4. 关闭交易台，启动常驻。
5. 先跑 1 个交易日，收盘后导出 Excel、生成评审单、按结算单核对费用。
6. 评审单签字后才算正式放行。

通过标准：真实成交与仿真口径一致；滑点不高于压力档；费用、保证金、净盈亏与结算单对得上。

#### 每天必做的对账

- 启动后看“启动权益已按柜台改本地账”。
- 持仓对不上会冻结自动交易，等人工认领。
- 手机/软件手工成交后，用运行页“手工单”录入，或点“同步柜台”让程序发现并记账。
- 认领后程序会接管止损、反向、收盘清仓；具体判断见下一小节。

#### 手动开仓后，程序为什么会自动平仓

先分清两种状态：

- **未认领**：柜台有仓、账本没有。程序会冻结自动交易，**不替这条仓做任何开平**；你在手机/软件上自己管。
- **已认领**：账本记上这条仓（价格用你填的成交价或柜台成交价），从此策略接管，止损、反向、收盘清仓都会对它生效。

程序平掉手动仓，只可能是下面几种之一，先看日志关键词：

| 日志关键词 | 原因 | 是否正常 |
|---|---|---|
| `…止损 … 离场`、`stop=…` | 策略止损（含 ATR 跟踪止损） | 正常；重点看止损价是否落在开仓价之外 |
| `反向`、平仓后又开反向仓 | 策略信号翻转 | 正常 |
| `收盘清仓`、`清仓时刻` | 品种表的 14:55 或夜盘收盘前 5 分钟 | 正常 |
| `动态减仓`、`减到 N 手` | 风控回撤减半/停手（仅“动态减仓”开启时） | 正常；只减不增，至少留 1 手 |
| `手工平仓`、`已执行 close` 由你触发 | 人工命令 | — |

**不会因为“账本和柜台对不上”就自动平仓。** 对不上时程序只冻结开新仓、等你认领，不会替你平。

**49.18.2 的防自触发规则**（专指认领/重建的仓）：

1. 没有止损价时，不再拿现价当止损；按「开仓价和现价里更差的一侧」外放 2×ATR。
2. 本根新算出的止损只从下一根开始判定；认领后的第一根不会用当根最高/最低价把自己打掉。
3. 所以空单 3751 认领、现价也是 3751 时，止损约在 3751+2×ATR，不会立刻平。

**认领后仍被平掉的三种情况（不是 bug）：**

- 认领时价格已经比开仓价不利超过 2×ATR → 下一根按保护止损。
- 策略信号翻转 → 反向平仓。
- 到了清仓时刻 → 收盘清仓。

**建议的操作顺序：**

1. 手机开仓后先“同步柜台”，核对柜台持仓、成交价、手数。
2. 要程序管：点认领；认领后至少看一根 K 线，确认止损线在开仓价之外。
3. 不要程序管：**不要认领**，保持冻结，手动处理这条仓；冻结期间程序不会开新仓。
4. 认领/录入价格必须是真实成交价；填错会让 2×ATR 止损带整体偏移。
5. 想让止损更宽或更窄：改策略的 ATR 止损参数，不能对单条仓单独指定。

#### 回退

任何一步不对：上线阶段退回上一阶段 → 账号页切回 `sim` 或仿真档案 → 停止常驻 → 保存。真实持仓先手工处理，不要让程序带着不明仓位继续跑。

## 六、下单链路与闸门

一次开仓要过这些关，任何一关不过都不会报柜台：

```
策略信号
→ 算仓：凯利/风险% → 仓位上限 → 单笔最大手数 → 策略手数 → 动态减仓
→ 早期闸门：暂停报单 / 策略健康 / 账本可写 / 同一根K线去重
→ 发送闸门：最小手数 / 上线阶段 / 未完成委托 / 账本与柜台 / 风控 Guardian
→ 定价：对手价、开仓滑点上限
→ 报单 → 成交回报 → 去重入账 → 风控状态更新
```

几个容易误解的点：

- **平仓不占“每日最多下单”额度**，也不受“下单最小间隔”限制。
- **止损和收盘清仓永远优先**：`close` 分支直接放行；只有“上一笔委托还没回报”时会等它结束。
- **60 秒间隔从成交/记账时刻算**，包括手机平仓被程序发现后补记的那一笔。
- **同一根 K 线平仓后不会立刻反手**：要等下一根已收盘 K 线。
- **15 分钟周期下 60 秒几乎无感**；1/3 分钟周期可能延迟一次开仓或反手。

## 七、每日运行流程

### 盘前

1. 启动程序，确认版本、通道、账号。
2. 账号页测试前置；`gui` 通道先确认同花顺已登录。
3. 看运行页持仓卡与柜台是否一致。
4. 确认上线阶段没被误改。
5. 确认数据齐全（数据管理）。

### 开盘

1. 启动常驻。
2. 看第一根 K 线的扫描解说：方向、形态、是否开仓、止损价。
3. 有手工仓先录入或认领。

### 盘中

- 只看三件事：有没有该开没开、有没有该平没平、账本和柜台是否一致。
- 暂停报单只停开仓；要停策略请用“停止常驻”。
- 出现冻结，先处理持仓差异，不要反复点“核对委托”。

### 收盘

- 日盘 14:55、夜盘收盘前 5 分钟，程序按品种表清仓；之后只平不开。
- 看日志“清仓 14:55,22:55”是否与品种表一致。

### 盘后

1. 运行页导出 Excel。
2. 复盘页生成复盘、保存基线。
3. 有真实成交时生成上线评审单。
4. 按期货公司结算单核对费用、保证金、净盈亏。
5. 记录当天异常：拒单、冻结、断线、人工干预。

## 八、今天优化了什么，人工怎么体验

### 8.1 不写脚本，回测就能看到的

- **费用**：跑一笔历史回测，看净盈亏和成交明细；再打开复盘页生成评审单，看“成本”一行。
- **成交约束**：选一个有过一字板/低成交量的品种（如 FG、SH），跑 15 分钟回测，看成交说明和拒单原因。
- **清仓时刻**：启动常驻后看启动日志；日盘 14:55 看程序是否自动平仓。
- **夜盘表**：22:00 后选生猪，看日志是否提示不在交易时段；或直接看品种表的时段列。

### 8.2 要在仿真/实盘里才能看到的

- **滑点时段统计**：需要真实 CTP 成交样本，复盘页才会分“日盘/夜盘/其他”给建议。
- **单笔最大手数生效**：把上限改成 2，等下一次真实信号；日志会显示算成 2 手。没有信号时，只能在界面上看到设置，不能验证拦截。
- **认领仓不再假止损**：用手机开 1 手空/多，点“同步柜台”并认领，观察下一两根 K 线是否还持有。注意：如果认领时已经亏超 2×ATR，仍会止损，这是正常保护。

### 8.3 必须人工核对、程序替代不了的

- **手续费**：价格型费率是折算值，必须按期货公司结算单核对；评审单遇到零费率会标“注意”。
- **两周 CTP 仿真 + 已签评审单**：R10 的放行门槛，目前仍未完成。
- **银期、看穿式、IP/MAC 报备**：柜台侧要求，程序只能提示。

## 九、常见问题速查

| 现象 | 常见原因 | 处理 |
|---|---|---|
| 日志“超过单笔最大 N 手” | 单笔最大手数设置太小 | 交易配置 → 风控与资金管理改大，保存即生效 |
| 日志“距上一笔下单不足 60 秒” | 平仓后开仓间隔未到 | 等；或调小“下单最小间隔秒” |
| 有信号没下单 | 暂停报单 / 上线阶段①② / 未完成委托 / 账本对不上 / 健康停开 | 按日志里的拒单原因逐项排查 |

| 手动开仓后程序自动平仓 | 策略止损 / 反向信号 / 收盘清仓 / 你手工平，四选一 | 先看日志关键词，按 5.3 小节判断是否正常 |
| 认领后第一根就被平 | 49.18.2 之前会拿现价当止损；当前版本已修 | 确认版本 49.18.2；若仍发生，核对认领价与 2×ATR 距离 |
| `gui` 点错位置 | 坐标失效/窗口变了 | 重新标定下单坐标 |
| CTP 登录被踢 | 交易台和常驻同时登录 | 挂机前关闭交易台 |
| 回测和以前不一样 | 49.17.0 起成交现实性默认开启 | 要复现旧成绩，在 `backtest.liquidity` 整组关掉 |

## 十一、边界与已知限制

1. 手续费是交易所标准折算值，最终以期货公司结算单为准。
2. 回测成交模型是近似：一字板、10% 成交量、1 根超时，不模拟排队和逐笔撮合。
3. 滑点统计需要真实成交样本；样本不足 3 笔时不给建议。
4. `gui` 通道依赖坐标，不适合多品种长期挂机。
5. CTP 通道要求交易台与常驻不同时登录同一账号。
6. 上线阶段 ①② 策略不会下单，这是设计，不是故障。
7. R10 的“两周仿真 + 签字评审单”尚未完成，完成前不建议放大真实资金。
