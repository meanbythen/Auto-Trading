## 一、启动前准备（一次性）

### 1. 环境

| 项 | 要求 |
|---|---|
| Python | 3.10~3.12 |
| 系统 | Windows（同花顺 GUI 自动点击只在 Windows 生效） |
| 依赖 | `pip install -r requirements.txt`（含 tqsdk 天勤行情） |
| 项目路径 | 随意；启动命令 `python src/main.py` |

### 2. 配置文件复制

```
copy config\config.example.yaml config\config.yaml
```

然后编辑 `config/config.yaml`（**下面所有配置都改这份**）。

### 3. 同花顺准备（GUI 模式必填）

1. 打开同花顺期货通，登录华泰期货账号
2. 进入「期货通」下单界面（确保有「普通下单」区域）
3. 程序首次启动时会自动把价格框设成「对手价」
4. 关键坐标标定（`trade.gui` 下）：

```yaml
trade:
  executor: gui
  gui:
    price_input:   [658, 1041]   # 对手价价格框坐标（鼠标悬停看）
    volume_input:   [507, 1042]   # 手数输入框
    buy_open_btn:   [386, 1123]   # 买开按钮
    sell_open_btn:  [550, 1125]   # 卖开按钮
    close_btn:      [704, 1127]   # 平仓按钮
    confirm_times:  0             # 期货通无确认框，点完买卖就结束
    assume_fill:    true          # 点击后立刻改内部持仓；改 false 更安全
```

> ⚠️ **坐标是你自己电脑的屏幕像素**，必须在你自己的分辨率和缩放下重新标定。

## 二、三步路线选择

一次只跑 **一套策略** + **一个执行通道**，两个独立配置项。

### 第一步：选执行通道 `trade.executor`

| 值 | 含义 | 何时用 |
|---|---|---|
| `sim` | 模拟成交（默认 dry_run=false 也不下真单） | 验证策略逻辑、回测前试跑 |
| `gui` | 鼠标点击同花顺下单 | 未开通程序化的实盘（你的当前方案） |
| `ctp` | 华泰 CTP 官方接口 | 已开通程序化交易（代码已通，配好前置/账号即用） |

**你当前用的是 `gui`**，坐标已标定。

### 第二步：选策略引擎 `strategy.engine`

程序内置多套策略，一次只用一套：

| 引擎 | 中文名 | 适用行情 | 核心逻辑 |
|---|---|---|---|
| `daily_body` | 日内实体（**默认**） | 箱体突破，避开已走出的单边 | 开盘 ETH 画箱体，收盘离开才开仓；止损守箱沿；策略内 ADX 过高不开 |
| `float_hold` | 日内浮盈飘单 | 日内趋势延续 | 等开盘观察结束，顺着 EMA60/120 开仓；止损放宽、过滤更少 |
| `trend_follow` | 趋势跟随 | 单边趋势 | 唐奇安海龟：破前 20 根高点进、破前 10 根低点出、2ATR 止损 |
| `supertrend` | SuperTrend | 持续趋势 | ATR 通道翻转开仓，默认反手（`reverse_on_flip`） |
| `dual_ma` | 双均线 | 缓趋势 | 短均线上穿长均线且收盘站上才做多，反向做空，2ATR 止损 |
| `ema_swing` | 均线波段 | 跨日波段（建议 15 分钟） | 方向均线 + 信号三线；多空分界线/止损/倾角可分开填 |
| `bollinger` | 布林突破 | 中速趋势 | 只顺势：中轨上方破上轨做多，跌回中轨离场 |
| `sar_trend` | SAR 波段 | 波段 | SAR 翻转 + EMA20 方向过滤，SAR 线本身当移动止损 |
| `multi_factor` | 多因子 CTA 加权打分 | 各趋势 | 日线定方向；四因子加权 ≥ 0.6；弱趋势要 ≥0.75 并打成仓位 |
| `swing_trend` | 长线加减仓 | 长线趋势 | 大周期定方向；回调跟信号周期、止损跟止损周期；可加可减 |
| `swing_box` | 长线箱体突破 | 箱体突破 | 震荡箱子收盘走出才顺势做；假突破回箱就走 |
| `liq_stop` | 以损定开 | 扫损后回流 | 击穿止损聚集区再收回区间外侧才进场；止损放区间外 ATR |
| `kelly_break` | 凯利突破 | 突破趋势 | 收盘破前 N 根高低点开仓；ATR 止损 + 固定盈亏比止盈 |
| `rule_dsl` | 自定义规则 | 自行定义 | 读 `config/rules/*.yaml`，用指标条件组合开平仓；见 [策略编辑器使用说明](策略编辑器使用说明.md) |

**默认引擎是 `daily_body`（日内实体）**，`config.example.yaml` 里也是它。多因子、日内浮盈飘单等仍可在下拉里选；已保存的配置不会被自动改掉。

每个引擎的详细参数配置写在对应引擎名的 yaml 小节里，比如：

```yaml
strategy:
  engine: daily_body
  daily_body:
    eth_minutes: 15          # 第一ETH窗口（从开盘起算，分钟）
    eth_minutes2: 30         # 第二ETH窗口（也从开盘起算；过点后丢掉第一窗口）
    stop_extra_ticks: 1      # 止损在箱沿外再让几跳
    skip_gap_atr_mult: 2.5   # 开盘跳空超过开盘前 ATR 几倍就不开（0=不限制）
    max_box_atr_mult: 5.0    # 箱子宽过开盘前 ATR 几倍就不开（0=不限制）
    max_chase_atr_mult: 1.0  # 离破位超过开盘前 ATR 几倍就先等回抽（0=不限制）
    ema_period: 20           # EMA 快线周期（过滤假突破用）
    ema_buffer_ticks: 2      # EMA 缓冲几跳
    day_cutoff: '10:45'      # 日盘开仓截止钟点（过了不再开新仓）
    night_cutoff: '22:30'    # 夜盘开仓截止钟点
```

> 你当前 config.yaml 的 `daily_body` 参数就是上面这组，ETH 15 分钟 + EMA 20 过滤 + 日盘 10:45 截止。

### 第三步：选信号周期 `strategy.timeframe`

| 值 | 说明 | 哪些引擎用 |
|---|---|---|
| `5` | 5 分钟（**日内实体推荐**） | daily_body, float_hold, trend_follow, supertrend, dual_ma, ema_swing, bollinger, sar_trend, multi_factor, liq_stop, kelly_break, rule_dsl |
| `15` | 15 分钟 | 同上，趋势更稳但开仓更少 |
| `60` | 60 分钟 | swing_box / swing_trend 可选用；ema_swing 也可 |
| `D` | 日线 | swing_box 可选用；swing_trend / multi_factor 的 `trend_timeframe` |

> swing_trend 的 `scale: D_60` / `60_15` 只定大周期方向。回调看 `strategy.timeframe`，止损看 `trail_timeframe`。
> swing_box 同样跟这两格。没填时默认日线。

## 三、行情适配过滤（各策略自己的开关）

公共行情过滤已经拆掉。各策略自己决定拦不拦。

**对应底层逻辑：策略有明确的适用行情，行情不匹配直接停手。**

- **日内实体**：ADX 过高（强单边）不开。写在策略自己里，一直在。
- **海龟 / SuperTrend / 双均线 / 布林 / SAR / 长线**：各自配置框「本策略行情过滤」。ADX 太低或波动压缩不开新仓。默认关。
- **多因子两套**：各自 `cta_filter`。

## 四、盘前行情审计（session_audit，v9.41.0 起）

每次启动常驻 + 每天三次盘前（08:55 / 13:25 / 20:25）自动跑。

**不阻塞主循环**，独立线程执行，结果写运行日志。日志长这样：

```
=== 盘前行情适配审计 (2026-11-04 08:55) ===

--- bu2701 ---
  [OK   ] 日内实体   [R] ADX=18.3(震荡) ATR分位=55%
  [OK   ] 趋势跟随   [T] ADX=18.3(震荡) ATR分位=55%
  [BLOCK] SuperTrend ADX=18.3<20 没有趋势
  ...
  [SKIP ] 长线箱体突破  日线箱子和 ADX 写在策略里

--- rb2710 ---
  ...

汇总：6 项适配 / 3 项不适配 / 1 项跳过
建议：BLOCK 多的合约今天少看，SKIP 多的检查行情源是否通畅。
```

**这只是建议**，不会自动停单。自动停单由各策略自己的过滤在每根 K 线评估时直接拦。

覆盖各交易所合约。只有启用=是 的会进关注列表。从 18.2.0 起多两列：**交易时段**、**清仓时刻**。白银可写成 `09:00-11:30,13:30-15:00,21:00-02:30` 和 `14:55,02:25`。空着时白银/黄金默认收到凌晨 2:30，沥青等默认到 23:00。常驻只盯当前合约，用那一行。

## 七、完整实盘交易流程

### 第 1 步：配置（改 config.yaml）

```yaml
dry_run: false                        # 关掉！不然不会点真实下单

strategy:
  enabled: true
  engine: daily_body                  # 日内实体（默认，你当前就是这套）
  timeframe: '5'                       # 5 分钟 K 线
  trail_timeframe: '5'
  entry_mode: close                    # close=等收盘确认才开仓（保守，你当前就是 close）
  symbols: [fu2701, bu2701, c2701, ...]  # 关注哪些品种（你当前 14 个）
  flatten_at_close: true              # 到 14:55 / 22:55 自动清仓（你当前开着）
  flatten_times: ['14:55', '22:55']    # 收盘清仓钟点
  stop_mode: touch                     # touch=触及止损位立刻平（实时看影线）
  generic_stop:
    kind: 'off'                        # 独立止损关（只用策略自身止损，你当前就是 off）
  daily_body:                          # 日内实体专属参数
    eth_minutes: 15
    eth_minutes2: 30
    stop_extra_ticks: 1
    skip_gap_atr_mult: 2.5
    max_box_atr_mult: 5.0
    max_chase_atr_mult: 1.0
    day_cutoff: '10:45'
    night_cutoff: '22:30'
    filter_adx_upper: 30
    filter_atr_high_pct: 0.8

data:
  source: akshare                      # 行情源：akshare（新浪免费）/ tq（天勤，需账号）/ eastmoney（东方财富）
  cache_dir: data/klines
  min_bars: 80
  live_max_bars: 200
  max_stale_minutes: 90

trade:
  executor: gui                        # 点击同花顺（你当前就是 gui）
  gui:
    confirm_times: 0                   # 期货通无确认框，点完买卖就结束；打开了下单确认再改成 1 或 2
    assume_fill: true                  # 点击后立刻改内部持仓
    allow_multi_symbol: false          # GUI 模式禁止多品种同时挂机（必须 false）
    price_input:   [658, 1041]         # 你自己电脑的同花顺下单窗口坐标
    volume_input:   [507, 1042]
    buy_open_btn:   [386, 1123]
    sell_open_btn:  [550, 1125]
    close_btn:      [704, 1127]

risk:
  sizing_mode: risk_pct                # 每笔风险%算手数
  capital: 18526.11                    # 当前账户余额（实盘用真实值）
  risk_per_trade_pct: 10.0             # 每笔风险 10%；凯利打开时不用这项
  # 凯利公式：自己跑完历史回测，把胜率和盈亏比填进配置页，打开开关后按凯利算手数（默认一半，每笔最多 2%）
  max_daily_loss: 2000                 # 日亏损熔断
  max_orders_per_day: 5                # 每天最多开仓次数（你当前 5 次，防手滑）
  min_order_interval_sec: 60           # 两次开仓至少间隔 60 秒
  universe_table: config/品种与合约.xlsx  # 保证金表（关注列表、交叉测试用）
```

### 第 2 步：启动程序

```
python src\main.py
```

### 第 3 步：启动常驻

界面「运行」选项卡 → 点「启动常驻」。

程序按顺序做：

```
启动常驻
  ├─ 打开同花顺期货通
  ├─ 登录华泰期货账号
  ├─ 等待下单窗口出现
  ├─ 把价格框设成「对手价」
  ├─ 跑盘前行情审计（独立线程，不阻塞）
  ├─ CTP 通道：登录后做一次「柜台 ↔ 账本 ↔ 内存」三方对账
  │    └─ 有差异：冻结该品种、界面出横幅，等你在横幅上「认领 / 平掉 / 忽略」
  ├─ 上次带仓退出（data/unprotected_positions.json 还在）：先对账、评估止损，恢复前暂停报单
  ├─ 启动心跳看门狗（5 秒一轮）
  └─ 进入主循环：每 schedule.scan_interval_sec 秒扫描一次（默认 30）
       ├─ 交易日切换（夜盘 21:00 起算下一个交易日）
       ├─ 盘前审计定时触发
       ├─ 不在任何交易时段 → 跳过
       ├─ 检查 K 线是否过期（90 分钟内有效）
       ├─ 对当前选中的那一个品种（trade.symbol）：
       │    ├─ 拉最新 K 线
       │    ├─ 本策略行情过滤检查适不适合开仓
       │    ├─ 策略 evaluate：产生 HOLD/bu2701+BU_OPEN/bu2701+CLOSE 等决策
       │    ├─ 风控：计算手数（风险% × 余额，或凯利）
       │    ├─ 执行：点同花顺买开/卖开/平仓，或走 CTP 报单
       │    ├─ 记账：更新内部持仓 + 信号账户账本（成交回报加锁入账、按成交键去重）
       │    └─ 收盘清仓：到 14:55/22:55 按时钟平仓
```

### 第 4 步：日常使用

| 场景 | 操作 |
|---|---|
| 盘中看运行 | 运行页顶部看心跳、持仓、盈亏；日志窗口看每笔下单 |
| 策略发出 BUY_OPEN 信号 | 程序自动点同花顺「对手价 + 手数 + 买开」。能成交就成交，否则进委托单，不再按确认 |
| 到止损价 / 收盘清仓 | 程序自动点平仓按钮 |
| 想紧急停手 | 运行页点「暂停报单」（扫描还在，止损和收盘清仓仍发）；要结束常驻点「停止常驻」。同花顺里的仓去同花顺平；程序账用「手工单录入」→「平仓」 |
| 想加新合约 | 改 config.yaml strategy.symbols → 保存 → 重启常驻 |
| 临近交割月 | 程序会在交割月前一个月最后一个交易日的日盘收盘平仓，交割月不再开仓。请把关注品种改成下一手 |
| 想换策略 | 改 config.yaml strategy.engine → 保存 → 重启常驻 |
| 想看哪个合约现在适合开 | 交叉测试页跑一次，看结果表的「当下行情」列 |
| 想手动平某笔 | 先在同花顺平掉；再在运行页或账户分析点「手工单录入」→ 填成交价 →「平仓」（只改程序的账） |
| 想用期货通模拟盘测点单 | 账户分析换成「同花顺模拟账」，期货通打开「模拟交易」，再启动常驻。真实资金那本账不会被改 |
| 收盘后复盘 | 收盘复盘页 → 自动生成当日成绩单 + 缺陷诊断 |

## 七·A、CTP 上线与操作要点

四步上线，**一步都不能跳**。手工和策略只换「谁下单」，接口是同一套：

| 步骤 | 谁下单 | 用哪本账 | 目的 |
|---|---|---|---|
| ① 手工仿真 | 人在交易台点 | 华泰仿真 | 连通、认证、确认结算单、买开/卖开/平仓/反手/撤单全测一遍 |
| ② 手工真实 | 人在交易台点 | 华泰真实 | 用真实账号、真实前置再测一遍报单与回报 |
| ③ 策略仿真 | 程序自动 | 华泰仿真 | 策略接 CTP，验证信号 → 报单 → 回报 → 记账闭环 |
| ④ 策略真实 | 程序自动 | 华泰真实 | 小资金实盘，先跑一天 |

操作与风险要点：

1. **交易台只用于调试**：开平撤先在「CTP 柜台测试」窗口手工测完，再让策略接管；不要在常驻运行时反复点「连接登录」。
2. **常驻连上 CTP 后不要再点「连接登录」**：重复登录会把已有会话挤掉，报单回报会断。
3. **暂停报单只停开仓**：运行页「暂停报单」不拦止损和收盘清仓；要全停就「停止常驻」。
4. **交割月与节假日**：合约进交割月前一个交易日日盘收盘强平，之后不再开仓；长假前自己提前换月或清仓。程序按 `config/holidays.yaml` 与 `schedule.closed_days` 判断休市；日历缺下一年时实盘会禁止开仓，只保留止损和清仓。
5. **fail-closed**：登录未 ready、行情过期、对账有差异、账本写入失败时，一律禁止开新仓；这些是保护，不是故障。
6. **复盘是近似口径**：复盘用当天行情重放，假设当天开始空仓；真实成交以事件日志和柜台回报为准。
7. **回测流动性默认关闭**：`backtest.liquidity` 的一字板与成交量上限默认关，打开后结果会变，历史成绩不能直接对比。
8. **本地止损有边界**：见文末「本地止损的边界与看门狗」。断网、休眠、进程被杀期间没有柜台条件单，只能靠重启后的对账与补挂止损。

## 八、快速排错

| 现象 | 原因 | 查哪里 |
|---|---|---|
| 心跳在跳但不发单 | 策略自己的行情过滤拦了？持仓里已经有了？对账冻结？ | 日志「扫描解说」+ `session_audit` 报告 + 运行台横幅 |
| GUI 点错地方 | 坐标漂了 | 重新标定 `trade.gui` 下的像素坐标 |
| 没拿到 K 线 | 行情源过期 / 天勤没登录 | 运行页「测试工具」→「拉 K 线测试」 |
| 收盘没有自动清仓 | `strategy.flatten_at_close` 没开 / 收盘钟点过了但 GUI 点不到 | 检查 flatten_times |
| 启动后提示「柜台有仓、程序无仓」 | 上次崩溃或手工在柜台开过 | 横幅点「认领」或「平掉」；不想处理点「忽略」（保持冻结） |
| 一直显示「暂停报单」 | 看门狗发现扫描停滞，或上次带仓退出 | 看 `data/alerts.jsonl` 的 `heartbeat_stale` / `exit_with_positions`；确认行情与网络后重启常驻 |
| 重复成交回报 | 已由成交键去重拦住 | 若仍出现，查 `fill_lock_timeout` 事件并反馈 |

## 本地止损的边界与看门狗

- 止损由本进程自己算：进程被杀、断网、系统休眠时，程序不在，止损也就失去保护。
- 程序正常退出时若还有持仓/挂单，会写 `data/unprotected_positions.json` 留标记；
  下次启动先对账、评估止损，恢复前暂停报单，确认完成后自动清掉标记。
- 心跳看门狗每 5 秒检查一次，阈值 `max(3×扫描间隔, 180 秒)`；空仓或休市不判。
  扫描卡住超过阈值会暂停报单、风控熔断 `stale_heartbeat` 并写 `heartbeat_stale` 告警。
- 看门狗只在进程还活着时有效，整机掉电/系统休眠同样保不住持仓。
- 柜台原生条件单尚未接入（`CtpNativeStopAdapter.supported()` 恒为 False），
  现阶段只能靠本地止损 + 看门狗兜底。

### 节假日日历（44.12.0）

- 休市日写在 `config/holidays.yaml`，只写工作日的节假日，周末不用写；临时休市/调休仍写 `schedule.closed_days`。
- 每年国务院公布次年放假安排后，在文件里追加一年，重启程序即可，不用升级。
- 实盘（`trade.executor=ctp` 且 `dry_run=false`）启动时要求日历覆盖未来 60 天（`schedule.holiday_min_cover_days`）。缺年份时风控熔断 `holiday_calendar_missing`：**只禁止开仓**，止损与收盘清仓照常。
- 补上日历年重启后自动解除限制；回测与数据缺口说明也读这份日历，区间缺年份会在覆盖说明里提示「结果可能偏差」。

### 告警推到手机（44.12.0，飞书）

`runtime.alerts` 默认关闭，打开后只推 `error` 级告警（熔断、断线、对账差异、心跳停滞、守护平仓等）：

```yaml
runtime:
  alerts:
    external: "webhook"      # off | webhook
    min_level: "error"
    rate_limit_per_hour: 10  # 同一个 code 每小时最多几条
    webhook:
      kind: "feishu"
      url: "https://open.feishu.cn/open-apis/bot/v2/hook/..."  # 只存本地
      timeout_sec: 5
```

- 发送在后台线程，队列满了丢最旧，不会拖慢扫描；失败重试 1 次，仍失败只写本地 `notify_failed`。
- 本机不在线时收不到；告警仍完整写入 `data/alerts.jsonl`，运行台也能看到最近一条。
- 每条告警都带 `run_id`，和事件日志、状态文件对得上；运行台状态卡第二行显示它的后 6 位。

### 冷备守护（44.12.0，可选，默认关）

`tools/guardian.py` 是单独进程，用来处理「主程序被结束、但电脑和网络还正常」这一种情况：

```bash
python tools/guardian.py          # 先确认 runtime.guardian.enabled=true
python tools/guardian.py --once   # 只检查一次，看它怎么判断
```

只有下面五条同时满足才动手：程序账上有仓、心跳超过 `stale_after_sec`（默认 180 秒）、
主进程 PID 已不存在、当前在交易时段、`trade.ctp` 配置齐全。动作是独立连柜台、按对手价平仓，
最多每品种 3 次，并写 `data/guardian_actions.jsonl` 和 `guardian_flatten` 告警。

- 主进程还在、只是卡住：只发 `guardian_stale_main` 告警，**绝不连接**，否则同账号会把主进程踢下线。
- 同一 `run_id` 只平一次；守护自己重启也从动作记录里认出已经处理过。
- 下次启动主程序会先提示「上次由守护平过仓」，并照常走三方对账后才恢复报单。
- 边界：整机断电、休眠、网断时守护进程也不在，救不了；这些场景只能等券商侧条件单。

### 三方对账怎么处理

| 横幅内容 | 含义 | 怎么办 |
|---|---|---|
| 柜台有仓、程序无仓（未认领） | 崩溃/重连后柜台多出来的仓 | 点「认领」把它加进程序持仓，之后止损与清仓都会管它 |
| 柜台无仓、程序有仓（幽灵仓） | 程序记着但柜台已经平掉 | 连续两轮确认后自动补记；也可点「平掉」立刻清内存 |
| 柜台手数 ≠ 账本手数 | 手工单或漏记造成 | 点「平掉」按柜台实际手数重建，然后手工核对账本 |
| 点了「忽略」 | 只清待办，品种保持冻结 | 该品种不会自动开平，直到你重启或重新处理 |

对账差异存在期间，该品种只保留通用止损，不做反手、加仓与策略平仓；这是防止越差越远。

### 关窗口时会发生什么

有持仓或挂单时先弹确认；确认后停止后台线程并最多等 15 秒。超时再问一次，仍然关闭就写 `force_close` 告警并退出。取消关闭会恢复界面定时器，不需要重启程序。
