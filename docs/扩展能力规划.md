# 扩展能力规划（对照代码重构方案第六条）

当前程序版本 **44.13.0**。  
第六条写的是「以后可以做」，**现在都还没做完**。本文把五条拆开：每条要解决什么、现在差在哪、分几步、你会不会要重新理解开平仓。

**这份文档不是马上开工的清单。** 没改开平仓、没升版本。真要做某一条，需要你点头，并且按下面的「版本档」涨号。

对照总原则仍是重构方案第〇节：不超过六层；K 线快照只放原始 bars + 特征；传副本；「要不要做」在风控，「怎么做」在执行器。扩展时也不再拆更碎。

和蓝图的关系：[archive/系统蓝图.md](archive/系统蓝图.md) 讲的是「个人系统 vs 机构生产」。本文只展开重构方案第六条那五项，不另开第七条。

## 〇、建议做的顺序（先易后难）

| 顺序 | 条目 | 你现在已经有多少 | 做完后开平仓会不会变 | 建议档 |
|------|------|------------------|----------------------|--------|
| 1 | 仿真盘（把「模拟 / 仿真 / 实盘」说清楚、走同一套策略和风控） | 大半有 | 默认不变 | 功能更新 |
| 2 | 多因子：因子计算下沉到数据层 | 因子已在策略旁的文件里，还没进数据层 | 数字对得上就不该变 | 功能更新；对不上才是大更新 |
| 3 | CIS：一致性筛选 + 分仓进仓位管理器 | 没有 | **会变**（可能从「一个信号就开」变成「齐了才开、同板块打折」） | **大更新** |
| 4 | 多账户：网关多账户 + 路由分发 | 只能切换账本，一次一本 | 同时挂两本才会变谁在下单 | 功能更新（只切换）或大更新（并行） |
| 5 | 分布式：Redis/MQ、拆成多个进程 | 没有，也不该先做 | 本身不该改规则；做错会乱序 | 功能更新（基础设施）；乱序就是事故 |

**不要并行五条一起改。** 一次只做一条，做完用回测和交叉测试对照「同一段历史上开平仓是否还对得上」。

明确不做（除非你以后另写需求）：

- 不把工程改名叫 `trading_system/`
- 不为了 CIS 强迫所有旧策略立刻改成「完全不看持仓」（会改掉现在的开平仓）
- 不把日亏损熔断、暂停报单塞进 CIS（那是风控链的事）
- 不上 Redis，直到单机已经跑不动、并且仿真盘和多账户已经稳
- 不让 AI 或规律候选池自动改开仓公式

## 一、多因子：因子计算下沉到数据层，策略只做加权打分

### 1. 一句话

先把「均线、突破、动量这些数」算好，再让策略只做一件事：**把几个分数合成总分，过线才喊开/平。** 算因子的人换了算法，策略文件不用跟着改开仓 if。

### 2. 现在怎样

- 多因子已经能用：加权打分。
- 四个因子的计算写在 `src/strategy/cta_factors.py`，策略在 `evaluate` 里当场调用 `compute_factors`。
- 指标函数在 `src/strategy/indicators.py`，回测和实盘共用，但**还不是**「K 线来了先算特征、再随快照发给所有策略」。
- 规律候选页扫的是另一套因子清单，和实盘多因子不是同一条流水线。

也就是说：因子已经从「写死在开仓 if 里」拆出来了一点，但还停在策略包里，数据层不知道这些分数。

### 3. 做成什么样

```
行情 K 线（副本）
    → 数据层：ATR / 均线 / 突破距离 / SAR 等写入 features
    → 策略：只读 features，加权合成，输出「想开多/开空/平」
    → 仓位管理器：手数
    → 风控链：拦不拦
    → 执行器：怎么下
```

策略不再自己从原始高低开收重算那一套因子。`BarSnapshot.features` 就是给策略看的字典，不往里面塞扫描临时变量。

### 4. 分步

| 步 | 做什么 | 验收 | 版本 |
|----|--------|------|------|
| A | 把 `compute_factors` 的输入输出写成固定字段（合约、周期、各因子分、缺失标记），用现在多因子回测样例做对照表 | 同一段 K 线，新函数和旧函数分数完全一样 | 不升版本也可，只是搬家准备 |
| B | 扫描和回测拉完 K 线后先算 features，再 `evaluate`；策略若拿不到某个因子就 HOLD，不编造 | 日内实体、均线等**不读这些因子**的策略，开平仓与搬家前一致 | 功能更新 |
| C | 多因子策略改为只读 features；加权合成仍在策略里（合成规则是驾驶员，不是数据） | 多因子历史回测与搬家前逐笔对照 | 分数一致：功能更新；不一致：停下来修，不能当小更新蒙混 |
| D（可选） | 规律候选扫描改用同一套因子函数，避免「研究一套、实盘一套」 | 候选池说明书里写清用的是哪套因子 | 功能更新，仍不下单 |

### 5. 踩坑

- 不要为每个因子建一个类。四个因子一个计算器够了。
- 不要把「过阈值才开」也下沉到数据层。那是策略。
- 不要让两个策略抢着改同一份 K 线表，必须用副本。

### 6. 你怎么验收（不会代码也可以）

选一个你熟悉的合约和日期，搬家前后各跑一次历史回测：笔数、开平时间、方向必须对得上。对不上就回退，不算完成。

## 二、CIS 模式：一致性筛选和分仓放进仓位管理器

### 1. 一句话

**策略只举手**（我想做多沥青）。  
**仓位管理器再问两句**：好几路意见是不是一边倒？钱会不会全砸在同一个板块上？  
意见不齐或盘子已经挤了，就少开或不开。这两句不要写进某个策略文件。

详细白话见对话里对 CIS 的说明；这里写成可施工的规则草案。

### 2. 现在怎样

- 一次常驻基本盯**一个**关注合约、**一套**策略。
- 手数：每笔风险% 和仓位上限% 取小（`src/risk/sizing.py`），再叠加回撤/波动动态减仓。
- 多因子的「几票才开、打分开几成」还在策略里。
- 长线「单元手数 × 加仓次数」还在策略里。
- **没有**「螺纹和热卷算同一组、整组风险当成一笔」这种分仓。

### 3. 做成什么样

仓位管理器增加两层，**插在策略信号之后、风控链之前**：

1. **一致性筛选（做不做、给几成「资格」）**  
   - 周期一致：例如信号周期和日线方向同向才给满资格。  
   - 因子/总分一致：应改成把「总分」当作信号附带的强度，由管理器决定资格，而不是策略自己把手数写成 0.5。  
   - 板块一致（多品种以后才有意义）：同板块多数合约同向，才给该板块额度。

2. **分仓（资格通过后，钱怎么切）**  
   - 单品种上限：例如单合约不超过账户风险预算的 X%。  
   - 板块上限：高度相关的合约共用一个篮子（例如黑色：螺纹/热卷/铁矿）。  
   - 分批：允许「先 1/3，走对再补」，三批加起来的风险等于原来一笔，不是越加越猛。  
   - 已有持仓占用篮子后，新信号只能吃剩余额度。

风控链仍然管：暂停报单、记账失败、同一根 K 线重复开、日亏损熔断、柜台对账。CIS **不代替**这些闸门。

执行器仍然管：反手先平再开、点同花顺还是发 CTP。CIS **不组报单**。

### 4. 必须你先拍板的数字（不做猜的）

落地前要写成配置，不要写死在代码里。建议默认先**全关**，打开才走 CIS：

| 项 | 建议讨论的默认 | 关掉时 |
|----|----------------|--------|
| 是否启用 CIS | 关 | 和现在 44.12.0 完全一样 |
| 周期一致 | 要信号和日线同向 | 不看日线 |
| 最少同向票数 | 2（仅多因子有票时） | 不看票 |
| 板块表 | 先只做你在用的：沥青单独一组；玉米单独一组 | 每合约独立 |
| 单品种风险上限 | 等于现在的每笔风险% | 只用现在的 sizing |
| 板块风险上限 | 等于单品种上限（避免同主题加倍） | 不合并 |
| 分批 | 关（一次开满资格手数） | 一次开完 |

**打开 CIS 一定是大更新**：同一根 K 线可能从「开」变成「不开」或「少开」。旧回测不能直接当新规则的成绩。

### 5. 分步

| 步 | 做什么 | 验收 |
|----|--------|------|
| A | 只加开关和日志：算出「若按 CIS 会给几成仓」，**不下单、不改手数** | 运行台能看见「资格 0/0.5/1、原因」；实际成交与关 CIS 时相同 |
| B | 开关打开后，资格乘数乘在现有 sizing 后面（仍取小，不能放大超过风控手数） | 关 CIS 与现在一致；开 CIS 后手数只少不多 |
| C | 多品种时才做板块篮子；同花顺一次盯一个合约时，板块篮意义不大，可推迟 | 两个相关品种同时喊开，整组手数不超过篮子 |
| D | 长线加减仓的「单元×次数」迁到管理器的分批规则；策略只发加仓/减仓意图 | 长线开关关着时，日内策略不受影响 |

### 6. 踩坑

- 不要在策略里再读 `self.pos` 来决定「已经有仓就不一致」。持仓以管理器为准。迁的时候必须对照回测，不能为了「纯洁」先改掉现在能开的那些 K 线。
- 不要把一致性写成 10 个过滤器类。周期 / 票数 / 板块 三格够了。
- 分仓不是「每个策略自己再开一手」。两个策略同时举手，管理器只看到一个目标仓位。
- 交叉测试今天按固定手数、不看权益。CIS 的回测要另开「按风险预算」模式，不能 silently 改交叉测试的筛选公平性。

### 7. 和「第四期组合」的关系

README 里写过：组合（多策略同时、按权重配）现在做不到。CIS 的板块分仓是组合的**前一阶**：还是同一类趋势信号，只是别在亲戚品种上加杠杆。真正的多策略组合（趋势 + 套利各一半）比 CIS 更晚，本文不展开。

## 三、多账户：网关支持多账户，路由分发订单

### 1. 一句话

现在是「左边换一本账，整台机器只给这一本干活」。  
目标可以分两档：先把账本和通道配对理顺；只有你真的要**两本账同时挂机**，才做路由分发。

### 2. 现在怎样

- 账户分析有四本账：同花顺实盘、同花顺模拟、华泰仿真、华泰真实。点单账和 CTP 账已经分开，资金账号相同也不混记。
- 常驻一次只用当前选中的账 + 当前 `trade.executor`（sim / gui / ctp）。
- 没有「这一单发给华泰仿真、那一单点同花顺」的路由器。
- 同花顺一次只盯一个合约（点击通道的物理限制）。

### 3. 做成什么样（两档）

**档 A — 账户与通道绑定（建议先做）**

- 每本账记住自己的执行通道、资金账号、持仓文件、事件日志。
- 切换账时自动带上对应通道，避免「看着是华泰账、实际还在点同花顺」。
- 仍一次只跑一本。开平仓规则不变。

**档 B — 真正的多账户路由（更晚）**

- 路由器：信号带上 `account_id`，发到该账绑定的网关。
- 风控按账隔离：华泰仿真亏到熔断，不影响同花顺模拟。
- 禁止：同一策略、同一合约、两本账各开一笔却共用一个止损脑子（除非你明确要影子盘对照）。

影子盘（仿真跟实盘同一信号、仿真先走）可以放在档 B，但默认**仿真成交不写进实盘账**。

### 4. 分步

| 步 | 档 | 验收 | 版本 |
|----|----|------|------|
| A1 | A | 四本账各自通道、权益、持仓文件列在一张表里，切换账不串文件 | 功能更新 |
| A2 | A | 华泰账不能选 gui 点单当主通道（或强提示）；同花顺账不能拿 CTP 资金改权益 | 功能更新 |
| B1 | B | 仅「影子」：同一信号先在仿真落一份记录，实盘仍只下一份单 | 功能更新（实盘开平仓不变） |
| B2 | B | 两本账同时报单 | **大更新**（你要重新理解「谁在下单」）；同花顺通道原则上不做双账户点击 |

### 5. 踩坑

- 路由是执行层的事，不要让策略知道账号密码、前置地址。
- 不要用全局「当前权益」一个数字给两本账算手数。
- GUI 点击通道做不到真正的双账户并行，不要假装能做。
- CTP 一进程连两个资金账号要先问华泰是否允许；不允许就两个进程，那已经碰到第五条分布式，不要提前挖坑。

## 四、仿真盘：切换仿真网关，和实盘同一套策略、风控

### 1. 一句话

换「假柜台 / 真柜台」，**不要换开平仓公式**。用来验证策略和风控，而不是另写一套「模拟专用逻辑」。

### 2. 现在怎样（已经最接近第六条）

| 名字 | 实际是什么 | 和实盘同一套策略吗 |
|------|------------|-------------------|
| `sim` | 程序内存里假装成交 | 是，但不经过期货公司 |
| `gui` + 模拟账 | 点同花顺模拟 | 是，但是点击成功 ≠ 成交 |
| `ctp` + 华泰仿真 | 主席仿真前置（如 28077） | 是，报单回报和对账走柜台 |
| `ctp` + 华泰真实 | 实盘前置 | 真钱 |
| 历史回测 | 用本地 K 线重放 | 策略同一套；撮合是回测引擎，不是柜台 |

上线四步已经写在 [archive/CTP上线流程.md](archive/CTP上线流程.md)（要点见 [实盘交易简易说明书.md](实盘交易简易说明书.md) 第七·A 节）：手工仿真 → 手工真实 → 策略仿真 → 策略真实。接口按设计是同一套 `CtpTrader`。

缺口主要是**概念和隔离**，不是再造一个网关类：

- 界面上「模拟 / 仿真 / 回测」三个词容易混。
- `sim` 内存撮合和华泰仿真不是同一个东西，不能拿 `sim` 的成绩当仿真盘过关。
- 回测引擎和常驻扫描仍是两条路，虽然策略文件相同；成交假设（收盘确认、下一根开盘）和仿真柜台的排队、部分成交不一样。

### 3. 做成什么样

三个环境标记，写在配置里，策略代码零分支：

| 环境 | 行情 | 交易 | 钱 |
|------|------|------|-----|
| backtest | 本地 K 线回放 | 回测撮合 | 虚拟 |
| simulation | 真实行情（或仿真行情） | 华泰仿真 CTP，或明确标注的 `sim` | 假钱 |
| real | 真实行情 | 华泰真实或同花顺实盘点击 | 真钱 |

规则：

- 策略、仓位公式、风控链、CIS（若已做）只认环境和账户注入进来的适配器。
- 禁止 `if 仿真: 少开一手` 这种写在策略里的分支。
- 仿真过关标准要写死：例如连续 N 个交易日无错单、持仓与柜台对得上、日亏损熔断能被手动触发一次。过关才能点策略真实。现有四步已经有「不许跳步」；本条是把「过关」写清楚。

### 4. 分步

| 步 | 做什么 | 验收 | 版本 |
|----|--------|------|------|
| A | 运行页用白话标明当前是：程序模拟 / 华泰仿真 / 同花顺点击 / 华泰真实 | 不会把 `sim` 显示成「已在期货公司仿真」 | 小更新或功能更新（只改字） |
| B | 仿真与真实的风控参数允许**同一份**；若你要仿真先用更小手数，用账户权益或「手数上限」配，不改策略 | 换通道后回测/扫描决策一致 | 功能更新 |
| C | `sim` 撮合尽量靠近回测规则（滑点跳数、手续费），并在日志写「非柜台」 | 同一段历史，`sim` 扫描与回测不必逐笔相同（一个用实时K、一个用全历史），但计费字段要有 | 功能更新 |
| D | 策略仿真阶段的检查单写进上线流程：对账、熔断、撤单、反手平仓各测一次 | 未勾完不能进策略真实（已有跳步拦截则补检查单） | 功能更新 |

### 5. 踩坑

- 不要为仿真再写一个 `SimDailyBodyStrategy`。
- 不要用回测曲线代替仿真盘过关。
- 华泰仿真成交质量 ≠ 真实盘口流动性；过关只证明程序没接错，不证明以后能赚钱。

## 五、分布式：事件总线改成消息队列，拆成多个进程

### 1. 一句话

把「拉行情、算策略、下单」拆到不同电脑或不同进程，中间用 Redis 或消息队列传事件。  
这是给**机构生产**或「一台机器已经转不动」准备的，不是挂机沥青/玉米的下一步。

### 2. 现在怎样

- `src/kernel/events.py` 是**进程内同步总线**：谁发布，订阅者马上按顺序处理。
- 常驻、界面、回测在同一套程序里。
- 这样时序简单：这根 K 线的信号一定在下一根之前处理完。回测也对得上。

### 3. 什么时候才需要

同时满足再考虑：

- 关注合约很多，单机拉 K + 算因子已经经常赶上不上下一根；
- 多账户档 B 已经要跑，且期货公司要求进程隔离；
- 你接受运维成本：队列挂了、时钟不同步、消息重复。

否则做了只会更难查「为什么这根没开」。

### 4. 若做，目标形态（仍不超过六层）

进程可以拆，**层不要拆**：

| 进程 | 对应层 | 发出的事件 |
|------|--------|------------|
| 行情服务 | 数据层 | K 线快照（副本）、features |
| 策略服务 | 策略层 | 信号 |
| 风控+仓位服务 | 仓位 + 风控 | 通过或拦截 |
| 执行服务 | 执行 + 网关 | 报单、成交 |

总线仍是那些事件名：`bar` / `signal` / `order_request` / `risk_block` / `trade`。换运输工具（内存 → Redis），不换报文。

硬性约束：

- **同一合约必须单线程顺序处理**，禁止同一品种两消费者抢消息（否则重复开仓或乱序平仓）。
- 每条消息带 `bar_id` + `account_id`，消费者幂等：处理过的 bar 不再开第二次。
- 回测继续用进程内同步总线，不用 Redis。回测和实盘策略代码相同，运输层不同。
- 时钟以交易所时间为准，不用各进程自己的「现在」。

### 5. 分步（很晚才走）

| 步 | 做什么 | 验收 |
|----|--------|------|
| A | 只打日志：每个事件进入/离开总线的时间，仍同步 | 不影响下单 |
| B | 本地 Redis，但策略+执行仍同一进程消费（等于把总线换皮） | 断 Redis 时拒绝开新仓，不瞎发 |
| C | 行情进程独立；策略仍与执行在一起 | 行情挂了只告警停开，持仓平仓通道还在 |
| D | 执行独立进程 | 杀策略进程时，执行进程仍能收到「暂停报单」；要有人工总闸 |

### 6. 踩坑

- 异步队列最容易把「先平再开」打乱。反手必须在**同一个执行消费者**里做完。
- 不要把 EventBus 再拆成 TickBus、BarBus、UiBus 三个框架。
- 不要在未做仿真盘过关之前上分布式。问题会分不清是策略错还是消息丢了。

## 六、依赖关系（一张图）

```
仿真盘说清楚、过关检查单
        ↓
多因子计算下沉（开平仓数字必须对上）
        ↓
CIS 开关默认关 → 只日志 → 打开后手数只少不多（大更新）
        ↓
多账户档 A（账和通道绑定）
        ↓
多账户档 B / 影子盘（可选）
        ↓
分布式（仅机器不够或监管要求进程隔离时）
```

CIS 不依赖多账户；但板块分仓要等「一次盯多个合约」才有意义。同花顺点击通道长期不适合多合约 CIS。

多因子下沉不依赖 CIS。先搬家再让 CIS 读 features 里的票数/总分，比先做 CIS 更干净。

## 七、和当前分层怎么接（不新开第七层）

| 扩展 | 落在现有哪一层 | 不放哪里 |
|------|----------------|----------|
| 因子计算 | 数据层 → `BarSnapshot.features` | 不放执行器、不放风控 |
| 加权合成 | 策略层 | 不放下沉到数据层 |
| CIS 一致性、分仓 | 仓位管理器（策略之后、风控之前） | 不放策略文件、不放执行器 |
| 多账户路由 | 执行层 | 不放策略 |
| 仿真/实盘切换 | 配置 + 网关适配器 | 不在策略里 `if 仿真` |
| Redis | 只替换事件运输 | 不替换风控规则、不改 DTO 字段含义 |

## 八、你怎么决定「下一步做哪一条」

按你的真实痛点选，不要按「听起来高级」选：

- 经常分不清现在是假钱还是真钱、仿真能不能当过关 → **先做第四条仿真盘**。
- 想加第五个因子、又怕改四个策略文件 → **先做第一条多因子下沉**。
- 已经或多或少同时看沥青和玉米、怕两个趋势单其实是同一笔风险 → **再谈 CIS，而且要先填第七节那张数字表**。
- 华泰一本、同花顺一本要同时挂 → **多账户**；只是切来切去看账 → 档 A 就够。
- 程序还在一台电脑上跑得动 → **不要做分布式**。

选定一条之后，再单独开施工说明（改哪些界面、哪些测试必须绿、版本怎么涨）。没有你点头，不改开平仓代码。
