# 交易通道通用化升级方案（GUI / CTP）

状态：**P1（CTP 券商档案）、P2（能力标志与调度解耦）已实施**；P3–P5 待开工。旧配置不改仍可运行，行为与升级前一致。
适用范围：执行通道 `trade.executor = gui | ctp`（`sim` 不受影响）。
相关文档：[配置说明书.md](配置说明书.md)、[扩展能力规划.md](扩展能力规划.md)（其第三节「多账户」、第四节「仿真盘」与本方案同向，开工时口径合并）。

---

## 〇、一句话

把「同花顺 + 华泰」从代码里的默认值，改成**可配置的通道档案**：

- **CTP**：期货公司差异（前置、BrokerID、AppID、认证码、平今品种）全部进 `trade.ctp_profiles`，换券商只加一段配置。
- **GUI**：把「窗口标题、进程名、菜单名、价格选项、坐标」收进 `trade.gui_profiles`，把「谁来点」收进供应商包（provider），核心下单流程不再出现软件名。
- **调度层**：不再判断 `executor == "ctp"`，改判通道能力（能不能查持仓、能不能确认成交）。

不变的东西：下单语义（买开/卖开/平仓）、风控链、账本文件名、坐标点击的既有行为。

## 一、必要性与边界

### 1. 为什么做

| 场景 | 现在要改什么 | 做完后 |
|---|---|---|
| 换期货公司（如华泰 → 中信建投/国君） | 改代码里的前置判断、端口配对、平今品种、多处文案 | 只加一段 `ctp_profiles` |
| 加一家仿真环境（SimNow / openctp） | 改 `trade.ctp.sim` 与代码默认值 | 加一份档案，`ctp_profile` 切换 |
| 同花顺升级改了窗口标题/菜单/价格下拉 | 改 `ths_login.py`、`price_mode.py` 里的字符串常量 | 改配置里的 `gui_profiles` |
| 换 GUI 软件（文华/博易/无限易） | 几乎重写登录与点击 | 新增一个 provider 文件 + 一段配置 |
| 新增通道类型（如带本地 API 的交易软件） | 改 `risk_chain`、`order_executor` 的厂商分支 | 只声明能力，不改调度 |

### 2. 必须承认的上限

- **GUI 点击无法做到「零代码换软件」**。不同软件的登录流程、结算单确认、价格输入语义、下单面板结构都不同。本方案的目标是：**通用骨架 + 每家一个供应商包**，把易碎部分圈进独立文件，而不是做一个万能 UI 驱动。
- **GUI 通道永远是 `assumed_fill`**（点击成功 ≠ 成交）。任何抽象都不能让它看起来能确认成交。
- **不做**：通用登录引擎、跨软件控件识别、GUI 双账户并行点击、把券商外接测试流程（`ctp_probe`）做成插件系统。

## 三、目标架构

### 1. 分层

```
策略 / 风控 / 调度
      │  只看能力（Capabilities），不看厂商名
      ▼
TraderBase（现有）＋ Capabilities（新增）
      │
      ├── SimTrader（不变）
      ├── CtpTrader ── CtpGateway ── BrokerProfile（券商档案）
      └── GuiTrader ── GuiAdapter ── 供应商包
                           ├── common.py   串行锁 / 鼠标锁定 / 窗口钉住 / 结果语义
                           ├── ths.py      同花顺：登录、结算单、价格下拉
                           └── generic.py  纯坐标模板（新软件起步用）
```

### 2. 能力标志

```python
@dataclass(frozen=True)
class Capabilities:
    can_query_positions: bool   # CTP=True，GUI=False
    can_query_orders: bool      # CTP=True，GUI=False
    confirms_fill: bool         # CTP=True，GUI=False → 上层按 assumed_fill 记账
    supports_symbol_switch: bool
    supports_price_mode: bool
    supports_cancel: bool
```

- `TraderBase` 增加只读属性 `capabilities`，`SimTrader/GuiTrader/CtpTrader` 各自声明。
- 调度层把厂商名分支替换为能力判断：
  - `executor == "ctp"` → `caps.confirms_fill` / `caps.can_query_positions`
  - `executor == "gui"` 且 `assumed_fill` → `not caps.confirms_fill`
- 判断通道是否支持「改价重报、查委托、撤单」时，一律查能力，不再查名字。

### 3. GUI 供应商包接口（最小集）

```python
class GuiAdapter(Protocol):
    provider: str
    capabilities: Capabilities

    def ensure_ready(self) -> tuple[bool, str]: ...      # 启动、激活、登录、结算单
    def ensure_symbol(self, symbol: str) -> bool: ...    # 可选；不支持时由能力标志关闭
    def ensure_price_mode(self, mode: str) -> bool: ...  # opponent / last / limit
    def write_price(self, text: str) -> bool: ...        # 仅限价模式使用
    def write_volume(self, volume: int) -> bool: ...
    def click_side(self, side: str) -> None: ...         # buy_open / sell_open / close
    def dismiss_confirm(self) -> None: ...
    def read_price(self) -> str | None: ...
```

`GuiTrader` 只保留编排：加锁 → `ensure_ready` → 合约 → 价格 → 手数 → `click_side` → 确认框 → 收尾 → 返回 `OrderResult`。现有同花顺实现整体搬进 `ths.py`，**逻辑不改**。

字段规则：

| 字段 | 规则 |
|---|---|
| `kind` | `live` 时若 `user_id` 为空，取 `account.user_id`（现有「资金账号只填一次」的规则不变） |
| `password_env` | 环境变量名；读不到再查 `secrets.local.yaml` 对应键。默认保持 `CTP_PASSWORD / CTP_LIVE_PASSWORD` |
| `auth_code_env` | 为空表示该柜台不需要认证码 |
| `md_front` | 必填或留空；**禁止**再按端口猜行情前置 |
| `close_split_products` | 缺省 `["bu","c"]`；上期所/能源中心/大商所仍由代码按交易所自动拆 |
| 其余 | 与现有 `trade.ctp` 同名同义，默认值不变 |

档案校验（新增，仅提示不阻断）：`kind=live` 但前置为空、`broker_id` 为空、`td_front` 与 `md_front` 完全相同、`auth_code_env` 指向的环境变量缺失。

## 五、迁移步骤

### 1. 迁移原则

1. **旧配置不改也能跑，行为与升级前一致。** 加载时若没有 `ctp_profiles / gui_profiles`，由加载器按旧键生成 `default` 档案。
2. **只迁移，不静默改写磁盘。** 首次加载不写回；用户在配置页点「保存」时才落新格式。
3. **旧键保留一个版本周期。** 新代码优先读新键，缺新键读旧键并记一条 info 日志；旧版本程序读到新键只会告警「未知键」，仍可启动，便于回滚。
4. **数据文件与内部 id 不动。** 见第 3 条。

### 2. 配置字段对照

| 旧键 | 新键 | 说明 |
|---|---|---|
| `trade.ctp.account_kind` | `trade.ctp_profile` 所指档案的 `kind` | 由档案决定，不再单独切换 |
| `trade.ctp.td_front / md_front / broker_id / user_id` | 档案同名字段 | sim 取 sim 档案，live 取 live 档案 |
| `trade.ctp.sim.*`、`trade.ctp.live.*` | 拆成两份独立档案 | 一份档案一个账号，不再嵌套 |
| `trade.ctp.app_id / auth_code_env / flow_dir / price_tick / max_order_volume / order_wait_sec / query_interval_sec / login_timeout_sec / order_count_warn / cancel_count_warn / auto_cancel_on_timeout / cancel_wait_sec / close_split_products` | 档案同名字段 | 允许在 `trade.ctp` 写公共默认值，档案覆盖 |
| `account.user_id` | **保留** | live 档案 `user_id` 留空时自动取用 |
| `app.path / window_title / startup_wait_sec` | `gui_profiles.<provider>.app.*` | 旧键仍可读，仅当没有 gui_profiles 时生效 |
| `trade.gui.price_input / volume_input / buy_open_btn / sell_open_btn / close_btn / confirm_btn / symbol_input` | `gui_profiles.<provider>.coords.*` | 坐标值原样搬运 |
| `trade.gui.confirm_mode / confirm_delay_sec / confirm_times / assume_fill / allow_multi_symbol` | `gui_profiles.<provider>.order.*` | 语义不变 |
| `account.broker / account.channel` | **保留** | 仅用于界面显示，不参与点击逻辑 |

### 3. 数据文件与内部 id（不得改动）

| 项 | 现状 | 要求 |
|---|---|---|
| 账本 id | `live / paper / ctp_sim / ctp_live` | 不改。只允许改 `PROFILES[*]["label"]` 显示名 |
| 账本文件 | `data/signal_account*.json` | 不改文件名 |
| 当前账 | `data/active_account.json` | 不改结构 |
| 委托意图 | `data/intents/<id>/` | 不改目录 |
| CTP 流文件 | `data/ctp_flow/` | 不改路径；档案里可覆盖 |
| 账本别名识别 | `normalize_id` | 新增「GUI实盘 / CTP仿真」等中性别名，**旧别名继续识别** |

### 4. 用户迁移操作（升级后照做）

1. 备份 `config/config.yaml`、`config/secrets.local.yaml`、`data/`。
2. 升级程序，直接用旧配置启动一次：确认日志里能正常创建/加载通道，`dry_run: true` 下走一遍 GUI 模拟点击。
3. 打开配置页 → 交易通道：程序提示「检测到旧配置，可一键生成档案」，或手工把第四节的 YAML 粘进 `config/config.yaml`。
4. 核对生成结果：
   - CTP 档案的 `td_front / md_front / broker_id / user_id` 与旧值一致；
   - GUI 档案的 `coords` 与旧 `trade.gui` 逐项一致；
   - `account.user_id` 未变。
5. 用 `ctp_profile` / `gui_provider` 切换到目标档案，保存。
6. 验证：
   - 交易台登录 CTP，`查持仓 / 查委托` 正常；
   - GUI 通道在 `dry_run: true` 下日志显示 `provider=ths_futures profile=ths_futures`，点击流程与升级前一致。
7. 需要回滚时：把 `ctp_profile / gui_provider` 删掉即可回到旧行为；旧版本程序忽略新键照常启动。
