# 因子挖掘模块升级实施方案

- 日期：2026-11-22（决策确认：2026-11-23）
- 适用代码：50.1.0 之后的 `src/research` 与「策略研究 → 因子挖掘」页（50.4.0 起由「规律候选」改名）
- 定位：研究层方案。**不下单、不自动换策略、不改实盘开平仓**
- 状态：8 项决策已确认（见第 14 节），第 0~4 阶段已按 50.4.0~50.8.0 落地；改名放在第 0 阶段

## 0. 结论摘要

1. **现状不是「因子挖掘」，更像「规律初筛」**：只有 11 个价量因子、7 个预置双因子组合、3 档未来收益；检验只有「两半显著 + 4 段同向 + 跨品种」。
2. **改名本身很简单**，难的是把研究口径补成两条完整流水线：
   - 流水线 A（目标 1）：寻找能预测未来收益的因子；
   - 流水线 B（目标 2）：识别市场状态，输出「状态 × 因子 × 策略」匹配清单。
3. **最大的硬阻塞是持仓量（OI）数据**：本地 K 线库 `data/klines/market.sqlite` 共 926,462 根，`oi` 非空为 **0 根**。不修数据层，持仓量因子一条都跑不了。tick 库有 228,852 条且都带 `open_interest`，可作为短周期补算来源。
4. **已有检验不重复造**：两半显著、4 段同向、跨品种、三分位差、Spearman、类型倾向、运行清单全部复用；新增的是 IC 序列/ICIR、互信息、Hurst、分层单调性、置换检验、BH-FDR、因子 WFA、共线性/增量、状态聚类与状态条件表。
5. **依赖策略已拍板：引入 scikit-learn**（见第 14 节）。KMeans、后续 GMM/树模型直接用 sklearn；直方图互信息、R/S Hurst、BH-FDR 仍用 numpy/pandas，保证可复现。代价是包更大，需要同步 `requirements.txt` 和打包说明。
6. **对资料中的两处做法做修正**：资料里的「直接打乱未来收益」在重叠标签下会高估显著性，改为**分块置换**；资料里的 WFA 示例是滚动固定窗，本项目策略 WFA 是扩张窗，两者分开，不混用口径。
7. **数据就绪要前置**：因子挖掘先定义门槛（快速 600 / 标准 1000 / 严格 1500 根可用 K 线，OI ≥90%，≥2 个合约），数据管理按同一口径算缺口、自动补齐、断点续传；满足后在因子挖掘页亮绿灯，不满足红灯禁用开始、黄灯只跑价量。
8. **下载不需要带宽限速**：历史 K 线和实时 tick 都很小；唯一重的是历史 tick（每合约每天 10~30 MB），用「非交易时段 + 1 并发 + 分块暂停」控制。真正要防的是天勤连接额度和 SQLite 写锁，不是网速。

### 1.4 数据硬缺口：持仓量

实测（2026-11-22）：

```
data/klines/market.sqlite
  bars 总数 926,462；oi 非空 0
  按周期：1 分钟 15,094 / 5 分钟 468,075 / 15 分钟 275,208 /
          30 分钟 97,502 / 60 分钟 57,179 / 日线 13,404，全部 oi=0

data/ticks/vnpy_data.db
  dbtickdata 228,852 条；open_interest 非空 228,852
```

原因链：

1. 新浪 K 线 [kline.py](../../src/data/kline.py#L1150) 把 `p` 列改名成 `hold`，而 [periods.py](../../src/data/periods.py#L29-L69) 的 `canonicalize_ohlc` 只保留 `oi`，于是 `hold` 被丢掉。
2. 天勤 [tq_source.py](../../src/data/tq_source.py#L336-L379) 的 `frame_from_klines` 只取开高低收量，没有取 `open_oi/close_oi`。
3. tick 合成的 K 线在 [periods.py](../../src/data/periods.py#L382-L386) 里会保留 `oi`，但只覆盖有 tick 的短区间。
4. 本地库与 [bar_store.py](../../src/data/bar_store.py) 本身支持 `oi`，缺的是上游写入。

**结论：持仓量研究必须先做数据层修复和回补；不能用 0 填充，也不能用成交量冒充持仓量。**

另一个正确性问题：**持仓量和成交量都是合约级的**。主力连续在换月点会跳变。OI 研究只能在「单一具体合约」上做，或按合约分段；不能直接在拼好的主连上算 OI 变化。界面要加护栏。

## 2. 目标、边界与总流水线

### 2.1 两条流水线

```
流水线 A：因子筛选
  K线/研究快照
    → 数据门（根数、缺口、OI 覆盖、合约级）
    → 因子面板（价格 / 成交量 / 持仓量，封闭目录）
    → 标签（未来 h 根收益 / 波动归一化收益 / 趋势延续）
    → 描述统计 + 半衰期
    → 已有稳定性门（两半、4段、跨品种）
    → Rank IC + ICIR
    → 互信息 MI
    → 分层单调性
    → 分块置换检验
    → BH-FDR
    → 因子 WFA（滚动样本外）
    → 共线性/增量
    → 结论与报告
    → 候选池（只勾选，不下单）

流水线 B：状态识别与策略匹配
  同一份因子面板
    → 状态特征集（ADX/ATR分位/波动/Hurst/自相关/量仓）
    → 只用样本内拟合标准化 + KMeans
    → 样本外按最近中心归类（不重拟合）
    → 状态画像、命名、样本占比、转移矩阵
    → 状态 × 因子有效性表
    → 状态 × 策略清单（复用类型倾向）
    → 研究报告（只给清单，不自动切策略）
```

### 2.2 边界（沿用仓库现有原则）

- 不自动下单；不自动改实盘策略；不自动改多因子权重。
- 不做无约束全市场乱挖；因子目录必须封闭且每条写清经济学逻辑。
- 不用未来函数；标签 `shift(-h)` 只用于研究，不进实盘策略。
- 不与「交叉测试 / 策略优化」抢活：因子挖掘只给候选和状态清单，策略回测仍由现有页面跑。
- 第一期不引入机器学习树模型/Lasso；先把统计检验做扎实。ML 作为后续可选，不列入本轮。

回补策略：

1. 优先用天勤重新下载历史分钟/日线（有 `open_oi/close_oi`）。
2. 新浪能补的区间用新浪（`p` 映射后）。
3. 只有 tick 的区间，用 tick 合成 1/5/15 分钟，作为交叉核对，不冒充长历史。
4. **不回填、不插值**。缺失就是缺失，报告里写明覆盖比例。

### 4.2 合约级护栏

- OI/成交量因子只允许在「具体合约」上跑。
- 如果用户选的是主力连续/拼接主连：
  - 关闭 OI 因子组，提示「换月会跳变，请选具体合约」；
  - 或在换月点前后各留缓冲，按合约分段跑，再汇总。
- 价格类因子可以继续在主连上跑；报告里标注「价格=主连，量仓=不参与」。

| 形成中 K 线 | 继续用 `drop_forming_bar` | 保留现有行为 |

### 4.4 标签与预处理

- 未来收益：`fwd_h = close[t+h]/close[t] - 1`，`h ∈ {1,3,6,12,24}`，默认 3/6/12。
- 波动归一化标签（新增，可选）：`fwd_h / ATR_t`，降低高波动段的异方差影响。
- 趋势延续标签（新增，可选）：`sign(fwd_h) == sign(close[t]/close[t-h]-1)`，用于「状态/策略匹配」，不用于收益预测。
- 因子缩尾：评估前对因子做 1%/99% winsorize；不改变因子原始定义。
- 标准化：只用于聚类和组合打分；**只用样本内拟合均值/标准差**，样本外直接套用。
- 所有因子只用 `t` 及以前的数据；测试里继续保留「改最后一根不影响更早因子」的断言。

还缺的：

| 缺口 | 现状 | 影响 |
|---|---|---|
| 自动启动 | 只能进数据管理页手动点 | 人忘了点就整天没数据 |
| 时段启停 | 手动启动后 24 小时保持连接，只在 `wait_update` 里空转 | 非交易时段白占天勤连接，可能和下载/研究抢连接 |

| 保留策略 | 只增不删 | tick 库每天约 100 MB，长期会撑爆磁盘 |
| 单实例保护 | 无 | 两个程序实例会各自连一条，重复采集、浪费额度 |
| 与历史下载互斥 | 只有弹窗提醒，没有硬互斥 | 免费账号可能被挤掉 |

建议改法（不改变现有采集器主体）：

1. **接线 `data.tick.enabled`**：程序启动后延时 1.5 秒，若为 `true` 且没有手动启动过，自动创建 `TickRecorder` 并 `start()`。没有账号/没有关注品种时只写一条日志和状态，不反复弹窗、不无限重连。
2. **采集器内置时段状态机**（推荐，比界面定时器可靠）：

```text
idle（休市）
  → 距离开盘还有 lead_seconds：waiting
  → 到开盘：connecting → running
  → 收盘后 close_grace_seconds：draining（flush）→ 断开 TqApi → idle
  → 循环到下一个时段
```

判断口径：

- 用 `sessions_for_symbol(cfg, symbol)` 取每个关注品种的时段，取并集；中金所和商品混在一份名单里也不会误判。
- 用 `is_trading_day(futures_trading_day(now))` 过滤周末、节假日、临时休市；周五夜盘属于下周一交易日，不会被误判成周末。
- 开盘前用 `in_trading_sessions(sessions, now + lead)` 判断「要不要提前连」；
- 收盘后用 `in_trading_sessions(sessions, now - grace)` 判断「要不要断」；
- 非交易时段每 30 秒醒一次即可，退出响应仍然及时。

3. **配置新增（都有默认值，旧配置不改也能跑）**：

```yaml
data:
  tick:
    enabled: false              # 已有键，改成真正生效：程序启动自动采集
    session_only: true          # true=只在交易时段连接；false=保持现在的常开
    open_lead_seconds: 30       # 开盘前提前连，避免漏掉第一笔
    close_grace_seconds: 60     # 收盘后多收一会儿，防止尾盘 tick 没到
    idle_poll_seconds: 30       # 休市时多久检查一次
    auto_synth: true            # 收盘后自动合成 1/5/15/30/60 分钟和日线
    synth_delay_seconds: 120    # 收盘后延迟多久合成，避开数据落库延迟
    retention_days: 30          # 原始 tick 保留天数；0=不删除
```

4. **收盘后自动合成**：在采集器状态机进入 `idle` 后，若 `auto_synth=true`，用后台线程调用 `synthesize_symbol()` 写 `data/klines/tick_bars.sqlite`。写一个 `data/ticks/synth_state.json` 记录「交易日 → 已合成」，同一天重复触发时跳过；合成失败只告警，下次收盘再补。
5. **保留策略**：只删原始 tick，不删合成后的 K 线。合成成功后，删除早于 `retention_days` 的 tick；删除走现有的 `manage.py` 审计/删除逻辑，先统计再删，日志写清条数。
6. **单实例与互斥**：
   - 启动时写 `data/ticks/recorder.lock`（PID + 启动时间）；发现另一个存活 PID 就直接拒绝启动，状态显示「已有采集器在跑」。
   - `pause_record_during_download=true`（默认）：点「下载历史 tick」前自动停采集，下载结束后按 `enabled` 自动恢复，避免免费账号被第二条连接挤掉。
   - `pause_record_during_research=true`（可选）：历史回测/优化占用天勤时暂停采集，结束后恢复。
7. **状态卡补充**：显示「等待开盘 09:00」「采集中：fu2701 等 3 个」「已收盘，今日 12.3 万条」「下次开盘 21:00」「磁盘占用 1.8 GB」。数据管理页再加一个「预估占用」提示。

存储估算（按现有库实测约 181 B/tick）：

| 关注合约数 | 约 tick/日 | 原始 tick/日 | 30 天 |
|---|---|---|---|
| 2 个 | 约 8.6 万 | 约 16 MB | 约 0.5 GB |
| 5 个 | 约 21.6 万 | 约 39 MB | 约 1.2 GB |
| 14 个 | 约 60 万 | 约 110 MB | 约 3.3 GB |

所以默认 `retention_days: 30`，并建议因子挖掘只盯 2~5 个合约。合成后的 5/15 分钟 K 线很小，可以长期保留，因子挖掘优先读合成 K 线，不直接读原始 tick。

与持仓量因子的关系：

- tick 入库已经带 `open_interest`，自动采集等于把持仓量数据源补上了；覆盖多久，OI 因子就能研究多久。
- 仍然是**合约级**数据：主力换月前后 OI 不连续，不能把不同合约的 OI 拼成一条序列。合成和因子研究都按具体合约分段，报告里写清合约与区间。
- 免费账号的 tick 是盘中快照，不是逐笔成交；用于 1/5/15 分钟研究足够，但不能当逐笔委托流做微观结构研究。

验收：

1. 配置 `enabled: true` 后启动程序，非交易时段状态为「等待开盘」，不建立天勤连接；
2. 开盘前 30 秒自动进入「采集中」，库里出现 tick；
3. 收盘 60 秒后自动 flush、断开，状态变「已收盘」；
4. 收盘 2 分钟后 `tick_bars.sqlite` 出现当天合成 K 线；
5. 周五夜盘正常采集，周六日盘不连接；
6. 节假日按 `config/holidays.yaml` 不连接；
7. 第二个程序实例启动时拒绝重复采集；
8. 下载历史 tick 时采集自动暂停，下载结束自动恢复；
9. 超过保留天数的原始 tick 被清理，合成 K 线仍在；
10. 关窗口时缓冲落盘、状态写「stopped」。

### 4.6 因子挖掘基础数据需求与自动补齐（数据管理新增）

#### 4.6.1 需求由研究层定义，数据管理只执行

新增 `src/research/data_requirements.py`，作为唯一口径：因子挖掘页用它判断绿灯，数据管理页用它算缺口。不要再在两边各写一套阈值。

「可用根数」= 原始根数 − 因子预热 60 根 − 标签最大周期 24 根。门槛按模式分：

| 研究模式 | 最少可用根数 | 建议根数 | 最少交易日跨度 | 最少合约数 |
|---|---|---|---|---|
| 快速（只看价量） | 600 | 1000 | 40 | 2 |
| 标准（IC/MI/置换/FDR） | 1000 | 2000 | 60 | 2 |
| 严格（加 WFA/Lock/状态） | 1500 | 3000 | 120 | 3 |
| 状态识别 | 1200 | 2500 | 90 | 3 |

附加条件：

| 条件 | 绿灯门槛 | 说明 |
|---|---|---|
| 持仓量覆盖 | 分析窗口内 `oi` 非空 ≥90%（严格 ≥95%） | 不满足时 OI 组禁用，不填 0 |
| 数据新鲜度 | 分钟线最后一根 ≤1 个交易日；日线 ≤3 个自然日 | 防止拿半年前数据跑 |
| 合约类型 | OI 只算具体合约 | 主连换月跳变，见 4.2 |
| 缺口 | 单品种缺口 >10% 时降级为快速模式 | 报告里写清 |
| 样本外 | 最后 15% 至少 150 根 | Lock 集最小可用 |

各周期在免费天勤「约 1 万根上限」下大约能拿到：

| 周期 | 约 1 万根对应跨度 | 能否满足标准模式 | 说明 |
|---|---|---|---|
| 1 分钟 | 约 25 个交易日 | 跨度不够 | 只做短样本观察，不给绿灯 |
| 5 分钟 | 约 120 个交易日 | 可以 | 因子挖掘推荐的最细周期 |
| 15 分钟 | 约 370 个交易日 | 可以 | 主力研究周期 |
| 30 分钟 | 约 700 个交易日 | 可以 | 稳定性和状态研究更合适 |
| 60 分钟 | 约 1400 个交易日 | 可以 | 长周期对照 |
| 日线 | 远长于需求 | 可以 | 合约存续期可能短于上限 |

结论：**因子挖掘默认用 5/15/30/60 分钟 + 日线，不用 1 分钟做主研究**；1 分钟只做辅助观察。这样免费账号也能达到绿灯。

#### 4.6.2 绿灯规则

| 状态 | 条件 | 因子挖掘页行为 |
|---|---|---|
| 红 | K 线根数/跨度/合约数任一不达标，或数据过期 | 禁用「开始因子挖掘」，显示缺什么、去哪个页面补 |
| 黄 | 价量 K 线达标，但 OI 覆盖不足（或没有专业版 tick 历史） | 允许跑价量；OI 组置灰；顶部写「OI 还需 X 个交易日」 |

状态落盘：`data/factor_mining/data_status.json`，记录检查时间、每个品种/周期的根数、OI 覆盖、结论。因子挖掘页打开时先读它，再后台复检，避免每次打开都扫全库。

#### 4.6.4 历史 K 线补齐与断点续传

| 账号 | 做法 | 能拿到多久 |
|---|---|---|
| 免费天勤 | `KlineProvider.fetch(..., keep_history=True)`，每次取服务端上限（实测约 1 万根），与本地合并；每天收盘后增量滚动 | 5 分钟约 6 个月；更早拿不到 |
| 专业天勤 | `DataDownloader(dur_sec=周期秒数)` 按月/90 天分块下载 CSV → 清洗入库；manifest 记已完成块 | 按权限和合约存续期 |
| 新浪/同花顺 | 只做补充，不作为自动补齐主通道（同花顺要抢鼠标） | 短 |

断点续传：

- 每块键：`合约|周期|起|止`，写 `data/factor_mining/kline_manifest.json`；`done` 跳过，`failed` 下次重试，已存在的 CSV 直接入库不重下；

#### 4.6.6 下载通道限速评估

结论：**不需要做网络层限速；需要做「时段 + 并发 + 分块暂停 + 优先级」四件事。**

| 通道 | 数据量 | 带宽占用 | 主要风险 | 建议 |
|---|---|---|---|---|
| 历史 K 线 | 每个合约/周期约 0.5~1 MB | 很小 | 天勤连接、SQLite 写锁 | 1 并发；默认非交易时段；WAL + 批量提交 |
| 实时 tick | 每合约约 360 B/s（2 笔/秒） | 可忽略 | 磁盘增长、天勤连接 | 不限制；批量落库；保留 30 天 |
| 历史 tick | 每合约每天约 10~30 MB CSV | 大 | 天勤连接、磁盘、CPU | 默认只在非交易时段；1 并发；1 天一块；块间停 3~5 秒；交易时段不跑 |
| 实时 K 线/行情 | 交易链路 | 小 | 被下载挤连接/CPU | 下载暂停或让路；独立账号更稳 |

具体策略：

1. **默认 `off_hours_only`**：只在 15:10–20:50、02:40–08:50、周末和节假日下载；交易时段一律暂停。这是最可靠的「不影响交易」。
2. **1 并发**：K 线和 tick 共用一个下载队列，任何时刻只跑一个块，不并发开多个 `TqApi/DataDownloader`。
3. **分块暂停**：历史 tick 每块之间 `sleep 3~5s`；极端情况下用户强制盘中下载，降到「1 块/60 秒」，并在开盘/收盘前后 5 分钟暂停。
4. **实时采集优先**：盘中只保留实时 tick 采集（它很小），历史下载让路；下载队列遇到 `is_trading_session` 直接休眠。
5. **忙时暂停**：`pause_when_trading: true` 时，调度器实盘运行/有持仓管理动作，就暂停下载；恢复后从断点继续。
6. **低优先级**：下载线程用守护线程，批量写库、短事务；K 线库已开 WAL，tick 库也建议开 WAL，避免合成/研究读的时候被写锁住。
7. **账号隔离**：免费账号连接数有限，**不要在同一账号、同一交易时段同时做实时行情 + 历史下载**；条件允许时给下载单独开一个天勤账号。

不建议做操作系统级带宽整形：K 线本身很小，实时 tick 也很小，真正的瓶颈是连接额度和 SQLite 写入，不是带宽；整形既复杂又解决不了根因。

配置建议：

```yaml
data:
  factor_backfill:
    enabled: true
    auto_on_start: true          # 启动后检查并补齐缺口
    after_close_topup: true      # 收盘后补当天新增
    policy: off_hours_only       # off_hours_only | throttled | manual
    max_concurrent: 1
    chunk_pause_sec: 3           # 历史 tick 块间暂停
    trading_pause_sec: 60        # 若允许盘中下载，每块间隔
    pause_when_trading: true     # 实盘运行/持仓管理时暂停
    target_mode: standard        # quick | standard | strict | regime
```

## 6. 因子筛选流水线（门顺序不可逆）

### 6.0 门顺序

```
门0 数据门
  → 门1 描述统计/半衰期
  → 门2 稳定性（复用：两半 + 4段 + 跨品种）
  → 门3 Rank IC 序列/ICIR
  → 门4 互信息 MI
  → 门5 分层单调性
  → 门6 分块置换
  → 门7 BH-FDR
  → 门8 因子 WFA
  → 门9 共线性/增量
  → 门10 状态条件
  → 结论分级
```

原则：**门 2 不过，后面不算**；**门 6/7 不过，直接驳回，不做 WFA**。避免在随机噪声上继续花时间。

### 6.1 门 1：描述统计与半衰期（新增）

输出：

- 因子分布：均值、标准差、偏度、峰度、1%/5%/50%/95%/99% 分位；
- 因子自相关 ACF(1..20)：因子自身持续性；
- 按预测周期的 IC 衰减：`IC_h`，`h=1,3,6,12,24`；
- 半衰期：若 `|IC_h|` 首次降到 `|IC_1|` 的一半，取该 h；或拟合 `|IC_h| = a·exp(-λh)`，半衰期 `ln2/λ`。报告里必须写用的是哪种口径；
- 5 层收益：按因子分 5 组，各组未来收益均值；单调性分 = 组序号与组均值的 Spearman；
- 淘汰提示：半衰期 < 1 根、或 5 层收益乱跳且单调性分接近 0，标「交易成本可能扛不住/不稳定」。

### 6.2 门 2：稳定性（复用，不重写）

直接复用：

- `_split_halves` + `_both_significant`：两半同号且 \|t\| ≥ 1.65；
- `_window_agreement`：4 段里至少 75% 同向显著；
- `scan_regularities` 的跨品种规则：多品种时至少 2 个合约过关。

新增只做一件事：把门槛做成配置（`min_abs_t`、`min_windows_ratio`、`require_cross_symbol`），默认值不变。**不要另写一套「两半检验」。**

说明：这一门回答的是「同一段历史里稳不稳」，不是样本外。样本外看门 8。

### 6.3 门 3：Rank IC 序列与 ICIR（新增）

- 全样本 Rank IC：因子名次与未来收益名次的 Pearson，就是 Spearman；与现有 `corr` 同口径，不重复造。
- 滚动 IC：窗口 `W=60`（可配 60/120），逐窗算 Rank IC，得到 `IC_t` 序列；**默认不重叠（步长=窗口）**，需要更密的曲线时才用重叠窗，并在报告里注明。
- 汇总：
  - `IC_mean`、`IC_std`、`ICIR = IC_mean / IC_std`；
  - `IC>0` 占比；
  - `t = IC_mean / (IC_std/√K)`，其中 K 为窗口数；重叠标签/重叠窗口用 Newey-West，滞后 `h-1`，并报告有效样本；
  - IC 均值 95% 置信区间：复用 [robustness.py](../../src/backtest/robustness.py#L69-L83) 的 `bootstrap_ci`（它接受任意浮点列表）。
- 报告：IC 时序图、IC 热力图（因子 × 周期）。
- 判定：ICIR 先作为**排序和结论参考**，不单独当硬门槛。硬门槛放在置换 + FDR，避免小样本下 ICIR 误杀。

### 6.4 门 4：互信息 MI（新增）

- 方法：分位分箱（默认 10 箱）直方图互信息，单位 nats；固定分箱规则，报告分箱数。
- 零分布：用同一套分块置换的未来收益，算 B=200 次 MI，得到 `MI_null`；`MI_z = (MI - mean)/std`，`p_mi`。
- 与 IC 并排：

| 情形 | 解释 | 后续 |
|---|---|---|
| IC 低、MI 高 | 非线性/状态型 | 标记「状态型因子」，进入门 10 |
| IC 高、MI 也高 | 线性强信号 | 正常候选 |
| IC 高、MI 接近 0 | 线性但信息量薄 | 降级观察 |
| 两者都低 | 无增量 | 驳回 |

- 冗余：因子两两 MI、与实盘四因子的 MI；`MI` 高且相关高 → 标「冗余」。
- 不引入 sklearn；`mutual_info_regression` 的 kNN 做法在 10 万根上太慢，直方图法足够做筛选。

### 6.5 门 5：分层单调性（新增，三分位差保留）

- 5 层（或 10 层）分组，输出每组样本数、未来收益均值、胜率；
- 单调性分：`Spearman(组序号, 组均值)`；
- 头尾差：复用现有三分位差的 t 口径作为交叉核对；
- 只对「5 层方向一致」的因子给高分；中间乱跳的标「两端有效、非单调」，不算通用因子。

### 6.6 门 6：分块置换检验（新增，修正资料做法）

原假设 H0：因子与未来收益无真实预测关系。

统计量：`|全样本 Rank IC|`（辅助看 `|头尾差|`）。

做法：

1. 固定因子顺序，只打乱未来收益；
2. **分块**打乱，块长 `L = max(h, ceil(n^(1/3)))`，环形拼接；不要逐点 iid 打乱；
3. 重复 `B=1000`，`p = (1 + #{|perm| ≥ |obs|}) / (B+1)`；
4. 输出置换分布直方图、真实值分位、p 值。

为什么不用资料里的直接打乱：往后 h 根的标签在相邻样本间重叠，本身强自相关。iid 打乱把这种相关性破坏掉，零分布会变窄，p 值偏小，容易把噪声当规律。分块置换保留局部时序结构，更保守。

性能设计：

- 每个「品种 × 周期」只生成一次置换索引矩阵（B × n），所有因子共用；
- 先把因子和标签转成名次，IC 就是名次向量的相关；用矩阵乘法一次算完 B 次；
- 29 个因子 × 3 档 × 5 品种 × 1000 次，在向量化下是秒级到分钟级，不需要并行框架。

### 6.7 门 7：BH-FDR 多重检验（新增）

- 一次运行内，检验族 = 所有「因子 × 周期 × 品种」；
- 用 Benjamini-Hochberg 算 adjusted p；默认 `alpha=0.05`；
- 报告必须写：检验总数、原始显著数、FDR 后显著数；
- 候选规则：`adjusted_p < alpha` 且门 2 通过 且（多品种时）≥2 个品种通过；
- 同因子跨品种高度相关，BH 在这种正相关下通常偏保守；报告同时给「按品种分组」的结果，避免一个品种带偏全族；
- Bonferroni 只作为参考列，不当默认（太保守）；
- 同一份数据反复换参数跑，要在报告里累计「本轮试验次数」，提醒数据窥探。

### 6.8 门 8：因子 WFA 样本外（新增）

- 切分：滚动固定训练窗（不是扩张窗）。默认：
  - 1 分钟：训练 200 根，步长 20；
  - 5/15 分钟：训练 250 根，步长 20；
  - 日线：训练 252 根，步长 20。
- 每段训练内只做一件事：确定方向（IC 符号）和分位阈值（20%/80%），不调参；
- 样本外：算 Rank IC、IC>0 占比、头尾多空收益、命中率、累计曲线；
- 汇总：OOS IC 均值、OOS/IS IC 比、符号翻转段数、分段胜率；
- 参数敏感性：训练窗 ±20%、步长 ±50%，至少 3 组，要求符号一致、无断崖；
- Lock 集：最后 15% 数据全程不参与任何选择，只在结论前跑一次，报告单列；
- 复用策略 WFA 的「训练不碰检验段」原则和指标命名；不强行套用策略 PnL 的 `walk_forward_metrics`，因为因子评估的统计量不同。

### 6.9 门 9：共线性与增量（新增）

- 因子间 Spearman 相关矩阵；\|ρ\|>0.8 标「高度相关」；
- VIF：数值因子相关矩阵求逆，取对角线；分类因子（价仓四象限）不直接进 VIF，改为分组统计；
- 与实盘四因子（MA/唐奇安/布林/SAR）比相关和 MI；
- 增量检验：把新因子与已有因子做等权名次组合，比较组合 IC 与单因子 IC；没有增量就标「冗余，不建议入库」；
- **只报告，不改实盘权重**。

### 6.10 门 10：状态条件（见第 7 节）

每个状态下单独算：样本数、未来收益均值、因子 IC、头尾差、命中率。样本 <80 的状态只做描述，不下结论；状态内多重检验同样走 BH-FDR 或明确标「探索性」。

### 6.11 结论分级

| 级别 | 条件（建议默认） | 候选池处理 |
|---|---|---|
| 候选-通用 | 门 2 过 + FDR 后显著 + 单调性不差 + 非冗余；严格模式再加 WFA 同号 | 进候选池，可勾选 |
| 候选-状态型 | 全样本一般，但某状态内 FDR 后显著、样本足、OOS 同号 | 进候选池，标「仅某状态」 |
| 观察 | FDR 边缘、WFA 衰减大、或分层不单调；标准模式未做 WFA 的标「未做样本外」 | 进报告，不进候选池 |
| 驳回 | 门 2 不过 / 置换 p 高 / FDR 后不显著 / 符号翻转 | 只留报告，明确写原因 |

所有结论都必须带一句：**这是历史统计，不是买卖点；要用必须另写完整开平仓规则。**

## 7. 市场状态识别与策略匹配

### 7.1 状态特征集（只用 t 及以前）

| 特征 | 口径 | 作用 |
|---|---|---|
| `adx_14` | 现有 ADX | 趋势强度 |
| `atr_pct` | ATR/close | 波动水平 |
| `atr_pctile_60` | ATR 在近 60 根的分位 | 波动状态 |
| `realized_vol_20` | 收益标准差 20 | 波动水平（与 ATR 互为校验） |
| `hurst_100` | 收益率 R/S Hurst | 趋势/回归/随机 |
| `autocorr_20` | 收益一阶自相关 | 延续/反转 |
| `volume_z_20` | 成交量 z 分 | 参与度 |
| `oi_chg_z_20` | 持仓变化 z 分（有 OI 时） | 资金驱动 |
| `ema20_slope` | EMA20 斜率 / ATR | 趋势方向强度 |
| `efficiency_ratio_20` | 净位移 / 路径长度 | 趋势效率（可选） |

默认 8 个：ADX、ATR 分位、波动、Hurst、自相关、量 z、OI z、EMA 斜率。特征之间先做相关筛选，避免高度共线（\|ρ\|>0.9 的留一个）。

### 7.2 聚类流程（防未来函数）

1. 只用样本内（前 60%~70%）拟合均值和标准差；
2. KMeans，`k=2..4`，k-means++ 初始化，固定随机种子，10 次重启；
3. 轮廓系数在最多 5,000 个样本上抽样计算（全量 O(n²) 太慢）；
4. 选 k：先看轮廓系数，再看最小簇占比 ≥10%，再看跨品种稳定性；k 越小越稳，优先 2~3；
5. 样本外不重拟合：按最近聚类中心归类；
6. 状态标签全程只用于研究，不写进实盘策略。

### 7.3 状态画像与命名

输出每个簇的：特征均值（原始单位 + z 分）、样本数、样本占比、未来收益均值、波动、主要因子 IC。

自动命名规则（示例）：

| 条件 | 名称 |
|---|---|
| ADX 高 + \|EMA 斜率\| 高 + ATR 分位低/中 | 趋势-低波 |
| ADX 高 + ATR 分位高 | 趋势-高波 |
| ADX 低 + ATR 分位低 + Hurst≈0.5 | 震荡-低波 |
| ADX 低 + ATR 分位高 + Hurst<0.45 | 高波-回归/无序 |
| Hurst>0.55 且自相关>0 | 延续态 |
| Hurst<0.45 且自相关<0 | 回归态 |

命名只是给人看的标签；报告同时给 z 分表，避免名字误导。

### 7.4 状态转移矩阵

统计 `P(下一根状态 | 当前状态)`，输出矩阵和持续概率（对角线）。持续概率低的状态，不适合做长期策略开关，只适合做短周期过滤。

### 7.5 状态 × 因子表

每行一个状态，每列一个因子/周期：IC、头尾差、样本数、FDR 后是否显著、OOS 是否同号。核心产出是一句话：

> 因子 X 只在「趋势-低波」状态有效，在「震荡-低波」失效。

这张表直接服务目标 2。

### 7.6 状态 × 策略清单

复用 [styles.py](../../src/research/styles.py#L39-L62) 的 `ENGINES_BY_STYLE`，加状态条件：

| 状态 | 可去交叉测试的引擎 | 说明 |
|---|---|---|
| 趋势-低波 | 双均线、SuperTrend、海龟突破、双周期通道、多因子 CTA | 趋势策略的主场 |
| 趋势-高波 | 海龟突破、双周期通道、SuperTrend | 降低仓位，防跳空 |
| 震荡-低波 | 不给新引擎；作为「少开/不开趋势」的过滤 | 遵守仓库「不新写震荡反向策略」原则 |
| 高波-无序 | 只做过滤/风险提示 | 不推荐新开仓 |
| 回归态（H<0.45） | 只做过滤；本程序没有专用回归引擎 | 与现有类型倾向一致 |

输出形式：

- 状态卡：状态名、样本占比、持续概率、有效因子、建议引擎；
- 按钮「带到交叉测试」：只预填品种/周期/引擎，不自动跑、不自动改实盘；
- 明确写「这是研究清单，不是切换指令」。

### 7.7 与现有 ADX/ATR 过滤的关系

- `market_state.py` 的规则过滤继续管实盘开仓，不改；
- 聚类状态是研究层的「数据画像」，用来解释「为什么某段策略不灵」；
- 两者不一致时，报告并列展示：
  - 规则=趋势、聚类=震荡 → 提示「规则放行但数据画像偏震荡，谨慎」；
  - 规则=震荡、聚类=趋势 → 提示「规则拦住但画像偏趋势，可复查参数」；
- **不自动用聚类结果覆盖规则过滤。**

### 7.8 状态稳定性

- 样本内/样本外同一簇的特征均值漂移 >1 个标准差，标「状态漂移」；
- 轮廓系数 <0.2，标「状态分离度弱」；
- 跨品种簇画像不一致，标「品种特异」，不推广；
- 不稳定的状态不能拿来给策略清单，只能做描述。

## 12. 测试与验收

### 12.1 单元测试

| 测试 | 断言 |
|---|---|
| 因子公式 | 已知小样本上手算值一致 |
| 无未来函数 | 改最后一根，不影响更早因子值（扩展现有测试） |
| Rank IC | 与手工 Spearman 一致；常数序列返回 0 |
| IC 序列/ICIR | 已知序列的均值/标准差/ICIR 正确 |
| 分块置换 | 纯噪声下 p 值近似均匀；强信号下 p 小；同种子可复现 |
| BH-FDR | 与已知 p 值表的 adjusted p 一致；单调性正确 |
| MI | `y=f(x)` 的 MI 明显高于独立随机；分箱固定 |
| Hurst | 趋势序列 >0.5、均值回归 <0.5、随机≈0.5（容差内） |
| KMeans | 固定种子标签稳定；样本外按最近中心归类 |
| 流水线 | 人造动量 → 有候选；纯噪声 → FDR 后很少/没有候选 |
| OI 缺失 | OI 因子跳过并写原因，不填 0 |
| 数据需求 | 600/1000/1500 三档边界正确；根数够时红转绿，OI 不足时绿转黄 |
| 缺口计算 | 已有 800 根、需 1000 根时只报 200 根缺口；不重下已有区间 |
| 断点续传 | 完成一半后中断，重启只补未完成块；manifest 不重复 |
| 免费上限 | 请求超上限只标 `cap_reached`，不循环重试 |
| 下载时段 | 交易时段 `off_hours_only` 不入队；收盘后自动继续 |
| 下载互斥 | 历史 tick 下载时实时采集暂停，完成后恢复 |
| 绿灯门槛 | 红灯时开始按钮禁用；黄灯时 OI 组禁用；绿灯全开 |
| 候选池迁移 | 旧 `规律候选池.json` 的勾选迁移到新文件 |
| 安全 | 研究层不 import `src.trader`（现有测试保留） |
| UI | 研究页签名更新；`因子挖掘` 能打开 |

### 12.2 手工验收

1. 用人造动量/回归数据各跑一次，结论方向符合预期；
2. 用真实具体合约（如 `fu2701`）跑标准模式，报告显示 OI 覆盖比例；
3. 同一份数据、同一种子重跑，指标完全一致；
4. 旧候选池勾选迁移后仍在；
5. 报告和 PNG 能打开；「带到交叉测试」只预填；
6. 全程无下单、无策略配置写入；
7. 关闭程序再打开，最近一次摘要能显示。

### 12.3 不通过的判定

- 出现未来函数（改最后一根影响更早值）→ 停止；
- 纯噪声数据 FDR 后仍大量入选 → 检查置换块长/检验族定义；
- 状态聚类在样本外完全换画像 → 标不稳定，不输出策略清单；
- OI 覆盖率不足却仍给 OI 结论 → 视为缺陷。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| OI 历史缺失 | 持仓量因子无法研究 | 先修数据层；不足就明确跳过，不填 0 |
| 主连换月跳变 | OI/成交量变化失真 | 只在具体合约上研究，或按合约分段 |
| 重叠标签 | 显著性被高估 | 分块置换 + NW t + 有效样本提示 |
| 多重检验 | 假阳性 | BH-FDR + 报告检验族大小 + 限制因子数量 |
| 小样本 | IC/FDR 不稳 | 最小根数、最小状态样本 80；不足只描述 |
| 状态漂移 | 策略清单过时 | IS/OOS 画像对比；漂移就标不稳定 |
| 数据窥探 | 反复调参挖出「漂亮结果」 | 假设前置、参数锁定、Lock 集、报告试验次数 |
| 性能 | 置换/WFA 太慢 | 共享置换矩阵、向量化、缓存、轮廓抽样 |
| 依赖膨胀 | EXE 变大、打包不稳 | 纯 numpy；sklearn 只作后续可选 |
| tick 每天约 100 MB | 长期占满磁盘 | 默认保留 30 天；先合成 K 线再删原始 tick；界面显示预估占用 |
| 免费账号多连接 | 采集/下载/研究互相挤掉 | 单实例锁；下载和历史研究时自动暂停采集；必要时改用专用账号 |
| 自动采集漏掉第一笔 | 开盘集合竞价后的首 tick 缺失 | 开盘前 30 秒预连接；状态卡显示连接时间，漏收写告警 |
