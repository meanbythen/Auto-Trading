## 1. 目的、范围与质量目标

### 1.1 目的

1. 用可重复的测试证据回答三个问题：**该开仓时是否开、不该开时是否拦住、出事后账能不能对上**。
2. 把「回测好看」与「实盘可用」分开验证，避免把历史拟合当成未来收益。
3. 为当前 53.7.3 版本建立可执行的测试基线，后续每个版本按同一套门禁回归。
4. 明确哪些必须自动化、哪些只能人工演练，避免用单测冒充实盘验收。

### 1.2 范围

**纳入测试：**

- `src/` 下全部业务代码：行情数据、策略、回测、风控、账户账本、调度执行、交易通道、告警运维、研究复盘、GUI。
- `config/` 配置读写、`config/holidays.yaml` 节假日、账户注册表与密钥库。
- `data/` 下的状态文件、SQLite 投影库、K 线库、告警文件、导出文件。
- 打包产物（PyInstaller onedir）与启动冒烟。
- 外部集成：天勤行情、新浪备源、同花顺 GUI、CTP 柜台（仿真优先）。

**不纳入测试：**

- 策略未来是否盈利（只验证逻辑一致性、统计口径与过拟合防护，不承诺收益）。
- 券商柜台、交易所、天勤/新浪服务端内部实现。
- Windows 操作系统、Python 解释器、第三方库自身的缺陷（只做版本兼容与升级回归）。
- 真实资金的全自动无人值守验收（必须人工监督、小单验证）。

### 1.3 质量目标

| 编号 | 目标 | 验收方式 |

### 3.5 关键业务链路

```
配置/账户
   │
   ▼
行情拉取 ── 清洗/拼接 ── 收线过滤 ── 指标/策略评估
                                      │
                                      ▼
                                 决策（开/平/反手/持有）
                                      │
                                      ▼
   风控链 EARLY: 暂停 → 健康 → 记账失败 → 同根去重
                                      │
                                      ▼
   风控链 SEND: 手数 → 上线阶段 → 未完成委托 → 对账 → 单账号 → 组合
                                      │
                                      ▼
                    订单定价/报单（sim / gui / ctp）
                                      │
                                      ▼
             成交回报（去重）→ JSON 账本 → SQLite 发件箱 → 投影
                                      │
                                      ▼
              对账（柜台/账本/内存）→ 告警/事件 → 界面与日志
```

该链路是 P0 测试主线。任何一环的「静默失败」都比「报错失败」更危险，因此测试不仅要验证成功路径，还要验证**失败一定可见、可见后不重复、重复后不改账**。

## 4. 测试原则与总体策略

### 4.1 测试原则（结合 Myers 与项目实际）

1. **测试为找错，不为证明无错。** 用例必须写预期结果，失败要能定位。
2. **有效输入与无效输入并重。** 价格 0、负手数、空 K 线、缺列、乱序时间、重复回报都要有对应用例。
3. **尽早测试、左移。** 策略/风控/账本的核心不变量在单元层锁死，不把问题留到实盘。
4. **缺陷集群。** 历史出过问题的区域（发件箱、投影、告警、周期拼接、换月）提高回归密度。
5. **杀虫剂悖论。** 固定用例集之外，每版本补充变异输入、边界组合与故障注入。
6. **风险驱动。** 资金安全 > 数据正确 > 核心功能 > 体验与文档。
7. **可重复。** 固定随机种子、固定时钟、隔离临时目录、测试不写真实数据。
8. **自动化分层。** 能用单测证明的绝不放到 E2E；必须靠真实通道的明确标为人工。

#### 4.2.1 白盒覆盖准则

白盒测试用于回答「哪些分支根本没被执行过」，不替代黑盒业务验收。执行时先看覆盖缺口，再按业务预期写断言。

| 准则 | 要求 | 适用模块 | 目标 |
|---|---|---|---|
| 语句覆盖 | 每行可执行代码至少执行一次 | 全部 `src/` | 全局 ≥56%，核心域 ≥80% |
| 分支/判定覆盖 | 每个 `if/elif/else`、三元、循环退出都取到 | `kernel/risk_chain.py`、`account/outbox.py`、`scheduler/fill_reconcile.py`、`flatten_manager.py`、`order_pricing.py`、`login_flow.py` | ≥90% 分支 |
| 条件组合 | 多条件判定中每个原子条件独立影响结果 | `risk_chain` 门禁、`strategy/decision_guard.py`、配置加载 | 安全相关判定逐步补 MC/DC |
| 循环覆盖 | 0 次、1 次、多次、异常退出 | 发件箱重试、凯利样本、K 线聚合、tick 合成 | 四类均有用例 |
| 路径覆盖 | 关键业务路径全覆盖 | 信号→门禁→报单→成交→入账→投影→告警 | P0 路径 100% |
| 数据流覆盖 | 定义-使用对、状态读写 | `bot_state`、账本、风控状态、配置双读 | 关键变量无未测试读写 |
| 异常路径 | 每个 `except`/降级分支至少一条用例 | 行情回退、SQLite 降级、告警失败、CTP 断线 | 100% 有对应用例 |

执行方式：`pytest --cov=src --cov-branch --cov-report=term-missing`，按模块查看未覆盖行，再补用例；禁止为了覆盖率写无断言的「走过场」测试。

### 4.4 分层自动化策略

按用例数量而非耗时分配，保持金字塔：

- **约 70% 单元/组件**：纯逻辑、边界、公式、状态机。
- **约 20% 集成**：模块接口、SQLite、临时工作区、事件流。
- **约 10% 系统/E2E 与人工**：GUI 冒烟、打包、通道联调、演练。

判断标准：**如果失败时无法在 5 分钟内指出大概哪一层出问题，说明用例层次放错了。**

### 4.5 基于风险的优先级

| 级别 | 定义 | 示例 | 要求 |
|---|---|---|---|
| P0 | 直接导致资金损失、错账、无法止损、数据损坏、密钥泄露 | 重复开仓、止损未发、成交重复入账、柜台有仓程序无仓、实盘通道错配 | 必须自动化 + 每版本人工复核；阻断发布 |
| P1 | 核心功能错误但有规避 | 回测口径错、周期拼接错、告警丢失、配置保存错 | 自动化；发布前必须通过 |
| P2 | 局部功能/体验问题 | 导出格式、图表显示、文案、非关键页签 | 自动化或人工抽检 |
| P3 | 建议与优化 | 性能优化、文档、日志可读性 | 记录，不阻断 |

### 4.6 明确不做的事

- 不在 CI 连接真实资金账户，不自动发真实委托。
- 不用 GUI 像素级截图比对作为主判据（坐标/主题/DPI 易变），以控件状态与业务结果为准。
- 不把回测收益率作为质量门禁，只校验口径、可复现与风险指标。
- 不追求 100% 覆盖率；核心不变量与失败路径优先。

### 5.2 P0 风险测试重点

1. **开仓唯一性**：同一 `bar_id`、同一信号、重复回报、重启后都只能产生一笔有效开仓。
2. **平仓可达性**：暂停、健康停开、上线阶段未批、对账未通过时，止损/反手/清仓仍必须能发出。
3. **成交幂等**：`event_id` + `fill_key` 双去重；失败重试不改变交易结果。
4. **对账闭环**：柜台、账本、内存三方每轮对齐；phantom 只补一次；未认领仓冻结并可见。
5. **时间正确**：交易日、夜盘归属、午休、尾盘半根、节假日缺年份。
6. **回测不偷看**：信号只用已收盘 K；成交在下一根可交易开盘；止损与主动退出同 bar 取保守价。

### 6.3 环境隔离与安全红线

1. **真实数据只读**：测试不得写 `data/trading.db`、`data/alerts.jsonl`、`data/bot_state.json`；统一用 `tmp_path` 工作区。
2. **密钥隔离**：`tests/conftest.py` 已用内存密钥库替换 DPAPI，禁止读取开发机真实密码。
3. **项目根隔离**：UI 用例通过 `monkeypatch` 把 `project_root` 指向临时目录。
4. **网络隔离**：单元/集成默认不联网；联网用例显式标记，失败可重跑。
5. **实盘红线**：CI 环境变量中不得出现真实账户、真实前置、真实密码；实盘 executor 配错必须拒绝启动。
6. **告警隔离**：任何测试产生的告警只能落在本次工作区，不得污染真实 `alerts.jsonl`。

### 6.4 测试数据策略

| 数据类型 | 生成方式 | 要求 |
|---|---|---|
| K 线 | 代码合成（固定种子）+ 真实库小样本 | 覆盖缺口、重复、乱序、异常价、跨午休、夜盘、换月 |
| 成交/订单 | 工厂函数构造 | 覆盖部分成交、重复回报、拒单、撤单、平今/平昨 |
| 账户/账本 | 临时 SQLite + 迁移脚本 | 覆盖旧账迁移、投影漂移、只读库 |
| 配置 | YAML 模板 + 参数化 | 覆盖缺键、未知键、越界、类型错、双读不一致 |
| 时间 | 固定时钟/注入 now | 覆盖交易日边界、夜盘跨日、节假日缺年 |
| 随机 | 固定 seed | 蒙特卡洛、优化器、扰动结果可复现 |

**原则：** 测试数据必须能解释「为什么这条数据能暴露这个缺陷」，不追求大而全的真实数据。

### 6.5 时间与随机性控制

- 禁止在断言中直接依赖 `datetime.now()`；通过参数注入或时钟夹具固定。
- 夜盘、跨日、周末、节假日、尾盘 15 分钟必须有专门时刻用例。
- 蒙特卡洛、优化器、参数扰动必须固定 seed，并在报告中记录 seed。
- 对「当前时间」敏感的逻辑（心跳、过期、冷却）用可控时钟推进，不 sleep 等待。

### 7.5 专项测试

#### 7.5.1 数据质量与 K 线合成

- 1 分钟到 5/15 分钟按自然时钟拼接，午休断开。
- 30/60 分钟按连续交易分钟累计，10:15–10:30、11:30–13:30 不计入，余量结转，夜盘/日盘分组重置。
- 日线时间归交易日 00:00；周线由日线合成，不直接请求一周秒数。
- 尾盘不足整周期半根只参与指标，不触发新开仓。
- 去重、排序、去形成中、异常价格清洗、缺口标记。
- 主力换月/连续合约：换月日不产生假跳空；OI 因子在主力连续上自动关闭。
- 数据源回退：天勤失败回退新浪并标记来源；本地库续接；免费账号上限提示只一次。

#### 7.5.2 回测可信度

| 检查项 | 方法 | 通过标准 |
|---|---|---|
| 前视偏差 | 构造未来才可知的数据，断言信号不提前 | 信号只依赖已收盘 K |
| 成交时点 | 下一根开盘、跨午休/夜盘、涨跌停 | 成交时间与价格符合规则 |
| 止损成交 | 跳空、盘中触及、收盘确认 | 跳空用开盘，否则止损价；同 bar 保守 |
| 费用/滑点 | 开平手续费、平今/平昨、双边滑点 | 与配置和品种一致 |
| 换月 | 主力切换、回测结束强平 | 不产生虚假盈亏 |
| 过拟合 | 冻结最后半年、同一段只验收一次、参数扰动、蒙特卡洛 | 搜索不碰冻结段；重复验收被拒 |
| 可复现 | 固定数据、固定 seed、固定配置 | 两次结果逐笔一致 |
| 极值 | 空数据、单根、全 NaN、巨幅跳空 | 不崩溃，给出明确拒绝原因 |

#### 7.5.3 回测-实盘一致性

- 同一策略、同一参数、同一 K 线序列，回测与调度 `evaluate` 输出一致。
- 同一成交规则：下一根开盘、止损、反手、收盘清仓、尾盘半根。
- 实盘镜像闸门：过期 K、追价过大时放弃开仓，结果与挂机对照。
- 1 分钟复核：已有仓用 1 分钟检查止损是否更早，但 1 分钟不自行开新仓。
- 差异必须归因到固定原因（数据、滑点、成交时点、通道、人工干预），不允许「差不多」。

#### 7.5.4 账本与三方对账

- 成交回报在交易锁内入账，按成交键去重。
- 发件箱先 pending 落库，JSON 账本成功后才 ready；ready 只做补偿/投影/审计。
- 启动与每轮扫描各对账一次：柜台、账本、内存。
- phantom 仓：连续两轮确认后只补记一次。
- 未认领仓：冻结、提示「认领/平掉/忽略」，不静默交易。
- 账户投影漂移：只在字段真不一致时告警；库不存在/只读打不开不告警。
- 账本写失败：禁止开新仓，平仓不受影响。
- 旧账迁移：幂等，重复执行不重复记账。

#### 7.5.5 故障注入与恢复

| 故障 | 注入方式 | 预期 |
|---|---|---|
| 行情超时/断网 | mock 抛异常、断网 | 回退备源/本地库，标记来源，不崩溃 |
| CTP 断线 | 仿真断线、重建 | 重连、对账、未完成委托可见、不重复报单 |
| 进程被杀 | 任务管理器结束 | 守护按配置平仓或留 `unprotected_positions.json`；重启先对账 |
| 磁盘满 | 临时目录配额/只读 | 记账失败禁开仓、告警可见、不丢已有数据 |
| SQLite 锁 | 并发写/长事务 | 超时重试、只读降级、不误报漂移 |
| 时间跳变 | 修改系统时间/注入时钟 | 交易日与会话判定正确，不重复日结 |
| 重复回报 | 重复投递同一 fill | 不二次改仓 |
| 部分成交 | 分笔回报 | 汇总正确，剩余可撤/可继续 |
| 告警写失败 | 只读目录 | 主流程不受影响，失败可见 |

#### 7.5.6 并发与线程安全

- 交易锁覆盖：成交入账、手工平账、扫描下单。
- 关窗：有持仓/挂单先确认，后台线程最多等待 15 秒。
- 后台发件箱单线程消费，避免并发投影。
- UI 长任务不阻塞主线程；停止/暂停命令可打断。
- 重复启动：单实例锁只允许一个进程。

#### 7.5.7 性能与容量

| 指标 | 测量方法 | 基线策略 |
|---|---|---|
| 冷启动到可操作 | 启动计时 | 登记基线，回归不超 120% |
| 单轮扫描耗时（多品种） | 日志时间戳 | 不超扫描间隔，超时告警 |
| 回测吞吐（根/秒） | 固定数据集计时 | 登记基线，优化不得劣化 |
| 内存峰值 | 任务管理器/psutil | 长跑 24h 不持续增长 |
| SQLite 增长 | 文件大小/行数 | 有轮转/归档策略 |
| 日志增长 | 文件大小 | 20MB 轮转（已有） |

#### 7.5.8 安全测试

- 密钥：DPAPI 加解密、测试内存密钥库、日志/导出/异常不出现明文。
- 账户隔离：GUI 与 CTP 同资金账号也不混记；一账号一本账。
- 配置：实盘 executor 写错拒绝启动；未知键清理；敏感值不落日志。
- 日志：结构化日志脱敏；`trace_id` 可追踪但不泄露密码。
- 依赖：锁版本；定期 `pip-audit`；升级前跑全量回归。
- 文件权限：`secrets.local.yaml`、`data/` 不被无关用户读取（部署检查）。

#### 7.5.9 GUI 与可用性

- 启动、十页签切换、关闭无异常。
- 配置保存→重开回填一致；越界值夹紧并有提示。
- 回测/优化/交叉测试长任务有进度与可停止；结果表字段完整。
- 错误提示可理解：缺数据、未登录、通道未配置、账户未选。
- 高 DPI/不同分辨率下控件不重叠、关键按钮可见。
- 同花顺坐标预设可保存/恢复；点击自检不记入账户。

#### 7.5.10 兼容性与安装打包

- Windows 10/11（至少一个主力版本 + CI 的 windows-latest）。
- Python 3.12 干净环境安装 `requirements-dev.txt` 成功。
- PyInstaller onedir 产物包含资源、hiddenimports；`verify_dist.py` 通过。
- exe 启动 12 秒仍存活；无控制台闪退；日志目录可写。
- 无网络、无同花顺、无 CTP 时能启动并给出降级提示。

#### 7.5.11 CTP 上线验收

按四步走，每步有独立记录与签字：

1. **手工仿真**：登录、订阅、下单、撤单、成交、持仓、资金。
2. **手工真实**：最小手数、人工盯盘、确认回报与柜台一致。
3. **策略仿真**：策略信号→仿真报单→对账→复盘，跑满约定交易日。
4. **策略真实**：最小资金、人工在场、日终对账、异常立即停手。

补充演练：断线重连、部分成交、拒单、平今/平昨、换月、收盘清仓、进程被杀后的守护行为。

### 7.7 用例设计示例

#### 示例 1：凯利手数边界值

| 输入 | 样本笔数 | 期望 |
|---|---|---|
| 29 笔正期望 | 29 | 退回固定风险 |
| 30 笔正期望 | 30 | 启用 1/4 凯利，且不超过固定风险 |
| 31 笔正期望 | 31 | 同上 |
| 30 笔负期望 | 30 | 停开 |
| 凯利目标 2%、固定风险 1% | 30 | 取 1% |
| 无亏损笔 | 30 | 盈亏比显示横杠，凯利不启用 |

设计依据：边界值分析 + 判定表，锁住「样本不足」「负期望」「硬上限」三条业务规则。

#### 示例 2：风控链判定表（节选）

| 暂停 | bar_consumed | already_sent | 记账失败 | 期望首条拒绝 |
|---|---|---|---|---|
| 是 | 否 | 否 | 否 | `order_paused` |
| 否 | 是 | 否 | 否 | `order_wait_next_bar` |
| 否 | 否 | 是 | 否 | `order_dedup` |
| 否 | 否 | 否 | 是 | `ledger_error_block` |
| 否 | 否 | 否 | 否 | 进入 SEND 链 |

设计依据：判定表 + 错误猜测。重点是**顺序**，不是单条规则；顺序错了会出现「该止损被暂停拦住」这类事故。

#### 示例 3：K 线聚合属性

对任意合法 1 分钟序列聚合到 5/15 分钟，必须满足：

1. `open` = 第一根 1m 的 open；
2. `high` = 区间最大 high；
3. `low` = 区间最小 low；
4. `close` = 最后一根 1m 的 close；
5. `volume` = 区间求和；
6. 时间戳严格递增且落在周期整点；
7. 聚合两次结果不变（幂等）。

设计依据：属性测试/蜕变测试。可用 Hypothesis 生成随机但合法的 1m 序列，比手写十几组数据更容易发现边界问题。

**白盒补测原则：**

1. 先读被测函数的所有分支，列出「未执行分支」再写用例，不为覆盖率凑数。
2. 每个边界至少三组：边界前、边界、边界后；每个可空输入至少两组：有值/无值。
3. 纯函数优先；带状态的 mixin 用最小 Fake 对象，只实现被测路径需要的方法。
4. 新增用例必须能在无网络、无真实账户、无 GUI 的环境下独立运行。

## 8. 自动化测试与持续集成

### 8.1 分层执行节奏

| 时机 | 执行内容 | 目标 |
|---|---|---|
| 本地提交前 | pre-commit：ruff、mypy（增量）、相关单测 | 5 分钟内得到反馈 |
| PR | ruff + mypy + import-linter + 全量 pytest + 覆盖率 | 不合并不通过 |
| 合并 main | 同上 + 打包 + `verify_dist` + 12 秒冒烟 | 保证可发布 |
| 每日/夜间 | 慢用例、UI 回归、联网行情、仿真 CTP（可选） | 发现环境与集成问题 |
| 版本发布前 | 全量 + 人工演练 + 四步上线记录 | 发布门禁 |

### 8.2 目录、命名与夹具规范

- 测试文件：`tests/test_<模块或主题>.py`；用例名 `test_<行为>_<条件>_<预期>`。
- 共享夹具放 `tests/conftest.py`；模块级大数据放 `tests/fixtures/`。
- 每个用例使用 `tmp_path` 工作区；禁止硬编码 `D:\Auto-Trading\data`。
- 密钥统一用内存密钥库；UI 统一用模块级窗口夹具，避免句柄泄漏。
- 断言业务结果（状态、金额、持仓、原因码），不断言日志全文。
- 测试必须独立可单跑；不依赖执行顺序。

### 8.3 标记与执行命令

已注册的标记只有 `perf`、`soak`（`pyproject.toml`），默认回归为 `-m 'not perf and not soak'`。`ui`、`network`、`ctp`、`slow` 尚未注册，也没有用例使用，暂不作为筛选条件。

```bash
# 日常回归（默认已排除 perf/soak）
python -m pytest -q

# 全量 + 覆盖率
python -m pytest -q --cov=src --cov-report=term-missing

# 性能 / 长稳
python -m pytest -q -m perf
python -m pytest -q -m soak
```

### 8.4 CI 流水线门禁

```
ruff check .
   ↓
mypy
   ↓
lint-imports（分层依赖）
   ↓
pytest -q --cov=src --cov-report=term-missing
   ↓（覆盖率 >= 56）
python tools/build_exe.py（预检 → 打包 → 收尾 → 验收 → 12 秒冒烟）
   ↓
产物归档 / 发布候选
```

任何一步失败即阻断合并或发布。

### 8.5 覆盖率策略

1. 全局门槛不降低；每次补测后只上调。
2. 核心域单独统计，目标 ≥80%：`src/domain`、`src/kernel`、`src/risk`、`src/account`、`src/backtest/metrics.py`、`src/backtest/fill.py`。
3. 新增/修改代码增量覆盖率 ≥80%，可用 diff-cover 在 PR 中展示。
4. 覆盖率不是唯一指标：核心不变量用属性测试与金标准补强。
5. 允许合理豁免：纯 UI 布局、第三方适配、不可达的防御分支；豁免需在 PR 说明。

### 8.6 Flaky 治理

- 禁止 `sleep` 等时间；用可控时钟与事件等待。
- 网络/通道用例与纯逻辑用例分离，失败可单独重跑。
- 每个用例设置超时（建议 pytest-timeout，单测 30s，UI/集成 120s）。
- 失败重跑只用于确认 flaky，不掩盖真实缺陷；连续两次失败按缺陷处理。
- 记录 flaky 率，超过 1% 必须排查。

4. `docs/perf-soak-checklist.md`：24h/72h 长稳的开始前、执行中、终止条件、结束检查与结论模板。
5. 新增 `tests/test_perf_report.py`、`tests/test_perf_soak.py`，覆盖比值判定、严格退出码、发件箱统计、终止条件与 dry-run 冒烟。

## 9. 进入准则、退出准则与暂停/恢复

### 9.1 进入准则

- 需求/缺陷单明确，验收标准可测。
- 代码可运行，依赖安装成功，CI 基线绿。
- 测试数据与环境就绪；涉及实盘的必须有仿真账号与回滚方案。
- 高风险改动（开平仓、风控、账本、通道）已完成设计评审。

### 9.2 退出准则

1. P0 用例 100% 通过；P1 用例无未关闭失败。
2. 无 S0/S1 缺陷；S2 有规避方案与修复计划。
3. 全局覆盖率 ≥56%，核心域 ≥80%，增量 ≥80%。
4. CI 全绿，打包与 12 秒冒烟通过。
5. 回测-实盘一致性对照完成，差异有归因。
6. 三方对账在仿真环境连续通过。
7. 人工演练清单（附录 C）完成并留记录。
8. 文档、CHANGELOG、版本号按项目规则更新。

### 9.3 发布门禁检查单

- [ ] `ruff check .` 通过
- [ ] `mypy` 通过
- [ ] `lint-imports` 通过
- [ ] `pytest` 全量通过，覆盖率达标
- [ ] `verify_dist.py` 通过，exe 冒烟通过
- [ ] P0 用例与人工演练记录齐全
- [ ] 回测/实盘一致性报告已归档
- [ ] 告警文件无测试噪音
- [ ] 版本号、CHANGELOG、README、文档索引一致
- [ ] 实盘配置复核（通道、账户、前置、手数上限、风控）

### 9.4 暂停与恢复

出现以下情况立即暂停测试并升级：

- 发现可能影响真实资金的缺陷（重复开仓、止损未发、账实不符）。
- 测试污染真实数据或密钥。
- 仿真环境不可用且无法判定结果。
- 需求/配置发生重大变更，现有用例失效。

恢复条件：缺陷已定位/修复/回归，环境恢复，用例与数据重新基线化。

## 10. 缺陷管理

### 10.1 严重度

| 级别 | 定义 | 示例 |
|---|---|---|
| S0 致命 | 资金损失、数据损坏、密钥泄露、无法止损 | 重复开仓、成交重复入账、实盘通道错配 |
| S1 严重 | 核心功能错误，无合理规避 | 回测口径错、对账失效、清仓不发 |
| S2 一般 | 功能错误但有规避 | 导出字段错、告警丢失、部分页面异常 |
| S3 轻微 | 体验/文案/日志 | 提示不清、排版、日志噪音 |
| S4 建议 | 优化项 | 性能、可维护性 |

### 10.2 优先级

| 级别 | 处理时机 |
|---|---|
| P0 | 立即停止发布，优先修复 |
| P1 | 当前版本必须修复 |
| P2 | 排入后续版本 |
| P3 | 待办池 |

### 10.3 生命周期

```
新建 → 确认/分级 → 分配 → 修复中 → 待验证 → 关闭
                    │                 │
                    └→ 延期/拒绝 ←────┘（需记录理由与风险接受人）
```

### 10.4 缺陷报告模板

```markdown
标题：[模块] 现象一句话
版本/环境：
严重度/优先级：
前置条件：
复现步骤：
  1.
  2.
实际结果：
预期结果：
证据：日志片段 / trace_id / 截图 / 数据库查询
影响范围：资金 / 数据 / 功能 / 体验
规避方案：
根因分类：
```

### 10.5 根因分类

- 需求理解错 / 规则实现错 / 边界未处理 / 并发与状态 / 数据质量 / 外部依赖 / 配置错误 / 测试缺失 / 文档误导。

根因用于反哺用例：每修一个 S0/S1，必须补至少一条回归用例，并检查同类模块是否存在相同问题。

## 11. 度量与报告

### 11.1 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 用例执行率 | 已执行/计划 | 100% |
| 用例通过率 | 通过/执行 | ≥99% |
| 语句覆盖率 | 全局/核心域/增量 | 56% / 80% / 80% |
| 缺陷密度 | 缺陷数/千行或按模块 | 趋势下降 |
| 缺陷逃逸率 | 上线后发现/总缺陷 | 越低越好，S0/S1 为 0 |

| 对账差异数 | 每轮三方差异 | 0 或有归因 |

| 告警噪音率 | 无效告警/总告警 | 趋近 0 |
| 性能回归 | 当前/基线 | ≤120% |
| 平均修复时长 | 从确认到关闭 | 按严重度分级跟踪 |

### 11.2 报告

- **每版本测试报告**：范围、环境、执行统计、缺陷、覆盖率、风险与结论、可否发布。

### 11.3 质量看板建议

- CI 状态与最近 30 次通过率。
- 覆盖率趋势（全局/核心/增量）。
- 未关闭缺陷按严重度分布。
- Flaky 用例 TOP N。
- 对账差异与告警噪音趋势。

**数据引用**

**运算**

- [ ] 乘数、手续费、滑点、保证金公式与文档一致。
- [ ] 手数取整、上限、0 手、负数处理正确。

**比较与控制流**

- [ ] 边界是 `>` 还是 `>=`；0 是否表示关闭。

**接口**

- [ ] 通道能力标志是否被正确使用，未按通道名硬编码。

**输入/输出**

- [ ] 文件路径、编码、换行、权限。
- [ ] SQLite 事务、锁、WAL、只读降级。
- [ ] 日志是否脱敏，是否可能写真实数据目录。

**并发**

- [ ] 共享状态是否有锁；锁顺序是否可能死锁。
