# P3 性能与长稳测试方案

对应版本 **53.7.7**（2026-11-24）。本文件是 [软件测试方案](软件测试方案.md) 8.8 节 P3 阶段的执行设计，目标是让「启动、扫描、回测、账本、长稳、故障注入」都有可量化门禁，而不是只看任务管理器。

---

## 1. 目标与范围

### 1.1 目标

1. 建立冷启动、单轮扫描、回测吞吐、账本写入四类性能基线。
2. 用 24 小时与 72 小时长稳证明：内存、线程、句柄、日志、SQLite 不持续增长。
3. 在负载下注入断网、杀进程、磁盘只读、SQLite 锁、时钟跳变，确认降级与恢复符合预期。
4. 把结果做成可比对的 JSON + 一页报告，能回答「这次比上次慢了吗」。

### 1.2 范围

| 纳入 | 不纳入 |
|---|---|
| 单进程、多线程主程序与回测引擎 | 多进程集群、容器编排 |
| Windows 10/11 本机与 CI `windows-latest` | Linux/macOS 功能差异 |
| demo/本地缓存 K 线，固定随机种子 | 真实行情波动与交易所网络质量 |
| CTP/同花顺模拟通道的本地替代实现 | 真实柜台容量与券商侧限流 |
| GUI 启动与事件循环响应 | 高 DPI 视觉细节（归 P4 人工） |

### 1.3 设计原则

- **先基线、后门禁**：第一轮只记录，不设绝对阈值；第二轮起按基线设相对阈值。
- **性能不进日常 PR**：PR 只跑单元/集成；性能在夜间或手动专用机跑。
- **同机比较**：跨机器只比趋势，不做绝对判定。
- **可复现**：固定数据、固定种子、固定线程数、固定电源模式，先预热再计时。

## 2. 性能模型与关键路径

### 2.1 冷启动

```
python 入口 → 导入模块 → 读配置 → 建日志/账本 → 恢复状态 → 建 GUI → 进入主循环 → 首轮扫描
```

关注：导入耗时、配置与账本加载、状态恢复、窗口可见、首轮扫描完成。

### 2.2 单轮扫描（每品种）

```
fetch K 线 → 去掉未收盘根 → evaluate → 风控链 → 报单/记账 → 更新界面 → 写市场健康
```

现有代码已埋点：`scan_gap_sec`、`evaluation_ms`、`download_ms`、回测 `duration_ms`。P3 直接复用，不另造一套计时。

### 2.3 回测

```
读本地 K 线 → 指标/策略 → 逐根撮合 → 统计 → 报告
```

关注：单位时间处理 K 线数、固定数据集总时长、优化/交叉测试单任务时长。

### 2.4 长稳资源面

内存 RSS、私有字节、线程数、句柄数、CPU、SQLite 文件与 WAL、日志目录、告警 JSONL、未完成发件箱事件。

## 3. 指标体系与初始门禁

> 「初始阈值」用于第一轮建立基线；首轮完成后以 `baseline.json` 的 120% 作为回归门禁。绝对阈值只在专用机上执行。

| 编号 | 指标 | 定义 | 初始阈值 | 门禁 |
|---|---|---|---|---|
| PERF-C1 | 导入耗时 | `import src.ui.app` 的 `perf_counter` | ≤ 3.0 s | 相对基线 120% |
| PERF-C2 | 冷启动到窗口可操作 | 进程启动→主循环可响应 | ≤ 10.0 s | 相对基线 120% |
| PERF-C3 | 冷启动到首轮扫描完成 | 启动→首条扫描日志 | ≤ 20.0 s | 记录 |
| PERF-S1 | 单品种扫描 p95 | `evaluation_ms + download_ms` | ≤ 2000 ms | 相对基线 120% |
| PERF-S2 | 10 品种一轮 p95 | 一轮全部品种扫描 | ≤ 8000 ms | 相对基线 120% |
| PERF-S3 | 扫描按时完成率 | 轮次在下一个 K 线周期内完成 | ≥ 99% | 硬门禁 |
| PERF-B1 | 回测吞吐 | 已收盘 K 线数 / 秒 | ≥ 1500 根/秒 | 相对基线 85% |
| PERF-B2 | 优化单任务时长 | 固定参数网格总时长 | 记录 | 相对基线 120% |
| PERF-D1 | 账本写入延迟 p95 | 单笔成交入账→投影可见 | ≤ 200 ms | 相对基线 120% |
| PERF-D2 | 对账耗时 p95 | 三方对账一轮 | ≤ 500 ms | 相对基线 120% |
| PERF-M1 | 24h RSS 增长 | 预热后峰值 − 起点 | ≤ 50 MB 且无单调上升 | 硬门禁 |
| PERF-M2 | 线程/句柄增长 | 24h 结束 − 起点 | 线程 ≤ 2、句柄 ≤ 50 | 硬门禁 |
| PERF-M3 | 日志/DB 增长 | 24h 增量 | 日志按 20MB 轮转；WAL 不持续增大 | 硬门禁 |
| PERF-R1 | 长稳可用性 | 24h 内主循环存活 | 无崩溃、无卡死 | 硬门禁 |

判定方法：

- 每个场景 **预热 1 次 + 正式 5 次**，取中位数与 p95；报告同时给出 min/max。
- 相对门禁：`本次 p95 ≤ 基线 p95 × 1.2`；吞吐类反过来 `本次中位数 ≥ 基线 × 0.85`。
- 内存趋势：对每小时采样做线性回归，斜率显著为正且总增长超阈值即失败。

## 4. 测试环境与基线管理

### 4.1 环境卡

每次执行必须记录：

```
机型 / CPU / 内存 / 磁盘类型 / Windows 版本 / Python 版本 / 依赖锁文件哈希
电源模式（高性能）/ 是否插电 / 后台进程白名单 / 屏幕缩放
数据源（demo 或本地缓存）/ 数据区间 / K 线周期 / 品种列表 / 固定种子
```

### 4.2 基线文件

- 位置：`build/perf/baseline.json`（本地生成，不进 Git）。
- 入库摘要：`docs/perf-baseline.md`（只写机型、日期、各指标中位数/p95，便于评审）。
- 更新规则：机型、Python 大版本、关键依赖、核心算法变更时才重设基线；重设需在报告中注明原因。

### 4.3 数据准备

- 使用仓库内 demo 数据或 `data/klines` 的固定副本，复制到临时目录，避免污染真实缓存。
- 品种集固定：1 个、5 个、10 个三档；每档使用同一份 K 线。
- 回测固定区间（例如最近 3 年 15 分钟），报告写明根数与起止时间。
- 所有随机过程固定 seed；禁用网络与自动更新。

## 5. 场景设计

### 5.1 冷启动（PERF-01 ~ PERF-03）

| 编号 | 场景 | 方法 | 产物 |
|---|---|---|---|
| PERF-01 | 模块导入耗时 | 子进程 `python -c "import time; t=perf_counter(); import src.ui.app; print(perf_counter()-t)"`，重复 5 次 | 中位数/p95 |
| PERF-02 | 冷启动到窗口可操作 | 启动真实程序，记录「主循环开始」日志时间；无 GUI 环境用 `--headless` 等价入口 | 秒 |
| PERF-03 | 冷启动到首轮扫描 | 记录首条扫描完成日志；同时记录扫描品种数 | 秒 |

注意：冷启动前清空 Python `__pycache__` 不计入，正式测量前至少预热一次文件缓存。

### 5.2 扫描（PERF-04 ~ PERF-06）

| 编号 | 场景 | 方法 | 通过标准 |
|---|---|---|---|
| PERF-04 | 单品种空仓扫描 | demo 数据，无仓无单，连续 200 轮 | p95 ≤ 2 s，无异常 |
| PERF-05 | 单品种持仓+挂单扫描 | 预置仓位与未完成委托 | 与空仓差异 ≤ 30% |
| PERF-06 | 10 品种并行扫描 | 10 个品种同一轮 | p95 ≤ 8 s，按时完成率 ≥ 99% |

数据来源：调度日志中的 `evaluation_ms`、`download_ms`、`scan_gap_sec`；测试用伪行情时在夹具层注入固定延迟，避免把网络波动算进代码性能。

### 5.3 回测吞吐（PERF-07 ~ PERF-08）

| 编号 | 场景 | 方法 | 通过标准 |
|---|---|---|---|
| PERF-07 | 固定数据集回测 | 同一份 3 年 15 分钟数据，跑 5 次 | 吞吐 ≥ 1500 根/秒；5 次结果逐笔一致 |
| PERF-08 | 参数优化单任务 | 固定网格（如 5×5），跑 3 次 | 记录总时长；结果与基线一致 |

### 5.4 账本与投影（PERF-09 ~ PERF-10）

| 编号 | 场景 | 方法 | 通过标准 |
|---|---|---|---|
| PERF-09 | 连续成交入账 | 临时工作区顺序写入 1000 笔成交 | p95 ≤ 200 ms/笔；JSON 与 SQLite 一致 |
| PERF-10 | 三方对账 | 内存/账本/柜台各 100 仓，跑 100 轮 | p95 ≤ 500 ms/轮；无漂移 |

### 5.5 GUI 响应（PERF-11）

| 编号 | 场景 | 方法 | 通过标准 |
|---|---|---|---|
| PERF-11 | 页签切换与刷新 | 自动切换 7 个页签各 20 次，记录事件循环延迟 | 单次 ≤ 200 ms；无「未响应」 |

### 5.6 长稳（SOAK-01 ~ SOAK-03）

| 编号 | 时长 | 负载 | 采样 | 通过标准 |
|---|---|---|---|---|
| SOAK-01 | 24h | 10 品种、模拟报单、每分钟扫描 | 每 30 s：RSS/句柄/线程/CPU；每 1h：DB/日志大小、发件箱积压 | 满足 PERF-M1~M3/R1 |
| SOAK-02 | 72h | 同 SOAK-01，叠加每 6h 一次断线重连 | 同上 | 无泄漏、无重复入账、无卡死 |
| SOAK-03 | 24h | 空闲界面 + 单品种 | 同上 | 空闲不持续占用 CPU（平均 ≤ 5%） |

### 5.7 故障注入（FAULT-01 ~ FAULT-08）

| 编号 | 注入 | 预期 | 观测点 |
|---|---|---|---|
| FAULT-01 | 行情源超时 | 回退备源/本地库，标记来源，不崩溃 | 日志、市场健康、告警 |
| FAULT-02 | 断网 5 分钟后恢复 | 自动重连，不重复报单 | 连接状态、委托表 |
| FAULT-03 | 强杀进程（有仓） | 守护平仓或写 `unprotected_positions.json` | 文件、下次启动对账 |
| FAULT-04 | `data/trading.db` 只读 | 禁止开新仓、平仓放行、告警可见 | 风控事件、界面 |
| FAULT-05 | SQLite 长时间锁 | 超时重试、只读降级、不误报漂移 | 对账日志 |
| FAULT-06 | 系统时钟前跳/后跳 1 小时 | 交易日/会话判定正确，不重复日结 | 日结计数、调度 |
| FAULT-07 | 磁盘剩余空间不足 | 停止写入非关键日志，核心账本不丢，告警 | 日志、告警 |
| FAULT-08 | 重复成交回报 ×100 | 只入账一次，发件箱不积压 | 账本、投影、发件箱 |

## 6. 测量方法与工具

### 6.1 复用现有计时代码

| 位置 | 字段 |
|---|---|
| `src/scheduler/runner.py` | `scan_gap_sec`、`evaluation_ms`、`download_ms` |
| `src/backtest/engine.py` | `duration_ms` |
| `src/data/kline.py` | `download_ms` |
| `src/research/scan.py`、`src/review/replay.py` | `duration_ms` |

原则：生产代码只保留轻量 `perf_counter`；重采样、`tracemalloc`、`cProfile` 只在测试夹具或专用脚本中开启。

### 6.2 采样器

独立脚本 `tools/perf_soak.py`（已实施）：

- 用子进程启动目标（默认 `[当前解释器, "-m", "src.main"]`，`--command` 可覆盖）。
- 每 30 秒用 `psutil.Process` 采样：RSS、私有字节、线程数、句柄数、CPU 百分比。
- 每 1 小时记录：`data/trading.db` 及 WAL、`logs/` 总大小、告警文件、发件箱 pending/failed、磁盘剩余空间。
- 每 6 小时刷新一次 Markdown 检查点；结束时写最终摘要。
- 输出 `build/perf/soak-<timestamp>.jsonl` 与 `soak-<timestamp>.md`；Ctrl+C 会正常收尾并终止目标进程。
- 自动终止：目标进程退出、磁盘剩余 < 1 GB、预热后 RSS 连续 3 点上升且累计 > 200 MB。

```powershell
.\.venv\Scripts\python.exe tools\perf_soak.py --hours 24 --symbols 10
.\.venv\Scripts\python.exe tools\perf_soak.py --dry-run --hours 0 --max-samples 3 --interval 0
```

### 6.3 基准脚本

`tests/perf/`（已实施）：

```
tests/perf/conftest.py          # 标记、环境卡、临时工作区、固定数据
tests/perf/test_perf_coldstart.py
tests/perf/test_perf_scan.py
tests/perf/test_perf_backtest.py
tests/perf/test_perf_ledger.py
tests/perf/test_perf_gui.py
```

- 报告命令：`python tools/perf_report.py [--latest] [--output 文件] [--strict]`；`--strict` 有失败用例时退出码 1。

## 7. 长稳执行手册

### 7.1 前置检查

- [ ] 机器插电、高性能电源、关闭自动更新与屏保
- [ ] 关闭无关后台程序；记录白名单
- [ ] 使用临时工作区或专用测试账号，不碰真实账本
- [ ] 确认日志轮转、告警目录、SQLite 路径可写
- [ ] 记录起始文件大小与进程资源

### 7.2 执行

1. 启动采样器，再启动目标程序。
2. 前 30 分钟为预热，不计入内存趋势。
3. 每 6 小时记录：RSS、句柄、线程、CPU、DB/日志大小、发件箱积压、异常日志条数。
4. 每 24 小时做一次对账与只读功能检查（切页签、查持仓、看告警）。

### 7.3 终止条件（任一触发即停止并留证）

- 进程崩溃、卡死超过 2 分钟、主循环停止超过 3 个扫描周期。
- RSS 连续 3 个采样点单调上升且累计超过 200 MB。
- 线程/句柄持续增长且无回落。
- 出现重复入账、账实漂移、无法恢复的数据库锁。
- 磁盘剩余空间低于 1 GB。

### 7.4 产物

- `build/perf/soak-*.jsonl` 原始采样
- `build/perf/soak-*.md` 摘要（含趋势图数据）
- 异常日志片段与复现步骤
- 结论：通过 / 有条件通过 / 失败，附最小复现

## 8. 报告与门禁

### 8.1 报告结构

1. 环境卡与代码版本
2. 指标总表：本次 vs 基线、比值、是否通过
3. 趋势图数据：RSS/句柄/线程/DB 大小
4. 异常与故障注入记录
5. 结论与后续动作（优化项、基线重设、已知波动）

### 8.2 分层门禁

| 场景 | 频率 | 门禁 |
|---|---|---|
| PR | 每次提交 | 不跑性能，只跑单元/集成 |
| 夜间 | 每日 | 冷启动、扫描、回测基准；相对基线超 120% 告警，不阻断合并 |
| 周度/发版前 | 每周或发版 | 24h 长稳 + 故障注入；不通过则阻断发版 |
| 季度 | 每季度 | 72h 长稳；更新基线摘要 |

CI 只做「同机相对比较」；绝对 SLO 在专用机执行并签字。

### 9.2 P3.1 首轮结果（2026-11-24，本机）

环境：Windows 11 / 32 核 / 31.7 GB / Python 3.12.10。基线写入 `build/perf/baseline.json`（本地，不提交）。

| 用例 | 指标 | 当前基线 | 初始阈值 | 结果 |
|---|---|---|---|---|
| PERF-01 | 子进程导入 `src.ui.app` | 626.4 ms | ≤ 3000 ms | 通过 |
| PERF-04 | 单品种 evaluate | 0.015 ms | ≤ 2000 ms | 通过 |
| PERF-06 | 10 品种一轮 evaluate | 0.362 ms | ≤ 8000 ms | 通过 |
| PERF-07 | 回测吞吐（4000 根） | 3419.3 bars/s | ≥ 1500 bars/s | 通过 |
| PERF-09 | 单笔入账 + SQLite 投影 | 22.7 ms | ≤ 200 ms | 通过 |

用法：

```powershell
# 生成报告：最近一次 + 趋势；--strict 时有 FAIL 退出码 1
.\.venv\Scripts\python.exe tools\perf_report.py --latest
.\.venv\Scripts\python.exe tools\perf_report.py --output build\perf\report.md --strict

# 只记录，超阈值给 warning
.\.venv\Scripts\python.exe -m pytest -m perf tests\perf

# 严格门禁：超阈值直接失败
$env:PERF_STRICT="1"; .\.venv\Scripts\python.exe -m pytest -m perf tests\perf

# 重新固化基线（机型/依赖变化时）
$env:PERF_WRITE_BASELINE="1"; .\.venv\Scripts\python.exe -m pytest -m perf tests\perf
```

说明：亚毫秒指标设置了噪声下限（PERF-04/06 为 5 ms），差异小于下限时只比绝对阈值，避免把测量抖动当回归。

## 10. 用例清单

### 10.1 性能基准

| 编号 | 用例 | 方法 | 期望 |
|---|---|---|---|

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| CI 机器噪声导致误报 | 门禁不可信 | 性能只在夜间专用机跑；PR 不跑；相对基线比较 |
| 数据/缓存不一致 | 结果不可比 | 固定数据副本 + 数据哈希写入报告 |
| 长稳被人工操作打断 | 结果作废 | 专用测试账号与工作区；操作清单化 |
| 计时埋点影响生产性能 | 主流程变慢 | 只保留轻量 `perf_counter`；重采样仅在测试开启 |
| 基线随依赖漂移 | 门禁失效 | 依赖哈希变化时重设基线并注明 |
| 故障注入误伤真实环境 | 数据风险 | 仅临时工作区；注入前备份；默认 dry-run |
