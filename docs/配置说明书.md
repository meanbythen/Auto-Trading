# Auto-Trading 界面配置说明书

对应版本：**49.18.2**
适用界面：主窗口 11 个页签，按界面从左到右的顺序编排：**运行 → 交易账号 → 交易配置 → 策略编辑器 → 历史回测 → 数据管理 → 交叉测试 → 策略优化 → 复盘 → 账户分析 → 规律候选**。

每个条目给出 8 项信息：编号、界面名称、当前值/默认值、对应配置键、逻辑与作用、影响大小、是否影响运行速度、是否影响下单时间。可直接用编号逐条对照。

44.10.0 新增「策略编辑器」页和「自定义规则（DSL）」策略：`strategy.engine` 除内置策略名外，还可以填 `rule_dsl:<文件名>`，对应 `config\rules\<文件名>.yaml`。原内置策略的配置键、默认值和含义均未改变；规则写错时只停这套策略并写告警，不会换成别的策略。

44.11.0 没有新增配置键，只在运行台加了安全提示：启动/运行中对账有差异时，顶部出现横幅与「处理对账」按钮（认领 / 平掉 / 忽略）；扫描停滞时看门狗自动打上「暂停报单」并说明原因；上次带仓退出后首次启动会提示先核对持仓。这些状态由 `data/bot_state.json` 的 `reconcile` / `frozen_symbols` / `protective` 字段驱动，不需要手工配置。

44.12.0 新增的都是「不开也能用」的配置：`schedule.holidays_file` / `schedule.holiday_min_cover_days`（节假日日历）、`runtime.alerts.*`（飞书告警外发，默认 off）、`runtime.guardian.*`（冷备守护，默认关闭）。这些键不在配置页暴露，直接改 `config.yaml`；默认值下行为与 44.11.0 一致。逐条见第九节 HD-14～HD-23。

44.13.0 新增 `trade.ctp_profile` 与 `trade.ctp_profiles`：前者选当前用哪份券商档案，后者一段一份柜台（`kind`、`broker_id`、`td_front`、`md_front`、`user_id`、`password_env`、`auth_code_env` 等）。行情前置不再按交易端口推断，必须在档案里显式填写。逐条见 CF-23c / CF-23d。

45.0.0 删除 CTP 旧写法：`trade.ctp.sim / live` 与顶层 `td_front / md_front / broker_id / user_id` 不再读取，配置页的「实盘交易前置 / 实盘行情前置」也已删除。现在只认 `ctp_profiles`；仿真和实盘用同一套字段，换实盘时把档案前置换成柜台地址、把 `kind` 改成 `live`。档案为空或档案名不存在时不会猜别的券商，登录会因缺少前置明确失败。

49.15.0 复核：按 `config/config.example.yaml` 和代码重核了本手册引用的配置键，控件说明沿用原文；已删除或废弃的键统一在第九节 WY 组标注。45.0.0 之后新增的键以 `config.example.yaml` 注释和 `CHANGELOG.md` 对应版本为准。

49.16.0 复核：本轮是架构收敛（报单模块拆分、界面保存改走命令层、依赖方向约束），没有新增、改名或删除配置键，控件行为不变。配置页保存后仍一次同步扫描间隔、交易时段、合约表与日亏限额，只是改由 `TradingBot.apply_runtime_config` 在交易锁内完成。

49.17.0 复核：`backtest.liquidity` 三项默认值改为「开 / 0.1 / 1」，新增 `entry_timeout_bars`（CF-116c / BT-16d）。品种与合约表的 `commission`、`trading_sessions`、`flatten_times` 已按交易所标准回写，清仓时刻不再有代码内硬编码兜底；价格型手续费按近期典型价折算，签字前需按期货公司结算单核对。

49.18.0 复核：新增 CF-115「单笔最大手数」（`trade.ctp.max_order_volume`），放在交易配置页「风控与资金管理」块。保存时同时写入当前券商档案；运行中保存会立即推给交易对象，不用重连。

49.18.1 复核：CF-115 改为算仓时就生效。资金管理算出超过上限的手数时直接取小，日志多一段「单笔上限N」；回测不传该上限，历史结果不变。

49.18.2 复核：修柜台认领的持仓启动即被平仓。认领或按账本重建的仓没有止损价时，按开仓价和现价里更差的一侧外放 2×ATR，并且本根新算出的止损只从下一根判定。

## 阅读约定

- **影响大小**：大＝直接改变开/平仓与盈亏；中＝改变筛选、统计或使用体验；小＝仅显示或提示。
- **影响运行速度**：指常驻运行时 CPU / 网络 / 磁盘开销，或该页操作本身的耗时。
- **影响下单时间**：指「信号出现 → 点击发出」这一段真实链路（同花顺点击通道）。当前基线约 **1.5~2.5 秒**（点完买卖不再等确认框）；需要现场改价时再加约 0.5 秒。
- 「当前值」取自 `config/config.yaml`；「默认值」取自代码里的兜底值。两者不同时会并列写出。
- 配置页的改动**只有点「保存交易配置」才写盘**；运行台的 `dry_run` 开关也只在点「启动常驻」时才落盘。
- 加载配置时会把键名和 `config.example.yaml` 对照：多写的键记一条告警；少写的键按程序默认值处理，不阻断运行；同一层重复写的键也会点名（后写的生效）。

> **三个容易混的按钮**：
> - **处理对账**（状态栏粉红）：柜台手数和程序账对不上时出现。认领 / 按现价补记平仓 / 暂不处理。**会改持仓记账**。

> - **手工单录入**：把你在同花顺/手机实际做的开平仓补进程序账。
> - 正确顺序：先在交易软件核对 → 成交了先「手工单录入」或「处理对账」→ 还有熔断再点「核对委托」。
> - **9.50.7 起两者联动**：手工录入的品种、方向和手数如果与遗留委托对得上（平仓只比品种和方向，手数由程序持仓决定），录入成功后会弹框「这笔和上次没核对完的委托一致，现在解除熔断吗」，确认即等于顺手点了「对账确认」。对不上则不弹，避免误放行。

# 二、交易账号页（页签「交易账号」）

执行通道、CTP操作账、券商前置都在这一页。交易配置只管策略、开仓止损和仓位。某一格密码留空再点保存，不改已经存过的值。打包 exe 不会带走密码文件，换电脑后到这一页再填。

账号与连接已分开：

- **账号**：身份（资金账号、环境、状态、密码引用），一个账号一本账，账本 id 默认等于 `account_id`。
- **连接**：期货公司接入点（前置、BrokerID、AppID、超时），不含资金号和密码；一条连接可被多个账号引用。
- **当前使用**：顶部只读卡片。切换账号后 `trade.executor`、`trade.ctp.ctp_profile`、`trade.ctp.account_kind` 和账本一起切换。
- **行情数据源**：天勤账号已移到「数据管理 → 行情数据源」，和交易账号完全解耦。
- **存储**：`config/accounts.yaml`（YAML 权威，v2 结构 `connections` + `accounts`）、`data/active_account.json`（当前账号）、本机 DPAPI 密钥库（密码）。
